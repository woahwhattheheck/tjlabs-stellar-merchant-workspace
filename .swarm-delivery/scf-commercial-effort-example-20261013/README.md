# Complete commercial delivery effort and private economics example

This distribution opens the original Merchant and SF47 Operations applications together. It contains the full application source, the editable internal example, and one launcher that finds the installed Node, Playwright and Chromium runtimes.

The example starts with an internally authored quotation and acceptance, records Work against its original accepted task, saves a reviewed Installation, then carries the browser-downloaded Installation ZIP into private economics and an independently received Merchant case.

## Run the complete operator course

From the repository root, choose an absolute private output directory:

```sh
python3 .swarm-delivery/scf-commercial-effort-example-20261013/receive.py \
  .swarm-delivery/scf-commercial-effort-example-20261013/source-carrier.json \
  /ABS/private/scf-commercial-effort-example
```

The launcher extracts all selected source into that directory's `source/`, discovers already-installed runtimes, and runs the original example with its `--receive` option. It installs no packages. The original apps listen on loopback ports **18776** and **18777** while the course operates; the launcher owns and closes those listeners.

The whole retained `operator-course/` contains the editable Merchant and Operations workspaces, original preparation and browser requests, selected Installation ZIP, private assessment, full exported and received Merchant case, original Installation HTML, actual screenshots and operated result. Transfer that complete private directory when another operator needs to continue its history. Keep its private access file private.

After the automated course closes, reopen the same application state interactively:

```sh
node /ABS/private/scf-commercial-effort-example/source/stellar/scf-starforge-20261009/sf74-merchant-support-console/commercial/effort-economics-example.mjs \
  --out /ABS/private/scf-commercial-effort-example/operator-course
```

Use the printed Merchant URL and the printed local Operations access file. The two original apps expose their ordinary editing, history, download and import controls. Reopening keeps the original request UUIDs and selected historical preparation; later operator edits remain in those workspaces.

If runtime discovery needs explicit installed paths, the original entry point also accepts:

```sh
node /ABS/private/scf-commercial-effort-example/source/stellar/scf-starforge-20261009/sf74-merchant-support-console/commercial/effort-economics-example.mjs \
```

## Business scenario

The separate **INTERNAL WALKTHROUGH** uses these editable assumptions:

| Item | Value |
| --- | ---: |
| Proposed implementation price | USD 7,200 |
| Original private implementation plan | 60 hours |
| Original recorded Work | 42 hours |
| Of recorded Work, internally accepted | 18 hours |
| Reviewed remaining implementation effort | 30 hours |
| Projected total implementation effort | 72 hours |
| Selected labor valuation | USD 95/hour |
| Selected referral cost | USD 360 |
| Proposed monthly care | USD 600 |

At the original 60-hour plan, implementation revenue less valued labor and the selected referral cost is USD 1,140. At the 72-hour projected total, that same valuation result is USD 0. The application computes the assessment through its original economics engine. Actual cash labor cost is a separate input, and the internally accepted Work amount is a separate measure from recorded or projected effort.

The actual accepted task has no quoted task-effort field. The example retains that unspecified value; the 60-hour figure belongs to the separately selected private planning assessment.

## What the operator course does

1. Prepare the original quotation and its private plan, retain the full authored acceptance and Merchant handoff, and create the separate WALKTHROUGH case through the original writers.
2. Attribute the two original Work records to the accepted task and retain a reviewed remaining estimate through the original Installation engine.
3. Open the actual Installation UI, review its remaining-work controls, save the next edition and download that exact edition's complete ZIP and saved input.
4. Independently receive that ZIP, select its projected hours and explicitly reuse the selected private plan's cost assumptions, then save the original private economics assessment.
5. Export and independently receive the full Merchant case and source; reopen both economics interfaces and their JSON/report/draft downloads.
6. Open the producer's unchanged Installation HTML from the complete ZIP. Retain 1440-pixel and 390-pixel screenshots from the Installation, original Merchant, received Merchant and HTML report.

The returned state `OPERATED` records completion of those original controls. The producing operator then opens and personally inspects the actual screenshots and exports, following the standing owner instruction below.
