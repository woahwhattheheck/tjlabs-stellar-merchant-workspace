# Orkyo import preparation contract
Prepared 2026-10-15. Source commit 9b773566ecbfb0947f51f6e20ea925c03ddb2a22, Git tree db4200ca628cf281f3d55d6ff37a8344d28b792e.
## Operator integration
Embed adapter/orkyo-import.js or import its .mjs counterpart. createOrkyoImportAdapter().inspect accepts kind requests/resources, full original text, sourceId, format csv/json, selected resource type and actual custom-field definitions. Requests support CSV. Resources support CSV and the native JSON envelope. Every occurrence retains its original cells, normalized native cells, native create payload and concrete review findings. Retain the complete result in the workshare workspace. SourceId and row occurrence belong to this product; a native target ID is acquired separately.
Use encodeCSV only for reviewed new-create rows. It preserves standard quoted multiline values and neutralizes native formula-trigger prefixes. A literal leading apostrophe followed by a formula trigger cannot survive the pinned native CSV parser; this serializer rejects that specific value instead of losing it. Resource JSON is a separate route where appropriate.
The preview neither sends provider requests nor changes the receiving workspace. Service-side validation and the authorized operator's selected import are separate steps.
## Current native behaviour
Per-page imports always create. IDs do not make an upsert. Resource pages choose the target type; resource_type_key in the file does not override that page. Native flat resource JSON uses data rows with snake_case names, metadata schemaVersion 1.0.0 and context resources:TYPE. It is different from the organization export's nested data object.
Request CSV carries the 15 headers in REQUEST_HEADERS. It does not restore site, hierarchy, dependencies or requirement definitions; requirements_count is only a count. The native importer parseInt truncates decimal durations and defaults absent/invalid minimal duration to 1 hour. Retain the source quantity/unit and choose a reviewed whole-number unit, for example 2.5 hours = 150 minutes where that was actually intended.
Resource fields use declared meta.TYPE columns. Numeric serial numbers remain text when declared text. List lookups require the receiving row identity. Generic resource create does not restore active state, group membership or user linking. Unknown source columns remain in the preparation record.
The current backend permits exact allocation modes Exclusive and Fractional. The native CSV resource parser defaults an omitted mode to lowercase exclusive, which does not match that declared list. Prepared files must use the actual accepted mode.
Base availability is 0–100. Capacity is concurrent occupancy, at least 1, and does not mean hours per day. Physical resources require geometry. Names are at most 200 characters. The preview highlights these observed contract distinctions without claiming to replace all backend validation.
## Workbook pathway
The actual retained workbook reader uses Workstations and Jobs, headers on row5/data from row6, Workstations A:E and Jobs A:F. Its XLSX reader uses cached formula values and ignores workbook styles. Workstation codes match exactly; the current-site active placeable-resource lookup stops if its response was truncated. Workstation capacity hours/day is intentionally not mapped to concurrent occupancy.
The native workbook path creates workstations sequentially and then jobs; an interruption leaves the already-created records in the target. Repeating the import reuses station codes but creates jobs again. The job's inclusive end date becomes the next midnight UTC; weekday count ignores weekends but does not read the site's actual holidays. Hours/day times that weekday count becomes minimum hours; absent/nonpositive duration falls back to one hour. These semantics differ from per-page CSV.
## Receiving
node receiving/compare-native.mjs executes the pinned original import functions after explicit, signature-checked TypeScript type erasure. It compares complete payload values for authored source rows against the production adapter. Full untouched TypeScript and license are retained below vendor/orkyo-foundation. The recorded functions-V8 course is the actual run performed during preparation; a later Node run reports its own runtime.
The authored example includes a fractional-duration/requirement-loss review and a corrected minutes example, plus typed numeric/boolean/text resource metadata and multiline cells. It contains no buyer or plant production data.
