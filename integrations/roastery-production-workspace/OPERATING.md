# Installed roastery production

## Open a complete working period

Build/install source selection `roastery-production-workspace` through the maintained distribution launcher. Open **Applications → Roastery production**. Select a physical owner-private directory; add **New workspace label** to create an unused workspace. Start and Open. The same saved request and installation identity resume after restart.

The complete original seven-table roastery desk is retained. Receive exact UTF-8 CSV originals for lots, profiles, products, recipes, orders, roasted stock and packaged stock. Inspect due-order allocation, existing-stock use, balanced roast batches, declared loss/capacity and green availability. Weights are grams and recipe shares are roasted component percentages. The original domain guide is [docs/OPERATOR.md](docs/OPERATOR.md).

Enter **Reviewer / operation actor**, preserve unfinished table/review/outcome drafts, and freeze a reviewed plan only after source drafts are applied and the original checks pass. Record weighed green/roasted output against that exact frozen batch. Corrections append an outcome linked to the earlier record. Frozen tables and all original captures remain available; actual outcomes do not silently rewrite stock. Begin the next period with new received counts.

## Save, recover and continue

**Save complete session** commits the complete editor through the sole private host writer. Browser changes retain their own full IndexedDB recovery. **Open newest saved edition** retains displaced local writing as a complete prior session. An ambiguous transport outcome keeps its exact original request pending; **Recover original request** queries/retries the same ID, base and full successor. A stale-base rejection is retained and leaves the complete local branch available for explicit selection.

Competing browser tabs compare the complete saved browser shell transactionally. **Keep this browser branch; retain saved copy** retains both complete preimages, pending request identities and earlier branches. Save recovery JSON before intentionally changing the listener port; normal restart reuses the original port. Opening another recovery cannot discard a current different pending request.

**Retained complete prior sessions** includes unfinished source/review/outcome writing before original source changes, plan/outcome decisions, new production periods, incoming working files and restored sessions. Restoring one retains the displaced complete session. Ordinary original workspace JSON remains accepted; complete working JSON also carries the prior session collection and editor choices.

## Complete handover

**Save retained handover ZIP** uses the saved host edition, receives every returned byte and verifies the full hash. The archive contains complete current source, ordinary full working JSON, original workspace JSON, editable standalone HTML, every original CSV capture and capture context, current report/plan, frozen input plans, measured outcome reports, prior working sessions and all retained host requests/editions. The history index distinguishes selected outcomes and interrupted prepared records.

Standalone complete working JSON/HTML and source exports remain available while writing. Prospect records received privately are retained with the complete workspace. The maintained repository carries generic code and authored input; original private programme data stays in its private source carrier.

## Native commands

```sh
node integrations/roastery-production-workspace/cli.mjs init /physical/private/roastery "Production period"
node integrations/roastery-production-workspace/cli.mjs course /physical/private/authored-roastery
node integrations/roastery-production-workspace/managed.mjs --workspace /physical/private/roastery
node integrations/roastery-production-workspace/cli.mjs receive /physical/private/received /physical/private/Roastery_Working.json
node integrations/roastery-production-workspace/cli.mjs inspect /physical/private/roastery
node integrations/roastery-production-workspace/cli.mjs connected /physical/private/roastery /physical/private/original-request.json
node integrations/roastery-production-workspace/cli.mjs connected-status /physical/private/roastery /physical/private/original-request.json
```

Create owner-private parents. Close Applications before standalone writer commands; connected commands attach to its existing writer. `session`, `desk`, and `export` write complete new outputs. `ingest` reads an original declared UTF-8 CSV into a retained request before applying it. The original `native/cli.mjs` command-file course and original builders remain available unchanged.

The source-owned Merchant provider declares installation/input aliases in `stellar-forge.roastery-host.v1`, pins exact input and saved-edition SHA values, and attaches to the same writer. Its inspect routes page complete table, source, plan, frozen outcome, draft and request context. Native actions use original `receive`, `freeze`, `outcome`, `name` and `notes` operations with the full workspace head; every domain action retains the prior complete editor.
