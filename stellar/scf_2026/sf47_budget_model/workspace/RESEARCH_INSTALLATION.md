# Economic Research → Workshare Customer Installation

This is the complete source and customer receiving path inside the existing Grant Operations Source Desk. It connects an actual Workshare-backed Installation to whole Economic Research inputs: the native economic project, the original issued product package, and an optional original customer return. The original Operations, Workshare, Installation, Research and Source Desk implementations remain the business writers.

Preparation produces a reviewable document and complete source record. Attaching records that provenance in the original Operations case. Saving creates an explicit Installation edition. Receiving retains that saved edition and all original source bytes in an independently editable customer workspace. These are separate outcomes; none is a claim of accepted work, licensing permission, commissioning or payment.

## 3. Original capacities and full byte custody

| Original file | Native kind | Maximum |
| --- | --- | --- |
| Complete economic project JSON | project | 480 MiB |
| Issued Research gzip package | issued-package | 256 MiB |
| Original customer return gzip | customer-return | 256 MiB |
| Complete customer Installation ZIP | installation-archive | 2 GiB |
| Compact Source Desk selection | original selection.save | 8 MiB |

The project, package and return limits are whole original file limits, not permission to truncate a larger input. The complete archive must also fit its aggregate limit including the case, complete Source Desk history and retained files. The original ordinary 8 MiB Source Desk file route and 192 MiB generic archive route remain unchanged. Use the dedicated Research path for these larger originals.

Uploads are immutable sidecars of the same case and Source Desk draft. They retain the exact request UUID, actor, original filename, byte count, SHA256, source URL and actual observation time before accepting the full body. Uploading does not advance the Source Desk revision. Selection, preparation and attachment use the existing Source Desk revision/request transaction.

The retained file ID is an opaque research- followed by 64 hexadecimal characters. It identifies the full original upload intent, including actor and request. It is not the file body SHA. Always retain both the ID and the separately checked original body SHA.

No full project or archive is embedded in an agent JSON request. Installed tools select a declared host file alias and its expected SHA. Native copies and browser downloads retain all bytes; public inspection metadata excludes source bodies and internal filesystem paths.

## 4. Staff workflow

1. Open the original Operations case and Source Desk. Select the current draft or create one with the original writer and an explicit title.
2. In Research, choose the complete original project or issued package. An optional customer return is a separate retained input. Select a source URL, actual observation time and the original operator.
3. Retain the upload descriptor and UUID before sending. The route accepts the whole raw file, verifies length/SHA and calls the maintained Research receiver. A complete native project is inspected in an isolated receiving directory; it does not alter the producer.
4. Read the native inspection. Select the actual producer project, product and issued edition. When both project and issued package are present, the package fixes the selected issued authority. Full original definitions, captures and reviews are compared internally; matching IDs alone are insufficient.
5. Review every bound source definition. Record purpose, rightsStatus, authorityReference, redistribution and retention. Preparation requires permitted for each selected source; review-required and not-permitted remain editable unresolved decisions.
6. Obtain the original Workshare-backed template and retain its full document. Review actual host/operator, source authority and change policy, maintenance, acceptance, payment authority and original commercial fields.
7. Save the whole selection through selection.save at the current Source Desk revision. Prepare with the exact selected engine and selection hashes.
8. Open the complete prepared inspection, original source descriptors and native Installation preview. Use research.attach with the exact preparation and current Operations version.
9. Attachment adds one compact provenance source through the original Operations source writer and returns a fresh Installation preview. Carry its complete document into the existing Installation editor. Explicitly preview and save with the original writer and expected preview SHA.
10. Reopen the saved Installation edition. Describe its complete Research archive, then download the exact described SHA. Retain the full ZIP and verify its byte count/SHA.
11. Independently receive into a selected native workspace and open the saved Installation, source draft, all original inputs and the editable Research project. Use a current-case template and fresh preview before making received-side Installation changes.
12. Personally inspect the exact outgoing rendered edition and full attachments before calling it customer-ready.

A retained customer return is never silently applied to a producer. Its original bytes and IDs remain available. Use the existing Research return comparison, editable working draft and explicit apply action when the actual producer authorizes adoption.

## 5. Native HTTP contract

All routes stay beneath the authenticated original Source Desk case/draft route:

    /api/operations/CASE/installation-sources/DRAFT/research

The original local host authentication and request custody apply. Do not create another service or separate browser journal.

| Method and suffix | Input and result |
| --- | --- |
| POST /import | Raw application/octet-stream, exact Content-Length; query requestId, actor, kind, name, bytes, sha256, sourceUrl, observedAt. |
| GET /requests/UUID?actor=... | Original same-actor upload status. |
| POST /requests/UUID/resume | Compact JSON {"actor":"actual operator"}; validate the retained complete body without reupload. |
| POST /inspect | {"fileId":"research-…","expectedSha256":"…"}; complete public native metadata, no bodyBase64. |
| POST /template | Original Workshare seed fields and optional full document. |
| GET /files/FILE?expectedSha256=SHA&describe=1 | Full original descriptor. Omit describe to stream the exact file. |
| GET /preparations/PREPARATION/archive?installationId=ID&revision=N&describe=1 | Freeze and describe the complete selected customer archive. |
| GET /preparations/PREPARATION/archive?installationId=ID&revision=N&expectedSha256=SHA | Stream exactly that previously described archive; later case edits do not select another file. |
| GET /original-requests/ID | A received draft's exact historical request record, with explicit original case provenance; not a replay route. |

Upload COMPLETE has schema, caseId, draftId, requestId, actor, status, original request, file and inspection. A lost response is resolved by the same request status. NOT_RECORDED with inputIntentRetained means the complete body is absent; reselect the exact original file under the same intent. INPUT_RETAINED means the full body is already present; use resume without sending it again. COMPLETE returns the original saved receipt.

An accepted original source that fails semantic validation remains retained for inspection and correction. Do not overwrite its bytes or silently substitute another file under its UUID. A genuinely different corrected source receives an explicit new upload request, while the old source remains in custody.
