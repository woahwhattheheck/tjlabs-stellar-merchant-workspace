# Research sources in the original Installation Source Desk

This chapter commissions an explicitly selected, issued Research product against the actual customer Workshare. It uses the existing Operations case, staff session, Source Desk draft, native preview and Installation Save. Full original economic project, issued package and customer return files remain exact receiving artifacts.

## Open the original customer case

Sign in as the actual recording operator, open the existing Operations case and its Installation Source Desk, then create or open a source preparation. Choose **Research Installation**. The same browser working-copy journal retains this tab together with the original source mapping, current source revision, pending requests, earlier copies and complete native receipts.

The current case must have its real Workshare source available. Use **Read attached original Workshares** and choose the intended Workshare. The desk preserves its source selection, commercial terms, phase hours, original native IDs and acceptance checks. If the attached source is not available through that inventory, enter its complete original Workshare source selection; do not invent source IDs, hours or contract terms.

## Retain complete Research inputs

Choose the actual source kind before selecting a file:

| Source kind | Complete original capacity | Role |
| --- | ---: | --- |
| Economic project | 480 MiB | Complete original project, selected issued product and original histories |
| Issued package | 256 MiB | Exact issued Research delivery and its selected source graph |
| Customer return | 256 MiB | Optional related complete customer return retained as context |

Record the actual source reference and original receiving or retrieval time with timezone. The complete Blob is hashed incrementally. Its original actor, case, source-draft identity, request ID, filename, length, SHA256 and provenance are saved before its first upload. The ordinary Source Desk 8 MiB file route remains unchanged.

Large Research files are immutable sidecars scoped to this original case and source draft. Upload does not add a small substitute to ordinary draft files or advance the source draft revision. Native Research validators inspect the actual original format; the browser never reconstructs or replaces its bytes.

After receiving, choose the exact project or package input and, when applicable, the matching original package and related return. Each kind permits one selected full original; other previously received files remain retained. Read its complete native inspection and choose an actual issued product edition. Current definitions and immutable issued definitions remain separately visible. The source-use rows are derived from that edition's exact entry and definition IDs.

A customer return is receiving context. This workflow does not automatically apply it to a Research product or change its paid publication, Buyer requests or financial custody.

## Save, prepare, attach, then original Save

1. Use **Compose complete selected source document**. This gathers the selected original inputs, issued product, all explicit source uses, actual Workshare case version and complete Installation document.
2. Review the complete Research selection JSON. Unfinished text is retained in the browser working copy.
3. Use **Save exact Research selection**. This is the ordinary Source Desk selection.save action, with its original actor, request ID and source draft revision.
4. Use **Prepare saved complete Installation**. The original preparation action verifies the installed source engine, exact saved selection hash, original full source files and all native rights/document rules.
5. Download and inspect the complete preparation outputs. Use **Attach complete Research source to original case**. The original research.attach action records the complete source provenance and recomputes the Installation preview against the actual new case version.
6. Use **Preview attached Installation** and inspect the complete native result.
7. Use **Open original Installation draft**. Then use the existing Installation editor's explicit Preview and Save to record the intended native edition.

Opening the draft does not save it, accept delivery, authorize spending or complete commissioning. An intervening case or Workshare change requires review of the current source and a new explicit preparation. Earlier complete source selections, receipts and documents remain retained.

## Interrupted uploads and native actions

A raw upload has three native statuses. NOT_RECORDED requires the same original file to be reselected; the desk verifies its filename, full bytes and SHA before replaying the unchanged request. INPUT_RETAINED means the full original bytes already exist: the original request's body-free resume endpoint continues native inspection. COMPLETE is adopted only when the full receipt matches the original actor, case, draft, source kind and body identity.

The **Continue exact original request** control reads status before deciding which continuation applies. An ambiguous response never creates a second upload or substitutes a new actor. A native validation failure remains visible beside the exact original request.

Selection saving, preparation and attachment use the existing Source Desk request journal. The full body is retained before submission; recorded receipts are reopened through the same request status, and an absent request is replayed unchanged. A failure in subsequent readback does not turn an accepted mutation into a new request.

The complete pending upload cannot be discarded by opening a different working copy. First resolve it with its original operator, or retain and inspect the exact complete copy without dispatching another mutation. For a confirmed absent upload or a completed 400/422 input-validation failure with all original bytes retained, **Retain unsuccessful input in history** reads native status and preserves the whole request and outcome before clearing only the active editor. It does not delete native source history. Unknown, timed-out, access-denied and still-unresolved operations stay pending.

An older or conflicting request cannot replace an active pending request. The native source draft and its revision remain authority.

After the Installation is actually saved, enter its original ID and revision and use **Download whole case and Research archive**. The native descriptor specifies the full file length and SHA256; the browser verifies the complete download using the original streaming download path. The archive may be up to 2 GiB and includes the whole Operations case, original selected Research input files, inspection, selection and source-use decisions, preparation, manifest and readable report.

Use the maintained native Research Installation receiver for independent receiving. It imports the original Operations bundle and receives the original Research formats through their native functions. It does not silently apply a customer return. Reopen the actual case, source preparation and saved Installation edition, inspect the same complete source identities and original receipt history, and retain the resulting independent receiving receipt.
