# Material catalogue source desk

This is the Material Catalog family inside the existing Grant Operations Installation editor. It uses the original retained catalogue reader, commercial Workshare and supplier-catalogues preparation profile. The original Installation editor remains the only Installation writer.

## Open the complete original work

Open the correct plan and Operations case, enter the actual recording actor, and receive the original complete commercial Workshare as a **new, unsaved Installation draft**. Keep its source, terms, phases, funding, payment evidence and receiving packet together. Select **Material catalogue source** from that editor.

Choose an attached typed material catalogue, or attach the original whole JSONL bundle. The typed source route accepts at most 128 MiB; existing native aggregate and whole-case budgets remain authoritative. Upload records the complete original command, actor, request ID, expected case version, original filename, exact Base64 bytes and SHA-256 in browser storage before contacting the native writer. A pending source intake must be recovered using that exact request. No alternate account, source ID or request is substituted after an uncertain response.

Name a working copy and open it. The desk downloads and hashes the full attached source, then obtains the complete native inspection bound to that source ID, SHA-256 and current case version. One full source body is retained per exact source identity in the complete browser archive. Named copies and checkpoints refer to that body; they do not silently omit it or duplicate a large feed for every note.

## Read the actual catalogue and original feeds

**Overview** shows the original catalogue, active edition, complete table counts, every retained edition and the plan/review inventory. **Records** exposes paginated complete original native rows, including wrapper identity columns and parsed record values. Pagination is an inspection of the selected complete catalogue; it does not select a reduced preparation.

**Sources** lists every original embedded source manifest with exact byte count and SHA-256. Read a bounded original byte range or download the complete original. The latter follows every native range to EOF, checks contiguous offsets, exact source identity, complete byte count and final hash. Binary text and split UTF-8 boundaries are explicitly described; they are not replaced with plausible text.

**Editions** compares two retained native edition IDs. Added, changed and removed original records remain available through all pages. This comparison is read-only. Cumulative source history and original supplier outcomes remain authoritative.

## Receive and review the original Workshare

In **Installation**, receive the complete current Workshare draft. The maintained template preserves its full commercial document and returns the original profile bindings, source bindings, missing-source decisions and optional supplier plan/review inventory.

The preparation selection has exactly these fields:

- schema and stable operationId;
- catalogId, catalogRevision and activeEditionId;
- complete bundleSha256;
- optional supplierPlanId, exact supplierPlanRevision and supplierReviewId.

There is no per-material subset field. Choosing a plan binds an existing retained plan revision. Choosing a review binds an existing review for that plan. The desk does not rerun a supplier evaluation or translate the catalogue into another supplier engine.

Review the labeled task fields and complete bindings JSON. Every source/receiving/payment/facilitator reference remains in the full original document. Incomplete typed JSON, notes and an unfinished name are retained as working text. They cannot be used as a valid preparation until the native engine accepts them.

Selecting **Prepare and review complete Installation** calls the existing native engine with the complete document, exact selection and full bindings. The saved result includes the original native preview, current case scope, source identity, preparation SHA-256, prepared document, complete source inventory, Workshare and rendered commercial/workorder outputs. Replacing a preparation or editing its input preserves the prior version in a complete checkpoint.

## Separate draft handoff and original save

**Open as separate Installation draft** first rechecks the retained catalogue against the current case and reexecutes the same read-only native preparation. The response must equal the retained result. The original Installation mount then checks current case/version/plan, exact attached material source and equality between the original native preview document and prepared document.

The mount creates a distinct unsaved draft and preserves every prior draft, original pending save, accepted receipt, source intake and per-window recovery entry. Its full complete document is persisted through the original editor. Use that editor’s existing **Review complete installation** and **Save reviewed edition** to save an immutable Installation. The material desk never calls installation.save itself.

After any case change, the desk explicitly marks a retained older preparation stale. Its frozen files remain downloadable. A fresh editor handoff or newly built customer package requires a current original preparation.

## Whole customer package and exact downloads

Build the complete customer ZIP **before the original Installation Save advances the case version**, or prepare again against the current case afterward. The handover route repeats the exact reviewed preparation request and expected preparation SHA-256. It uses the maintained full-source composer, then independently copies and reopens the resulting directory before returning the archive.

The browser verifies X-Material-Preparation-Sha256 and hashes the complete downloaded ZIP against X-Material-Package-Sha256. Its receipt records the exact bytes, SHA-256 and original preparation scope. Original feeds, selected catalogue, original Workshare/packet and explicitly referenced source/receiving/payment/facilitator attachments remain included by the native source composer. Unrelated case attachments are not selected implicitly.

Download controls also expose the exact original catalogue, complete preparation JSON, exact native selection, commercial HTML, commercial Markdown and workorder Markdown. They use the retained prepared edition, not later unsaved fields.

## Full working export, import and recovery

**Download all source and review history** exports the complete browser review: original source bodies and native inspections, named copies, all draft text, full prepared results, checkpoints, package/editor receipts and original source-command journals. The declared archive ceiling is 512 MiB. Capacity failures preserve the current full work; they do not shorten history or discard sources.

The original browser store uses an IndexedDB revision comparison. If another tab saved a competing revision, this tab stays intact. Download it, then explicitly reopen saved work or retain both complete alternatives. A same-ID incoming copy with different content is rejected by normal import. **Import as explicit alternatives** preserves both branches. Same original request IDs may merge only when their complete input and actual terminal receipt agree.

Opening a checkpoint creates a separate named review. Its source is still the same retained complete source. Reopening an older prepared checkpoint shows a stale warning if the current case version differs. Export a complete working archive before changing browser or clearing browser storage.

### Retain, map, preview and select

1. Retain the complete original full file in **Supplier files**. Inspect its filename, byte count, SHA-256, exact format JSON and provenance. Download and reopen the retained original when checking its source meaning. The complete browser archive retains original bytes before upload. Each original file is limited to 16 MiB for this intake route.
2. Use **Upload exact original supplier source**. The response retains the native source identity and original sample. CSV/JSON sample success does not prove the complete file is valid: native preview reads and validates the whole source. Original BMEcat parsing completes the full document before exposing its sample.
3. For BMEcat, **Read original BMEcat profile** retains its exact native source profile. **Use this original catalogue mapping** is an explicit mapping choice. It does not accept a supplier recipient plan or classify a partial price/product-data transaction as a full replacement.
4. In **Catalogue mapping**, explicitly create a new catalogue or receive a selected existing catalogue. Preserve its original tenant, identifiers, field/reference/unit bindings and operation semantics. Save the complete native mapping. The server returns its normalized mapping and actual revision; that exact result is retained alongside the submitted request. A different tenant requires a new catalogue.
5. In **Edition review**, choose **Complete replacement** or **Explicit complete upserts and deletes**, and select the exact original base. A delta requires a retained base from this catalogue. No base is inferred silently. Preview retains a new immutable edition and its counts; selection is a separate action.
6. Read the actual changed records and material pages, including their original identity and totals. Download the exact native preview. The preview is marked historical after any source, typed mapping, mapping revision, meaning or base change. Only a preview matching the current full basis can be explicitly selected.
7. Retain the complete update file separately and repeat its actual upload, mapping, preview and explicit selection. A full publisher snapshot used as upserts is an operator-selected interpretation: retain that reason in the mapping. Do not call it a publisher-issued delta.

Original request IDs are generated once and retained before dispatch. A completed response keeps the full original request, exact native result and exchanges. Native upload metadata may contain normalized format defaults; that normalization does not replace the original browser request or raw file.

### Unknown outcomes and retained alternatives

The browser stores every proxy dispatch attempt before sending. A response bound to this exact request with dispatchStarted:false proves only that this attempt did not dispatch. Earlier unknown attempts remain pending. A later read returning no operation is not proof that an earlier network attempt can never arrive.

Do not change an unresolved request or replace it with a fresh ID. Native COMPLETE, FAILED and INTERRUPTED outcomes are retained. FAILED/INTERRUPTED are terminal original operations, not resumable by changing their input; review the source and error before starting a new explicit operation.
