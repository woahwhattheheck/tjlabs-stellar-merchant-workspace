## Interrupted operation behavior

Each financial mutation and browser phase is followed by an awaited checkpoint. A checkpoint names the workspace and journals before copying all file objects. CURRENT advances only after the entire original inventory is complete. CANDIDATE retains an unfinished, newer intent. Receiving resolves that newer intent before falling back to an older complete case.

The receiver compares the full inventory and retained observation time as well as the financial revision. Browser progress can advance without a new financial write. If a surviving original case has later evidence, the selected manifest's complete original file set is recovered first. Missing original paths are filled and differing later workspace/journal bytes are retained separately while remaining in place. The resulting complete current case is preserved before replacing the earlier checkpoint pointer.

The native producer holds an exclusive file lock and passes it into the financial writer and its CLI. A terminated launcher therefore cannot free the lease while that writer continues. Shutdown uses the kernel's current PID namespace to observe the original writer's own process group, retains timeout observations, and requires that group to cease existing before recording a stopped snapshot. A differently mounted /proc view cannot supply that proof.

Every invocation has its own attempt output directory under the same original operation. A previous completed delivery is reusable only when the complete current case and source inventories match, all output hashes match, the complete archive manifest validates, and all original artifact-save entries succeeded. Earlier attempts and their partial archives remain separate inputs for exact recovery.

New accountant outputs are written to private temporary files, flushed and published atomically. A matching interrupted prefix is retained as a named predecessor. An unrelated changed complete file fails the identity check.
