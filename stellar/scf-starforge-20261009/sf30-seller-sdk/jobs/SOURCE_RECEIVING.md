## Source and receiving contract

The input packet contains the actual original signed commit response, the complete untruncated recursive tree, and the initial required paths. The unchanged distribution/git-object-receiving.py validates the original commit bytes and every tree object, then verifies the type, byte count and Git object identity of each selected blob. Objects are received into a private cache at DIRECTORY/repository.git. The metadata file is retained outside that new cache because the original receiver requires an empty new cache directory.

The initial paths contain the distribution builder and its own imports, the selected distribution and contribution specifications, the exact paid-job-files recipe and the license. The original builder then discovers its complete selected closure. When its original reader returns MISSING_SOURCE_OBJECTS, the programme retains that error and its exact object IDs, receives those objects through the same original cache, and resumes the same build. Each requested object is bound to an actual path and blob in the original tree. Additional paths only extend the original receiver's recorded selection.

OBJECTS_AVAILABLE means every object required by that receiver selection exists. It does not claim that every blob named by the complete recursive tree has been downloaded. The completed distribution manifest is the authority for the final selected paths. The programme does not substitute a hand-written approximation of the component or browser dependency closure.

## Provider reads

source_read.py uses the unchanged HostedAppsClient, paginated tools/list and actual connector metadata to select normal github_fetch_file and library_prepare_materialize. It does not guess an account or connector identifier. Source files use github_fetch_file with the original repository, exact commit, actual selected path and encoding=base64; this existing route supports binary source as well as text. Each returned SHA must match the original tree, and the complete decoded bytes must match its size and Git object hash. The full original request and returned envelope remain in the receipt. Successful Git envelopes are preserved in full. The existing git_file_leaf helper unwraps the original MCP structured, text or JSON-RPC envelope and stops at the base64 file with its returned Git identity: a JSON source file remains exact source text or base64, not another connector envelope.

The read boundary retries only an actual RATE_LIMITED response with a valid provider-supplied delay, at most nine reads, retaining the complete provider response privately and sleeping in chunks no longer than thirty seconds. Other returned errors remain the original error. An inaccessible account, a Git failure or an unavailable provider is not replaced with a different account or an invented retry deadline.
