## Run and continue

Invoke the complete controller from its selected source tree:

```sh

  /absolute/humanitarian-installed-input.json
```

Keep the input file, output directory and operation ID for continuation. Re-running this exact command reconciles its saved source cache, build, installation attempt, Applications entries, browser checkpoints, original request IDs and selected outputs.

The controller has four durable stages:

| Stage | Maintained operation | Complete retained result |
| --- | --- | --- |
| Source and runtime | Original Git object receiver, distribution builder and runtime installer | Source manifest, archive, critical whole-source identities and READY binding |
| Operated source | Original Applications review/save/connect/start, authenticated console and typed client | Browser note revision, original saved request, complete report and downloads |
| Independent receiver | Original CLI initialization, Applications startup, UI packet receiving and native reconstruction | Full history, received local note, older-packet replay and cold reopen |
| Handover | Original fixed package selection under its destination lease | Complete ZIP, exact member manifest and final receipt |

An incomplete source acquisition retains its missing-object list. Supply the missing objects to the same original cache and rerun the same controller. An incomplete installer preparation is retained and continued through the original installer recover/prepare APIs in a separately recorded installation attempt. No incomplete attempt is treated as READY.

### Applications and browser lifetime

The programme persists each Application's port, browser profile, save request and source workspace before review/save/start. Every start and stop is reconciled through the original Applications journal. A prior interrupted managed command is recovered through that same API.

Source and independent recipient use separate persistent browser profiles and fixed origins. Only one Chromium context is open at a time. The cold recipient check reuses the same recipient profile and origin, which preserves the actual IndexedDB draft, request and receiving history. The browser module borrows this Page and never creates or owns the server, client or browser.

The first source view is the pinned core r2. The UI generates the original full save input, which is retained before dispatch. Its request ID is reused through an intentional interruption, reload and Continue. The resulting r3 changes only reviewer and notes; all original source editions, mappings, aliases, policies, outputs, coverage and comparison results remain equal.

The UI exposes four complete downloads: the full receiving ZIP, report ZIP, full report JSON and original review input JSON. Screenshots and complete source/reference/mapping/history/output/comparison observations are retained alongside those artifacts. The typed client verifies the whole corresponding ZIP bytes. The installed CLI repeats the actual saved UI request and exports the same source revision to an independently retained output; repeating that same export verifies its complete descriptor and bytes.

### Independent receiving

The recipient is initialized through the original installed CLI and registered as its own Application. The UI receives the entire operated-source ZIP. Native receiving checks all complete original inputs, every saved request and revision, exact report assets and required archive membership.

The parent checks the original full reference, mappings, request history, saved review prefix and semantic report. Native Dataset SQLite files can vary across platforms; independent reconstruction is checked through the original complete receiving and semantic identities. Repeated exports from the same unchanged workspace must retain exact bytes.

A named local recipient note creates r4. Importing the older source r3 packet again must preserve that later r4. The recipient is stopped, cold-opened through the installed CLI, then restarted at the same origin/profile for the final browser inspection. Complete source counts, decimal totals and all prior saved history remain available.

The core's original r1 retains its deliberate duplicate/unknown-alias issues. The source r2 and subsequent note revisions retain 64 included rows with zero exclusions. The selected donor output preserves the exact 0.1 plus 0.2 total as decimal text 0.3. These records remain labelled engineering fixtures throughout.

## Interrupted outputs and cleanup

Every controller and operator input is immutable and every output directory has one retained state lease. Complete publications use private staging, fsync and full readback. Existing completed downloads are verified before reuse. Private partial stages remain available when a write fails.

The operator retains the complete workflow before final cleanup. If closing a browser, draining a client or stopping an Application fails, the complete workflow and original handles remain selected. The next invocation reconciles those original Applications and finishes cleanup before publishing final result.json. It does not create another business operation.

Original CLI and packaging subprocess arguments, output logs and returned status are retained. Reentry checks actual matching original child arguments before issuing the same command again. The package helper independently owns its permanent destination lease, verifies the entire member selection and every CRC/SHA, and atomically publishes only the completed ZIP. A retained complete ZIP without its final receipt can be verified and adopted on the next invocation.
