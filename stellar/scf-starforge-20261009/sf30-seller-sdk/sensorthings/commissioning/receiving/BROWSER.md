# Receive the original commissioning operator

The exported `receiveBrowser` function is the browser phase of `DATACOVE-SENSORTHINGS-COMMISSIONING-0C7A-20261012`. It runs on the server and workspace already opened by `receive.mjs`, using the original commissioning job and the complete final verification. The native programme retains its existing target, source, request history and phase IDs.

## Call and placement

The parent calls the complete handoff phase before the browser phase. This gives the browser an actual retained package to download. The browser still uses the original `13-original-operator-browser` phase identity; the existing `14-complete-handoff` and `15-fresh-forward-older-receiving` identities remain intact.

`receiveBrowser({origin, workspaceId, accessUrl, projectId, primaryJobId, verificationJobId, operationDirectory, browserExecutable, playwrightModule})`

All values come from the parent's current private server and selected native operation. The executable and Playwright module are existing absolute paths. No browser or dependency installation occurs in this module. Include this module and this guide in the parent's frozen complete source manifest.

The browser owns its own contexts and closes them before returning. The parent owns server shutdown. It does not open a second workspace, native writer, FROST service or data capture.

## Complete receiving journey

1. Open the selected original project. Walk every page of the complete retained source graph, compare the displayed row count and exact inspected row with the original response, and download a complete original source file.
2. Load the selected mapping. Edit a private unsaved draft, navigate away and back, then reload and authenticate to the same server. Verify the original project and draft survived. The mapping is not submitted to the application.
3. Walk every page of the selected native plan. Inspect the exact authored request body without rewriting its JSON numbers or native identifiers.
4. Walk every page of the original native job. Inspect the complete attempt history and download an actual retained request or response file.
5. Load the actual pinned STAM map and Leaflet1.9.4. Walk all660 retained observation identities through the real map table. Compare original kind, exact native-ID JSON and selected snapshot; inspect the original native detail. Actual retained geometry and loaded Leaflet map controls are required.
6. Download the first selected complete project package from the real Receiving view and walk its complete project history.
7. Open a fresh mobile context at390×844, use all five sections and inspect the same retained package. Verify page width and the desktop keyboard skip link. Capture six actual viewport images.

All provider-facing browser activity uses the original application reads. The observed API/static methods must remain GET or HEAD. The selected actual responses are not replaced with fixtures. No plan acceptance, target write, outcome review or additional handoff is submitted by this phase.

Each of the three browser downloads is saved before its browser context is closed. The receiving code hashes the complete saved bytes and compares their size/SHA256 with both the original file metadata and the UI's own completed-download receipt.

## Interruption and retained selection

The first call retains its exact source module, workspace, project and original job bindings. A different binding is rejected without rewriting that operation's result or state.

The first source, mapping, plan, target-read snapshot and complete handoff selection are retained separately. A later legitimate export does not silently select a newer package or replace a completed browser result. Reopening a completed result checks its original package remains in project history and re-reads every saved artifact before returning that same result.

Incomplete attempts retain their own files and failure. They can repeat their read-only browser journey against the same selected snapshot. Earlier complete results are preserved when a subsequent artifact check finds a problem; the new failure is written to its own attempt directory. An unresolved or failed browser run never returns `completed: true`.

The native programme also re-reads all browser artifact bytes at its final custody boundary. This runs even when the browser phase itself is recovered from the parent's existing phase receipt.

## Outputs and completion

The operation directory contains the original binding and selection, current state, per-attempt downloads and viewport images, and the single completed `result.json`. Failure details stay in the relevant attempt directory. Access tokens and private launch URLs are omitted from retained summaries and error text.

A successful result includes the original selection, all seven completed stages, complete artifact identities, actual browser version and observed application paths. `completed: true` is written only after every owned browser context and the browser itself have closed.

Source review and syntax checks establish source readiness. Actual browser receiving completes only when the original full native programme executes this phase and returns its real complete result.
