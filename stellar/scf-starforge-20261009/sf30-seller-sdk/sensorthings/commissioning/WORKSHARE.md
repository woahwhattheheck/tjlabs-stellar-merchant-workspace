# DataCove SensorThings commissioning workshare

**Proposed implementation:** one source family to one existing FROST service, with reviewed mapping, native target operations, operator recovery and complete receiving.

**Fixed fee:** USD 7,800. **Delivery:** twelve business days after the agreed inputs and kickoff. **Payment:** USD 3,900 at kickoff and USD 3,900 at the accepted handoff.

This is a proposed engineering workshare for a customer or reference installation selected by DataCove. DataCove retains its customer relationship, data model and interpretation, service administration and production approval. TokenJunkie Labs supplies the agreed implementation, commissioning and receiving work. No customer engagement or purchase is implied by the reference source.

## What the receiving engineer gets

1. **Retained source and data-model intake.** One existing CSV or SensorThings source family, with an initial edition and one correction edition, up to twenty selected streams and twenty thousand observations per edition. Preserve each complete input, its owner/source reference, selected and excluded population, exact result types and timestamp text. Record each authored entity definition, unit decision and relationship mapping with its original row or JSON location.

2. **A complete commissioning operator.** Extend the maintained SensorThings Operations Desk with source inspection, saved target and mapping versions, complete proposed payloads, conflicts and review, current native jobs, STAM map/table views, and project history. Use the existing authenticated workspace and original request/revision controls. DataCove's STAM and the original Fraunhofer FROST Python client remain the underlying components.

3. **Native commissioning on the selected installation.** Inspect the actual target, review the full managed set, then execute approved create, bind or update steps through the selected original client. Retain sent bytes, returned bodies, typed target identifiers and source-to-target bindings. Compare every selected target entity's fields and relationships to its approved plan; retain any exclusions or unresolved differences for the responsible reviewer.

4. **Correction and operational recovery.** Apply the agreed corrected source edition, preserve earlier work and inspect its target effects. Exercise cancellation and same-job continuation on the agreed commissioning window. Reconcile an interrupted write from its original receipt or an explicit operator decision. Prepare and review a compensating plan for the selected managed changes, using retained before-images and current target comparison.

5. **Complete receiving and handoff.** Deliver the editable application and original-component source/notice closure, operating and recovery instructions, both reviewed source editions, mappings, plans, complete native request/response history, target bindings and comparison outputs. Receive the package into a separate private workspace; verify complete source/result bytes, repeat import, later compatible receiving and preservation of later work when an older package is opened.

The two editions use the same agreed source schema and target model. A different source system, custom server extension, additional target or new data-model family is a separately agreed change.

## Acceptance on the agreed installation

| Deliverable | Acceptance result |
|---|---|
| Source and mapping | All agreed input files are retained; selected/excluded counts and each field, result type, time, unit and relationship rule are explicit. Conflicting identities and missing required values are resolved or accepted by the reviewer. |
| Target plan | The selected target URL, complete payloads, managed identifiers, proposed changes and provenance additions are reviewed before a write. Existing target entities are bound or changed only as selected. |
| Native execution | Every approved step has its original outcome and typed binding. Verification reports the selected target fields and resolved relations for every included entity; remaining differences are disclosed and resolved or explicitly accepted. |
| Corrected edition and recovery | The selected correction, cancellation/continuation and reviewed compensation retain their original source, request and job identities. Reopening a completed operation does not dispatch its effects again. |
| Operator and receiving | The actual installed desktop/mobile operator can inspect the work and download complete files. A receiving engineer opens the full project, its history and original source/results in a separate installation, and repeat/forward/older receiving behaves as documented. |

Acceptance records the agreed software, mapping and target fidelity. DataCove or its customer approves the environmental meaning, scientific interpretation, legal data rights and suitability for use.

## Delivery plan

- **Days 1-2:** retain the agreed input editions, inspect the existing target and confirm the mapping/acceptance register.
- **Days 3-5:** complete the operator, exact native plan, original client/runtime and selected STAM interface integration.
- **Days 6-8:** commission the approved baseline and correction, review actual target comparisons and complete operational recovery.
- **Days 9-10:** finish the full receiving package and separate installed receiving workflow.
- **Days 11-12:** consolidate the two review rounds, resolve delivered-scope defects and conduct the handoff.

The delivery clock begins when both parties have accepted the input scope, target/access and commissioning window, the responsible data/technical reviewers, the receiving environment and kickoff payment. Delayed access, approvals or materially changed input are recorded with the resulting schedule adjustment.

DataCove supplies or approves the source files and their rights; the target data model, units and interpretation; one existing FROST endpoint and its service-level behavior; one Linux operator host and a receiving environment; the selected access/credential reference; an authorized target-change window; and one consolidated technical reviewer. Hosting, network, endpoint capacity and other chosen service charges remain with the selected services.
