# Groundwater Scientific Workspace in Applications

Open the complete original groundwater study through the maintained Merchant **Applications** lifecycle. The selected scientific workspace, Python interpreter and complete source are reviewed before launch. The original scientific UI and its operation engine remain unchanged.

**Receive & reopen a backup** adds a complete receiving workflow: select an original backup on the host, inspect every member, record a named receiving request, retain its exact archive and destination, invoke the original create-only restore, and open the independent working copy. Each working copy uses a distinct browser API namespace. A completed read verifies the retained archive, all original received members, native restore receipts and current workspace identity.

- [Operator and receiving guide](OPERATOR.md)
- [Native continuation input](native-input.schema.json)
- [Original scientific source contract](SCIENTIFIC_SOURCE.json)

The installed commands are `groundwater-application` and `groundwater-application-native`. The provider is `groundwater-application`; its catalog item is **Groundwater Scientific Workspace**. The separate **Groundwater Report Desk** retains merchant publication, SF88 and Operations receiving.

Starting this application opens an existing database. Scientific execution is still selected explicitly in the original UI and uses its original reviewed runtime. The managed receiving continuation consumes an existing study and complete backup; it does not install Python, acquire solvers, create a replacement study, start a model, or create a fresh backup.
