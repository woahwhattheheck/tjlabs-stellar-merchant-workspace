# Receive the complete Research comparison programme

This course receives the comparison product inside the maintained Research application, using its original dossier, blob store, portable stream, authenticated listener and installation source selection. Preserve the original scientific evaluator and private research input ownership when applying it to a real project.

## Source and installation

Use the full maintained `research-workspace` source selection or the existing complete repository installation. The comparison directory imports the original Research and Node store modules; copying this directory alone does not produce a complete application. Preserve the complete component, its browser assets, installed Research application configuration and private original connection file.

The full change includes the comparison contracts, immutable model, original-store adapter, authenticated routes, CLI and typed client, browser interface and styles, the original dossier/server/client/CLI joins, return-family registration and maintained source/distribution joins. [OPERATING.md](OPERATING.md) explains every user action and the complete measured-run contract.

Use the installed Research entry for the actual browser. The same listener serves the original application and comparison assets. Keep its configured private source store and token with its existing owner. Do not start a second listener on an occupied original operation.

## Run the complete native and browser continuation

Use [FOREGROUND_RECEIVING.md](FOREGROUND_RECEIVING.md) for one owned native-to-browser course over the complete original source selection. The launcher receives the same backend, starts the original authenticated Research listeners, uses a persistent browser profile, operates historical protocol review and original downloads, recovers prepared requests, exports the complete dossier and continues a named edit in the received project. It retains the original operation, exact source copy, stable browser origins and first completed output generation through interruption. Supply actual installed runtime paths and follow the guide's complete desktop/narrow and every-file inspection before recording rendered readiness.

## Run the original-store receiving controller

From the complete source checkout, run:

~~~sh
node stellar/scf-starforge-20261009/sf88-operator-buyer-cli/research-dossiers/comparison/receive.mjs --directory /absolute/private/comparison-receiving --operation ORIGINAL_STABLE_ID --reviewer "Actual receiving operator"
~~~

Use an absolute owned directory and a stable operation identifier chosen once for this course. Rerun the same command and directory to resume. Preserve the retained intent and full original request files. The controller uses GNU `flock` for one owned child lifetime and requires the installed original Node dependencies.

The controller creates a clearly identified training course for exercising application behavior. Its fixture result is marked `TRAINING_FIXTURE`. It does not calculate a project's scientific result or replace its original measured inputs.

The whole course uses the actual `openDossierStore` implementation. It retains the original question and source, saves exact case/candidate/request identities, imports a complete raw run and member, records a named judgment and decision, creates deliberate protocol and candidate successors, and receives the original saved request after later revisions. Decimal-string and explicitly undefined values remain unchanged.

It reads the paged original history, downloads the original run/member, exports the complete report in JSON, HTML and CSV, and retains the original streamed gzip dossier export. It cold-reopens that export in the original receiving store twice and replays the exact accepted request. The complete source, request and course identities stay in the operation directory.

Outputs live under:

| Path | Complete material |
| --- | --- |
| `store/` | Original course dossier, revisions and content blobs |
| `cold-store/` | Independently reopened editable dossier and original source |
| `requests/` | Exact saved comparison requests used for first apply and recovery |
| `outputs/` | Original raw run/member, complete report editions and streamed portable export |
| `receiving-result.json` | The controller's retained result and original identities |

A successful controller result has `BACKEND_RECEIVING_COMPLETE`; browser and literal inspection remain separately recorded. Read the actual result rather than treating a launched process as completion. Open the generated files before assembling a customer handover.

## Inspect the populated browser

Attach the original Research application to the course's owned store through its normal setup. Open the actual dossier and **Comparisons**. At desktop/screenshare size and 390px width, use and view the populated application:

1. Open the case and its exact criterion protocol. Inspect the original source edition and complete locator. Use **Protocol edition** to select the controller receipt's original `caseVersionId`, then its later `currentCaseVersionId`; confirm the displayed scope, criteria and candidate choices belong to the selected edition.
2. Read candidates and their complete configuration. Prepare a successor working copy, enter actual draft text, reload it, and confirm that the full original body remains.
3. Open Import measured run directly after selecting the first case. Confirm the candidate choices match the visible case and selected protocol. Preserve an unfinished working copy, switch protocols, and use **Reopen this working copy's protocol** to restore its original basis without changing its entered values.
4. Select the receipt's earlier `caseVersionId` in **Protocol edition**, then select **runs**. Inspect its original retained run and download its complete raw JSON and member. Reopen them in their intended application. Compare actual bytes with their declared identities. Switch to the later protocol and confirm the earlier run remains under its original protocol rather than appearing as a new-protocol measurement.
5. Under the earlier protocol, open **judgments** and **decisions**, including their original run IDs, reviewer, time, rationale and limitations. Read the exact record details, then return to the later protocol deliberately before preparing later-protocol work.
6. Read the measured/judgment tables, scroll wide tables by keyboard on a narrow screen, and open complete row definitions. Read and download a previous protocol's report through the selector and its case-edition row controls. Confirm the selected protocol and original dossier revision in the complete report.
7. Use HTML, JSON and CSV exports; after each download confirm that other controls remain usable. Open the CSV in a spreadsheet and the HTML in a browser. Check actual labels, values, undefined reasons and full model.
8. Exercise a real validation error on an unaccepted working copy and recover the entered fields. Preserve/download a complete working copy and open it again.
9. Use two tabs with the same draft. Refresh a clean copy after a remote save and inspect the whole new text. Make conflicting local edits and confirm that the losing tab retains its entered copy for download or separation.
10. Prepare a complete request, interrupt its response, then receive the same saved request. Reopen the unchanged accepted record after another operation advances the dossier. Create an editable successor without rewriting the old request.
11. Export the entire original dossier, reopen the received project, inspect its original files and history, and perform an additional named edit in the receiving workspace.
12. View relevant empty, loading and error states. Interrupt an unaccepted protocol/page read and confirm the prior complete case, protocol, section and page remain visible. Navigate to another dossier while a read is pending and confirm that the original response does not appear under the new selection. A late edition-inventory or page response must not overwrite a later selection.

Look at every captured screenshot. Inspect actual foreground/background pairs in the installed host, disabled labels, form wrapping, focus states and table scrolling. Fix the real source if text clips, controls break or downloads omit material, then rerun that affected action in the same course.

## Receive real evaluator output

For a customer study, retain the complete original protocol, source editions and permission context. Use that project's exact evaluator and rules. Send the evaluator the run contract in [OPERATING.md](OPERATING.md) and `contracts.mjs`, plus the actual case, candidate and source identities.

Keep full original input and output bytes, command, engine release, dependency/runtime choices, cohort and denominator identities, time, exit/status and logs. The envelope's complete producer result retains the evaluator's domain structures; metrics refer to the exact measured criteria. Import the original envelope without recomputing or relabeling the scientific output in the generic workspace.

Projects with different populations, modeling targets or study protocols remain distinct comparison cases. Record actual paired analysis, subgroup interpretation, uncertainty and sensitivity only when present in the original evaluator's output. Review comparability from the full source definition before producing a recommendation.

Model/platform/architecture studies and health-risk-adjustment studies retain their own protocols. Their researchers own their methodology and final submissions. Shared application source supports distinct studies; customer data and commercial proposals remain in their authorized private workspace.
