# Prepare original output in the Research application

## Start in the existing comparison

Open the original Research application, select its dossier and research question, then open **Comparisons**. Create or select the exact case and protocol edition. The protocol defines the actual measured criteria, units, purpose, population and original method references.

The **Prepare original output** desk continues that selected case. It uses the same authenticated listener, original tabular preparer and comparison store as the terminal workflow. It preserves literal producer values; scientific calculations and interpretations stay with their original producer and investigator.

Begin **New original output**, or choose a saved original-output working copy. Its dossier revision and case/protocol edition remain visible. Selecting another protocol does not change a retained working copy's basis.

## Retain the complete source

Choose the producer's complete CSV, TSV or semicolon-delimited table. It must have one measured result per row, exact named headers and no more than 10,000 rows. The reader supports quoted delimiters/newlines and a UTF-8 header BOM. It preserves strings, numeric lexemes, blank cells and source line references.

Select original workbooks, reports, figures and logs with **Add original workbooks, reports or logs**. Give each original a meaningful role, package member path and media type. The desk saves each complete file in the browser's private working-copy database, verifies its byte count and SHA256 and deduplicates identical content. A browser storage failure preserves the entered work and stops submission until it can be saved.

Choose **Read exact headers and source rows** after changing the delimiter. Every original row remains readable in the full source table, including rows that will be outside the eventual selection.

An existing complete preparation plan can also be opened. First select all the original files named by that plan. **Open existing complete preparation plan** compares each selected file with its original hash/byte identity and requires the same selected protocol. It binds logical file references to the selected browser files and retains the complete original plan as another original artifact. The resulting browser plan and the original incoming plan both travel in the prepared run.

Each original file can be downloaded directly from its verified browser copy. Before presenting the result, literally open its actual workbook, PDF, image, report or other content with the appropriate application.

## Map original values

Select the complete original row key, including every dimension needed to distinguish the original occurrences. Empty or repeated keys appear as findings. The key determines the source occurrence; the importer does not aggregate repeated measurements.

Map each measured criterion, label, original numeric value, unit, complete definition and population/segment reference. A mapping explicitly selects an original header or a reviewed literal. The numeric value always selects a source column. Its unit must match the selected measured criterion.

Retain each original denominator component separately: for example the named denominator basis, exact source denominator and period. Add further named components when the actual source requires them. A person count, member-month count, currency amount and risk-weighted population remain distinct quantities.

Enter the exact unavailable tokens as a JSON array, including an empty string only when that is the source's meaning. Select the original unavailable-reason column or enter an explicit reviewed explanation. Missing output remains null with that explanation; source zeroes remain zeroes.

Unformatted decimal strings such as 0, -1.25, 1.2500 and 4e-7 remain exact. Currency symbols, decimal commas, grouping marks, percent signs and leading/trailing whitespace require an explicitly reviewed producer export or conversion. Preserve that conversion and its complete original file as artifacts.

## Select and review every row

Add exact column filters when the chosen output covers several source populations. Different filters combine with AND; listed values within a filter match any exact value. Filtering never removes a source row from the review.

**Complete row review** provides full-record search, disposition selection and all pages of the original rows. Open each row's complete source values and finding. A reviewed exclusion selects the exact complete key and retains the entered reason, actual reviewer and review time. It can be removed only in an editable working copy or successor.

Prepare again after changing a mapping, filter, exclusion or original source. **Prepare and review complete output** uses the same native parser and mapper as the terminal preparer. The response binds the actual selected dossier revision, original protocol, exact complete plan, source identities and implementation files. Every selected, unavailable, reviewed-excluded, outside-selection and unresolved row remains in the review.

A review-required preparation has no importable native run. Correct the actual plan or source selection, retaining previous complete downloaded copies when relevant. A READY preparation still requires the operator's review of cohort, period, denominator, unit, source limitations and comparability.

## Record the actual producer edition

Enter the actual candidate name, type, release and operating context. Preserve its complete configuration and source references.

Enter the original run identifier, actual result state, original start and finish timestamps, elapsed time when available, producer name/version, command, runtime and configuration. Select **Imported producer measurement**, **Original native execution**, or **Explicit training fixture** according to the actual source. These labels are not inferred from successful preparation.

The input definition should retain observation dates, paid-through/as-of/source-release dates, cohort/filter membership, measure basis, denominator, currency/price year, runout and applicable case-mix qualifications. Different definitions require an explicit comparability judgment; a repeated label does not establish an equivalent measurement.

Original limitations and source references stay in the complete run. Source-native calculations are not rerun by this desk.

## Save the candidate and complete run

Enter the actual operator identifier and name. When the preparation is ready:

1. **Freeze and prepare candidate request** saves the complete original candidate command and UUID before any mutation. The source plan and file selection become read-only.
2. **Apply or receive original candidate** sends that exact saved request to the existing comparison writer. An interrupted reply continues the same UUID and body.
3. After the original candidate edition is received, **Prepare original output import** saves a complete run-import command bound to that exact candidate and protocol.
4. **Apply or receive original run** retains the producer table, complete original files, original preparation plan, complete source/mapping review and native run in the same dossier.

The two accepted commands remain explicit original dossier operations. Named scientific judgments and final decisions continue through the existing comparison controls.

A revision conflict preserves the complete original command. **Review current revision and prepare successor** first reads the actual original request at the newer saved dossier revision. If it was accepted, the desk receives it. If the old request is absent at a newer revision, it retains that superseded attempt and prepares a new UUID with the same reviewed payload at the current revision. It does not refresh a request silently.

Opening a complete downloaded working copy rechecks its file identities, original preparation and accepted operation history through read-only application routes. Original native commands are never executed merely by opening a file.

## Save, reopen and hand over

The complete browser working copy includes original source bytes, all fields, the selected protocol/revision, exact preparation and native command/result history. Each write compares the current saved browser revision. A separate tab cannot replace a newer working copy or its pending UUID. Unsaved copies keep their original browser comparison revision and complete body while navigating between dossiers. If another tab has won that comparison, **Preserve visible work as separate copy** retains this complete draft under a new working-copy identity and leaves the other edition unchanged. Download remains available when browser storage cannot accept the copy.

**Download complete working copy** produces its entire JSON, including all original files and saved requests. **Open complete output working copy** restores that source in the same original workspace and dossier. A different retained local edition gets a separate working-copy identity rather than overwriting it.

**Create editable successor** preserves the original copy and commands, explicitly selects the current dossier revision under that same protocol, and reopens the actual source/mapping selections for a new edition. Preparing and applying a successor creates an explicit later candidate/run under the chosen original protocol.

After the run is retained, use the original comparison reports, original-file downloads and named review controls. The original dossier **Export** carries the complete editable project, every accepted original run/artifact, preparation plan and history. Reopen that dossier in the independent receiving workspace and continue the same source and protocol. The browser working-copy file preserves unfinished local preparation; the dossier export preserves accepted application work.

## Complete recipient use

The producing worker uses the actual populated application at desktop and narrow widths. Operate the file inputs, source table, filters, full row details, reviewed exclusion, complete preparation, original candidate/run requests, conflict recovery, downloads and same-case reports. Reopen the browser working copy and independently received dossier.

Open and use every exact outgoing attachment and export: HTML reports, CSV in a spreadsheet, JSON, workbooks, PDFs, images, maps, slides, audio/video or other included formats. Extract archives and open their actual contained deliverables and editable project. View captured screenshots; screenshots, metadata and source checks alone do not substitute for recipient use.

Join this desk to the existing Research foreground receiving operation and its actual dossier/question. Preserve its source selection, process lifetime, original browser owner and completed phases. Reuse the accepted original producer output; keep training fixtures explicitly labeled and separate from customer or scientific execution.

## Installed source and API

The maintained research-dossiers contribution includes the complete desk route, public module/style, updated preparer, browser-storage helper and this guide. The original Applications entry and authenticated listener stay unchanged.

Read-only POST routes beneath the selected original dossier are:

- comparison/output/table — exact selected file and delimiter to complete native source rows.
- comparison/output/prepare — exact protocol/revision, full plan and complete source files to the original preparation result.
- comparison/output/verify — recompute a saved preparation against its retained protocol at the current authorized dossier snapshot, preserving its original basis revision.
- comparison/output/request — exact original native command to its COMPLETE or NOT_FOUND result at a saved dossier revision.

Accepted writes use the existing comparison/reviews route and its original full command hash. Reports, original files and the complete editable export use the original comparison and dossier routes.
