## What the course actually does

The first phase calls the unchanged receiveComparison function. It retains the original dossier/question/source; explicit case and candidate versions; a complete raw fixture run and attachment; named judgment and decision; later protocol/candidate versions; the accepted-request replay; JSON/HTML/CSV reports; a streamed complete dossier export; and an independently reopened original store. Read its complete receiving-result.json for actual IDs and results.

The browser phase uses the same original operated store and actual application. A persistent private browser profile preserves IndexedDB working copies and compare-and-swap revisions across restarts. The actual protocol selector restores the earlier protocol for its run, artifact, judgment, decision and report. It deliberately selects the later protocol before preparing later-protocol work.

The full module performs:

- Desktop operation at 1440 pixels and narrow operation at 390 pixels, with populated forms, reports, details and original source records.
- Actual displayed report generation retained before each report download, with the original dossier revision, protocol and complete model. The maintained renderer must reproduce every downloaded HTML/JSON/CSV byte. Same-revision files must also match the original native files. Later legitimate dossier editions retain their separate generation and must preserve the complete original protocol/run/judgment/decision/source records. Raw-run/member downloads always match their original whole-byte identities.
- A failed protocol read, proving the prior case, protocol and record page remain visible, followed by successful selection.
- Incomplete configuration entry, an actual validation error, reload and complete working-copy download.
- Clean cross-tab adoption and a conflicting local edit preserved as a separate complete working copy.
- Recovery of any already prepared complete request from the durable browser draft before another preparation. The same original request is retained before POST; a new interruption attempt records the actual server return before dropping only its browser response. After a restart, the same UUID is received and then explicitly replayed. Intended dispatch, observed return and observed response interruption remain separate facts.
- Dossier Export through its actual application control, independent portable reopening through the original application, and a named edit saved and reopened there.
- Actual opening of downloaded HTML and complete original JSON/CSV contents, plus retained populated screenshots.

Fixture values keep exact decimal text and explicit undefined reasons. Reports continue to identify the training fixture. The browser module does not rank or recalculate measurements.

The authenticated listener is the maintained startDossierWorkspace function. Its original close method drains its owned services. The launcher owns only its two listeners and browser context. Signal handling closes those owned resources; no unrelated process is killed. A cleanup error preserves the execution error as its cause. The final foreground result is written only after owned cleanup succeeds.

Immutable intent, request and result files publish from a complete fsynced temporary file through an exclusive hard link. An interrupted temporary write never occupies the final original name. Existing final bytes must match exactly. Mutable progress publishes by atomic replacement, followed by parent-directory fsync.

Every screenshot has a distinct attempt path. An interrupted capture cannot overwrite bytes named by an earlier progress record. Download phases retain their source/operation binding before requesting bytes. Each attempt has its own subordinate directory. A completed file is fsynced and hashed, then its full attempt receipt is published before selecting it as the original download. On restart, the first durably completed attempt is recovered before any new export request. The selected file is linked to its final name without replacement, so the first portable generation and its original exportedAt survive a crash between download completion and phase progress. Incomplete attempts remain retained private history; they are never mistaken for completed downloads. A report attempt also binds the exact complete report model shown by the application before its export control is used. Recovery verifies its selected bytes against that retained model, never against a newer overview. The original backend generation remains unchanged beside these browser generations.

Preparation and actual request dispatch are separate checkpoints. A crash after IndexedDB preparation but before filesystem progress recovers the exact prepared request from the application. A crash after dispatch intention but before the POST permits the same UUID's first accepted result to have duplicate:false; the next explicit replay must have duplicate:true and an identical original operation. The original API's first acceptance returns HTTP 201; a duplicate returns HTTP 200. Both are retained as actual observed outcomes. A stored intention is never described as an observed interrupted response. Phase completion retains all intermediate original-return observations. If a completed browser progress record survives before browser-result.json is published, resume verifies its full output inventory and publishes that exact retained completed state before returning to the foreground collector.

An error records the actual exception in foreground-error.json and retains the original phase files. Browser errors retain timestamped records. Reuse the same input and operation after resolving the concrete fault.
