# Complete comparison handover

This module exports a selected case and protocol from the existing Research dossier for attributed staff review in the maintained LDA Research handovers workspace. It uses the same original dossier store, comparison event history, portable serializer and report renderer. It performs no new research run and recomputes no scientific metric.

## Select the actual saved generation

Use the original Research comparison workspace to select a saved dossier revision, case ID and case version ID. These are immutable selection values. A case title or the current dossier head is not a substitute for the selected revision. The original receiving course's accepted final operation receipt carries the pinned dossierRevision; later browser work may legitimately advance the current head.

Run the installed maintained application:

```bash
node comparison/handover-cli.mjs \
  --store /absolute/existing-research-store \
  --dossier d_ORIGINAL_UUID \
  --revision SELECTED_INTEGER \
  --case ORIGINAL_CASE_ID \
  --case-version ORIGINAL_CASE_VERSION_ID \
  --operation ORIGINAL_HANDOVER_OPERATION \
  --directory /absolute/private-handover-directory
```

The command path is relative to research-dossiers. Node and Python must already be installed. Select an actual Python executable with --python if needed. No external account, provider call, payment, background listener or new database is involved.

The producer borrows openDossierStore. It requires all five original methods getMetadata, listRevisions, comparisonReport, exportComparison and exportStream. The complete reusable function is exportComparisonHandover(store, dossierId, options) in handover.mjs. It does not own or close the caller's store.

## First publication and replay

Before producing bytes, the private operation directory retains intent.json with the original store path and full selected generation. Its exclusive original private lock prevents a second writer from racing the first. Reusing that directory with a different source, case, protocol, revision or operation fails. Use a distinct deliberate operation and directory for a later generation.

The first complete original dossier.research.json.gz is atomically retained. A retry preserves it, including its original exportedAt value. All comparison JSON, HTML and CSV bytes are generated from the same selected revision and explicit case version. Saved source files and manifest must remain byte equal. The archive is written to a private temporary, checked completely, fsynced and published without replacing an existing file. An existing archive is re-opened, every member is checked, and the original immutable handover-result.json is returned. Later legitimate work on the original dossier is unaffected.

Keep the whole operation directory if the process is interrupted. Do not remove intent.json or substitute the latest dossier head. An outcome-unknown retry uses the same arguments and directory; no research operation or purchase is replayed.

## Delivered members

Research_Comparison_Handover.zip contains manifest.json, selection.json, dossier.research.json.gz, comparison.json, comparison.html, comparison.csv, README.md and six exact engine source members.

The portable retains all original dossier revisions and all retained source, run and artifact blob bytes through the selected revision. The report contains this case's full operation history and case/candidate editions, together with the selected protocol's measurements, judgments and decisions. Reference-only sources remain references with their original access terms; the exporter does not fetch them.

engine/ contains the exact fixed inspection source in its original relative topology: node/store.mjs, research-dossiers/portable.mjs, and comparison/contracts.mjs, model.mjs, render.mjs and inspect-handover.mjs. This is the complete inspection dependency set, not the complete editable Research application. Use the original installed Research application/distribution to edit or receive the native dossier.

## Receiving and authority

The installed LDA reader verifies every ordinary ZIP member, the exact engine identity, original portable hash chain, complete blob byte hashes, comparison event transitions and semantic bindings, and exact equality of the report regenerated by the original comparison renderer. It runs its installed reader, never an executable taken from the uploaded archive.

The comparison inspector does not replace the original complete-dossier semantic validator. For full native dossier receiving, pass dossier.research.json.gz to the maintained Research portable receiving/Open route, which invokes original reopenStream. LDA separately retains source-bound staff notes and explicit colleague-return choices. It does not change source measurements, candidate versions, named judgments or producer decisions.

Measurements retain producer kind and status, raw file identity, exact candidate/protocol, cohort, definition, unit, denominator and artifact references. Equal labels do not establish comparable populations or methods. Missing values retain their original reasons. TRAINING_FIXTURE runs and software-course annotations remain explicitly labeled. No automatic ranking, inferred scientific acceptance or inherited reviewer identity is added.

## Bounds and source closure

The whole archive and decoded members are each limited to 256 MiB. The original portable also has its maintained 256 MiB streamed bound, 8 MiB revision-entry and 64 MiB blob limits. Complete comparison report/inspection projections must fit 32 MiB. The reader rejects an oversized complete selection; it never clips raw runs, drops older versions or truncates sources to make it fit.

Install the producer together with handover-archive.py, handover-cli.mjs and inspect-handover.mjs in the original comparison directory, and retain the original application dependencies. Install the six exact inspector members under LDA tools/phone_driver/support/research_comparison. The LDA Python reader pins their exact bytes. Updating the inspection engine requires a reviewed successor of those pins; a mismatched carried engine fails explicitly.

Its operations/research_comparison_receiving.py prepares a complete editable plan and delegates the whole course to the existing research_handover_receiving. Open the complete HTML, JSON, CSV and native portable with their proper applications, inspect the original source members, and inspect the final LDA review/Brief/export and received copies. Source publication or a successful syntax check does not establish that a native host or browser has completed this course.
