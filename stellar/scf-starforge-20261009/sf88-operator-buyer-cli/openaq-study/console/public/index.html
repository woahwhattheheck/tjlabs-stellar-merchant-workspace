Operate and hand over one complete study




1 · Select the source
The host initialization chooses a reviewed handoff for inspection, that handoff with an existing original operator for acquisition, or a complete customer delivery for offline receiving. Its source hash and configuration remain fixed.
Observation values, units, sensor and parameter identity, offsets, interval meaning, flags and attribution remain in the original study. This application does not calculate regulatory AQI or health classifications.


2 · Approve original requests
Review the query, offered payment option and total cap, then prepare. A native merchant release can run the original Buyer. Each page presents the original native review and budget estimate before approval. A challenge-only release requires a separate native merchant release for paid acquisition.
Approve only the exact displayed page request. Original SF36 reservation, signing, settlement and accounting remain authoritative.


3 · Resume without guessing
If an HTTP reply is lost, retain its request ID and read that request on the same listener. After a host restart, inspect the saved Buyer and choose original recovery. Preparation, export and receiving reuse their original saved selections. A missing HTTP request is not permission to repeat a payment.
Stop active request aborts this host's operation and retains its original outcome for recovery; it is not a payment reversal.


4 · Receive the whole delivery
Export creates the original delivery directory with its manifest, source study, session archive, accounting, outputs and operating guide. The download action checks each declared file hash. Keep the complete directory; copying a report alone is not a full receiving handoff.
On a receiving workstation, initialize receive mode against that directory and manifest hash, then Receive and Reopen. No source-provider request or signing configuration is needed for this path.


Installed and agent use
Start and stop this application through the original Applications manager or openaq-buyer-console serve. The installed ./buyer/openaq-study/console typed client connects to this exact instance. Closing a client only closes its own requests.
The host runs on Linux with the existing flock, original Python/Buyer dependencies and, for browser acquisition, the original SF81 Unix-socket approval channel. The original terminal openaq-buyer commands remain available.


Keep source and operating history
Move or back up the complete private console directory using the original application/host procedure after stopping it. The original customer selection contains its absolute paths; portable transfer uses the complete delivery export and original receiving command.
Use the complete original developer guide in the installed package for initialization, typed calls, continuation and receiving commands.
