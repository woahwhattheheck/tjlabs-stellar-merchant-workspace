## Receiving and interrupted replies

POST /command persists an immutable request before a native write. Its request ID is32 lowercase hexadecimal characters. Same ID and changed body is rejected. Full JSON must be retained in the browser before POST, including workspace ID, action and args.

The response is a complete request record. COMPLETE includes result and reconciliation; PENDING includes the exact intent and safe last_error. Read the original request and replay that same command to receive it. Native error is not proof of no effect.

There are two authoritative no-effect boundaries: a StateError from the read-only basis calculation, and a StateError in the original save-query transaction followed by a successful rollback before any commit attempt. They retain the exact original intent as REJECTED with result:{error:{code},no_effect:true}. Replaying the same request returns the same rejection. The UI keeps that complete history, clears only this terminal pending selection, and lets the operator edit and deliberately submit a new command. Unknown errors or uncertain commit/transport outcomes remain PENDING.

For an uncertain pending operation, an explicit “Revise in alternative” may retain the original complete copy and its unresolved pending request while creating a separately editable copy. It must preserve prior_requests and reject an identical action+args under a new request ID; identical retries use the original request. This is an authored alternative, not cancellation or a no-effect claim.

- review: retain the full expected_source triple. Native review IDs intentionally exclude input-report bytes and paths; receiving an existing ID additionally checks its actual retained edition or open original report against that exact triple. The optional native precondition checks both source reads before review publication. A same-ID older report is an explicit mismatch, not the newly inspected source.
- import: require the exact completed workflow review and retain its request ID/full triple as the import basis. The original import_review checks that precondition inside its existing guard before returning a retained edition or importing a freshly opened delivery. Its existing final report-byte check still rolls back a report changed during import. The workflow checks the returned full source again. Original IDs and old callers remain unchanged.
- activate: the original native view writer checks CAS. Its exact expected historical transition or unchanged selected edition can be received without resetting a later view.
- save-query: the unchanged native _save_query_on writer and complete workflow receipt share one original DB transaction.
- export, source-handoff, warehouse-handoff: the unchanged DuckDBOperator retained request ID and native destination own recovery.
- publish: the same original VgiService request and its transaction own recovery.

A complete warehouse backup contains its own pending backup intent, because the backup bytes precede the outer completion receipt. Keep the returned complete handover receipt alongside the package. Do not claim a self-referential backup includes a receipt created after it.

Unknown native commands and explicit rejected intents remain readable with their exact intent. Correcting a source or selection requires an explicit new request, while the former request remains retained. Never rewrite it or turn an uncertain effect into absence.
