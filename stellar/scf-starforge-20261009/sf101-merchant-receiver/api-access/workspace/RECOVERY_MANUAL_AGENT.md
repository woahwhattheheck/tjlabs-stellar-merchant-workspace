# Original manual API agent recovery

The recovery profile supports the current generated agent setup and an original manual MCP connection. The manual route reads the native connection schema through the same pure decoder used by the maintained connection reader. It identifies exactly one configured alias for the selected customer UUID and original launch path. It retains the complete agent directory, including the original operation, snapshot, export, client-operation, download and input journals. Private session bytes remain private archive members; tokens and old endpoint values are not returned in the public selection.

A generated setup keeps its original four-member profile and normal setup inspection. A manual connection keeps its original connection bytes and source hash. The inspector validates all configured aliases and their declared directories, pinned inputs and purchase metadata within the selected state root. During staged verification it resolves these logical paths only through the retained archive map. It does not create missing directories, initialize Buyer or agent state, call a customer API, or start an MCP host.

The restored customer selection returns `manualAgent` for a manual connection, with its exact alias, customer UUID, connection file/hash, declared source-entry hash and original journal directories. It deliberately omits `agentDirectory` and `expectedAgentSetupSha256`, because those existing launch options configure generated setup. Passing the full selection to the normal customer launcher therefore reopens only the original customer. The original manual MCP operator may be explicitly started separately using the retained native configuration and normal current authentication. The saved endpoint or token in an earlier private session is historical evidence, not a resumed listener.

Keep the original `expectedEntrySha256` guard. If a received workspace is opened with different installed entry code, the native MCP connection must report the original source mismatch; recovery does not rewrite that pin. A separately reviewed connection change is an operator decision outside archive restoration.

Manual reopening rechecks the original connection and bound metadata, while leaving later customer edits, CLI journals and downloads untouched. A new or changed connection selection is an explicit conflict, not a request to recreate the former state. Generated captures retain the original public agent profile shape, and old generated profiles still use the same existing setup inspector on reopen.

An original manual connection can use `agent/connection.json`, `snapshots`, `operations`, `exports`, `client-operations`, `downloads` and `inputs`; no `setup.json` was authored. This compatibility makes those actual retained files valid recovery inputs. It does not claim that the source programme has been re-executed, that a stopped remote gateway is running, or that an API request has been dispatched.
