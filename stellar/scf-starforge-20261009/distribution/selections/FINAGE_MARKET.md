# Finage market review: selected installation and customer receiving

The `finage-market` product carries the original Finage capture client, retained
market-review application, exact customer mapping and export, managed
Applications integration, complete receiving program and original customer
warehouse. It uses the same Python workspace and maintained installation
workflow. It does not replace the provider, create a second data engine or change
an existing source/receiving operation.

The committed recipe declares eleven runtime/product commands, nineteen explicit
package exports, and the Finage and original Python Applications providers.
Its source includes the complete Finage warehouse reader, operating program,
installed receiver, original shared Python receiving engine, native source
workers, browser assets, managed release code and runtime installation closure.
Provider credentials and customer/source captures are supplied privately.

## Build and receive the actual selected release

In the existing runtime workspace's **Build a product** view, resolve the actual
retained repository/commit and select **Finage market review and customer
receiving**. Review the original source identity, declarations and optional
runtime profile, then continue that saved build/output to its complete archive.
[The original source-build workflow](../runtime-workspace/SOURCE_BUILDS.md)
retains the same UUID through source/build/download interruptions.

The original direct builder selects the same committed recipe:

```sh
node stellar/scf-starforge-20261009/distribution/build.mjs \
  --repo /absolute/existing/tjlabs-stellar-merchant-workspace \
  --ref ACTUAL_COMMITTED_SOURCE --selection finage-market \
  --out /absolute/releases/finage-market
```

Use the returned archive and full hash with the maintained installer:

```sh
npm install --ignore-scripts --offline --omit=optional /absolute/downloads/original-finage-package.tgz
./node_modules/.bin/starforge runtime-install prepare \
  --dir /absolute/private/finage-runtime \
  --archive /absolute/downloads/original-finage-package.tgz \
  --sha256 ACTUAL_ARCHIVE_SHA256 --feature schema --operator
./node_modules/.bin/starforge runtime-install install \
  --dir /absolute/private/finage-runtime
./node_modules/.bin/starforge runtime-install run \
  --dir /absolute/private/finage-runtime -- source
```

The operator uses the archive's original pinned dependency declarations and
actual host requirements. Select an existing Linux Python 3.11 or later, Node
compatible with the archive/profile, and `flock`. Node 24 can operate the original
native SQLite workspace. The processor and customer warehouse use Python's
standard library. Chromium and Playwright are selected only for an actual
browser-reading operation; the receiver does not install another browser.

Use the existing [runtime installation](../RUNTIME_INSTALL.md) and
[complete runtime transfer](../RUNTIME_TRANSFER.md) for the selected release.
Retain its actual READY directory, source root, profile/lock and original
manifest. Reuse an already completed matching runtime. A changed source commit
uses a new release/output rather than rewriting a retained customer operation.

## Retain original captures and source meaning

The [capture client](../../sf30-seller-sdk/finage/CAPTURE.md) uses the provider's
original REST/stream contracts. It preserves complete received bytes, request
and scope metadata, source hashes, known interruptions and explicit resume/
recovery context. It can receive an already retained complete source packet and
prepare the native dataset without contacting the provider again.

Inspect the selected provider method, dataset/model, credentials, time and
coverage declaration before acquisition. A returned record or stream timestamp
keeps its actual token, declared unit and kind. Preserve price/volume decimal
text, null/missing states and provider identifiers. An incomplete response or
stream prefix remains explicitly incomplete even when its available rows are
useful. The complete source, not a summary count, determines what was received.

Use `starforge finage-acquire --help` and the original capture guide for actual
capture/import/prepare arguments. Keep one stable original acquisition identity
and its retained files when continuing an interrupted operation. Importing
existing provider results is source receiving; it does not claim another live
provider request.

## Create or reopen the original review workbench

The prepared input follows
[CORE_CONTRACT.md](../../sf30-seller-sdk/finage/CORE_CONTRACT.md), schema
`tj.finage-market-workspace.v1`. Its source files and capture metadata remain
content-addressed beneath the prepared input.

```sh
starforge finage-workspace create \
  --dir /absolute/private/finage-operation \
  --dataset /absolute/received/workspace.json

starforge finage-workspace status --dir /absolute/private/finage-operation
starforge finage-workspace serve --dir /absolute/private/finage-operation --port 8431
```

An existing initialized workbench uses status/serve directly. The source root
defaults to the selected installed product; an existing receiver can supply the
same canonical source root explicitly with `--source-root`. Create retains the
complete input, all referenced source/metadata and the original executable
Python source in one immutable initial revision.

Without an explicit merchant plan the original wrapper records an unconfigured
deployment declaration. Private previews execute the retained local Python
source. They do not use a provider account, buyer signer or payment. Native paid
serving, where wanted by the actual deployment, selects `--native` in the original
runtime profile and uses the real service origin and payment tuple. Do not use a
service implementation quote as a transaction price.

The printed private operator URL opens the original market interface. The native
Python workspace remains on the same origin. Source editing, saved revisions,
named review choices, comparison, customer mapping, original preview outputs,
local draft recovery and full history all use that same native model.

## Inspect, compare and prepare a customer edition

The saved functions are `inspect_market`, `build_market` and
`customer_market`. Inspection pages the complete selected source's records,
findings, symbols, events, changes and sources through the original view
contract. The compact native result is bounded; full mapped records are streamed
by the original export command.

Choose the intended actual edition. Retain the provider/model/scope and capture
method for each source. Compare only an explicit comparable pair; a different
provider scope, independent reference, restarted stream or retained prefix does
not become a fabricated before/after pair.

The operator records source-bound findings and intended exclusions with a named
reason, saves the selected customer columns, and saves a native source revision
before building it. Original raw values remain available beside interpretation.
Customer mapping preserves exact JSON types, numeric text, provider IDs and
source identity. Private notes and operator-only source pages stay in the private
result; `customer_market` supplies the customer report.

The underlying original CLI remains available through:

```sh
starforge finage-workspace workspace \
  --dir /absolute/private/finage-operation -- --help
```

Use the exact completed native preview ID from the intended saved edition for
delivery. A completed preview is reused; reopening a workbench is not a reason
to reacquire data or repeat an accepted calculation.

workspace. Stop/reopen preserves the workspace ID and source history and creates

The same original application-review/save/start/output/recover commands are
documented in [Applications](../runtime-workspace/APPLICATIONS.md). Retain actual

  --dir /absolute/private/finage-operation \

The operator package additionally retains the exact native preview and complete
saved workspace/source/history. Reopen its existing completed result through the

## Receive two original exports in the customer warehouse

The complete [installed receiving guide](../FINAGE.md) documents the actual
`finage-receive` and `finage-warehouse` commands and package introspection.
Select two complete original export directories and their exact manifest hashes.
Their source roles and scope come from the original producer.

```sh
starforge finage-receive info
starforge finage-receive prepare \
  --first /customer/incoming/first-original-export \
  --second /customer/incoming/second-original-export \
  --first-sha ACTUAL_FIRST_MANIFEST_SHA256 \
  --second-sha ACTUAL_SECOND_MANIFEST_SHA256 \
  --output /customer/operations/finage-receiving-001 \
  --config /customer/operations/finage-receiving-001.json \
  --actor "Named customer operator" --operation-id finage-receiving-001 \
  --python /absolute/python3 \
  --playwright-module /absolute/playwright/index.mjs \
  --chromium /absolute/chromium --browser-node /absolute/node

starforge finage-receive run --config /customer/operations/finage-receiving-001.json
starforge finage-receive inspect --config /customer/operations/finage-receiving-001.json
starforge finage-receive resume --config /customer/operations/finage-receiving-001.json
```

Replace each illustrative path/hash with the original selected value. Preparation
is idempotent and retains the input, source, actor, decision and stable operation
identity. The complete native operation retains staged prefix continuation,
both source editions, named selection and stale-head handling, exact full/filtered
queries, complete exports, rollback, the original backup, fresh restore, and
desktop/mobile reading. If receiving finishes before an interruptible prefix is
observed, the retained result reports that actual outcome.

An existing operation continues from its saved checkpoint; it does not initialize
a second warehouse or replace a completed customer selection. The detailed
[operating program](../../sf30-seller-sdk/finage/receiving/OPERATE.md) retains each
actual command output and source correction.

For ordinary independent customer use, the original commands also receive,
inspect, query, activate, export and back up the complete warehouse:

```sh
starforge finage-warehouse status --warehouse /customer/finage-warehouse
starforge finage-warehouse backup \
  --warehouse /customer/finage-warehouse --out /customer/finage-backup
starforge finage-warehouse restore \
  --bundle /customer/finage-backup --out /customer/finage-restored
```

The backup carries its complete original Python receiving engine, SQLite state,
README and manifest. It can query/export the retained records and history on
the receiving host without the provider or original producer. A partially
imported delivery still resumes from the same complete original delivery files.
