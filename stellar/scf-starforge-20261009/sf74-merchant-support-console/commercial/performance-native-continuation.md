# Continue the original Performance operation from its completed commercial phase

The maintained `performance-native.mjs` used to retain its only final result after the complete Pricing-interface operation. An interruption during those interfaces caused the caller to reopen the original commercial phase, re-read its source and previews, export the same customer package and repeat recipient/MCP receiving. Its saved request IDs protected mutations, but that completed work and its allocations were repeated.

The new source retains `commercial-phase.json` once the existing commercial flow has completed and all of its owners have closed. It records state `COMMERCIAL_COMPLETE`. The original `flow-result.json` contract remains `COMPLETE` after the existing Pricing interfaces finish.

## Original identities and receiving

The checkpoint is published through the existing exclusive, synced `retainCaseArtifact` writer. It binds the original operation bytes, native/customer/output directories, case IDs, saved request files, measured/old-rate/revised quote IDs, source and document digests, complete package material and model versions. File hashing uses a 64 KiB stream instead of retaining complete file buffers.

On reopen, the caller checks:

- The exact original operation, native flow, customer flow, saved commercial requests and downloaded source/document materials.
- The complete original revised-pricing capture, customer package, received package and recipient source trees.
- The original source and recipient case revisions through the existing content-addressed CaseStore reader, including their complete workspace and runtime source identities. A later current case head remains available; receiving the old saved revision does not replace it.
- The selected configuration and snapshot bytes, the original usage manifest/report, and the committed Pricing manifest. A byte-identical config/snapshot may live in a different maintained-code checkout; the original native, case and output paths remain the same.

After those checks, it reloads the original performance envelope and the three saved performance/proposal requests, then calls the same `runPerformanceInterfaces` with the same IDs and `pricing-interfaces` directory. That existing operation retains its own request journals, receiving state, downloader checkpoint and loopback endpoint recovery.

## Memory and scope

The complete commercial flow is scoped to `runCommercialPhase`. Its models, case views, preview records, decoded source and reports become eligible for collection before the interface phase begins. The native reopen uses one model shared by tariffs and performance. The existing exact MCP source comparison now checks each chunk against the original bytes and updates a digest; it retains no chunk array or concatenated second full copy.

The original business calls, request payloads, quote values, source/export interfaces, final result fields and CLI arguments remain in place. An archive created before this checkpoint addition follows the original request recovery once and then writes the completed checkpoint. Publication of this caller is composed with the native04 source-graph version transition owned by the original receiving operator.

## Receiving an archived empty source directory

The original `receive-package` path opens the source-delivery service before receiving its manifest; it creates the declared `recipient-sources` directory even when the legal `sourceBundles` list is empty. The first commercial checkpoint still requires that original directory to exist. Full-work archives may omit empty directory entries. On reopen, only an exact saved `recipient-sources` tree with an empty `files` array may be recreated at its declared path with private permissions before identity comparison. A missing nonempty tree remains a missing material error. The final `completedAt` timestamp is assigned after the existing Pricing-interface operation completes; the intermediate phase keeps its own completion time.
