# Grafana delivery: source, implementation and receiving

Use this desk to attach a complete operated Grafana handover to an existing Merchant Support case. The original ZIP remains an SF49 source member. The reviewed mapping, readable native outcomes and task-linked deliverable remain in the original case history. Complete case export and receiving use the existing Support Handoffs and SF49 engines.

## Start the original host

Use the current Merchant Support release and the matching original Observability source, including `integrations/grafana_handover_inspect.py` and its original service/integration modules. Select the actual installed Python executable. From the Merchant Support checkout:

```sh
export SCF_PYTHON=/absolute/original/python
node stellar/scf-starforge-20261009/sf74-merchant-support-console/server.mjs \
  --cases-dir /absolute/private/support-cases \
  --source-dir /absolute/private/support-sources \
  --package-dir /absolute/private/support-packages \
  --grafana-source /absolute/commons/opportunities/ma_eotss_observability_2026 \
  --port 8784
```

Open the printed loopback address and choose **Grafana delivery**, or append `/grafana-delivery`. The browser receives neither host paths nor provider credentials. The optional source path is a host setting; it cannot be supplied in an HTTP request. This option is supported by the normal original server and CLI. The current managed-application connection format does not bind an external Grafana source, so managed JSON startup rejects this option rather than accepting an unreviewed path.

The installed `merchant-support` distribution includes the desk, original source-delivery dependencies, guide and `starforge merchant-grafana-delivery`. The matching Observability application is a separately selected original source installation. See [the full operator CLI](GRAFANA_CASE_DELIVERY_CLI.md) for its source/context inputs and exact commands.

## Prepare the saved case

Choose a case that already contains its actual runtime support capture, saved owner terms and implementation tasks. These are the same source inputs used by the existing Source delivery screen. The source transfer freezes the selected case revision; later case edits are never silently substituted.

Enter the actual receiving operator. Names are limited to 200 UTF-8 bytes by the original service. Select the complete native Grafana handover ZIP and choose **Retain and inspect**. The browser streams the original file into the existing SF49 upload, then prepares its original workorder/source edition. It does not start Grafana or a provider worker.

A source rejected because that saved revision lacks runtime support or terms retains its original command and error in Browser recovery. Open the current case, save those missing inputs, refresh the selection and deliberately prepare a new source. Unknown responses and active native requests continue with their original IDs.

## Read the complete scope

The inspector validates the original handover manifest and every file, the project and its retained revision history, every referenced Grafana source edition, the immutable provider objects and SQLite checkpoint, and the complete native job/action index. The displayed scope includes jobs not selected for this task mapping because they are still present in the private checkpoint.

Review these distinctions before delivering any file:

| Native observation | Meaning |
| --- | --- |
| Project revision and complete source history | The exact saved configuration and original source editions supplied in this handover |
| Selected operation IDs | The operations the handover owner selected; the desk cannot select an undeclared operation |
| Native job status | Its original recorded state; a completed query job can contain failed measurements |
| Target action status | The recorded apply/readback/reconciliation/rollback outcome for that resource |
| Pending jobs or unresolved actions | Work requiring the original target owner's review |
| Provider checkpoint | The complete supplied integration database and objects, including other jobs |
| Customer receiving | An explicit later observation in the original Support case |

The paired project and provider snapshots are separately identified. Read-only inspection does not establish simultaneous cross-database capture or stopped workers. File hashes establish exact bytes, not independent authentication of a customer's claim.

## Review and attach

Select the actual implementation tasks and only the native operation IDs that belong to the work. Enter delivery notes and acknowledge the full private checkpoint scope.

**Review exact attachment** is read-only. It retains the original and proposed plan/task definitions together in its returned selection. Expand **Complete retained selection** to review the native workorder's proposed source changes, source hashes and outcomes. Existing source task overrides remain under the original implementation model.

Confirm that exact review and choose **Attach to case**. The adapter uses four original case request IDs:

1. The reviewed intent becomes an observation material.
2. The original SF49 workorder is attached as a source edition.
3. The original ZIP becomes a source-backed deliverable linked to the selected tasks.
4. A readable HTML native-result review becomes an observation linked to those same tasks.

Each accepted step stays in the case if a later step is interrupted. The original case CAS and command receipt model preserve concurrent edits. No customer receiving, completion, deployment or payment is inferred by attachment.

A case revision conflict before the first material is committed is reconciled through original status. Only a returned native rejection plus `NOT_STARTED` and the actual changed case revision releases that browser attempt for a deliberate new review. A request with accepted steps remains its original continuation; it is not replaced.

## Resume accepted work

Browser recovery retains exact source/attachment inputs before dispatch and reads them back. The workspace binding includes the actual host case and source directories. A changed workspace cannot reuse another workspace's pending request.

Select a pending source or delivery to reopen its case. The native command/status receipt is read before continuing. If an upload is unfinished, select the same original file; the source engine compares retained bytes. A completed upload is used without requiring a second file selection.

If the server completed but browser result storage failed, the same original input is replayed through native command hashing. Do not invent another request ID to bypass an uncertain result. If a case's task definitions changed after the intent was committed, the accepted intent remains available and the original implementation owner resolves that change explicitly.

Changing the visible transfer or selected archive immediately clears the old inspection and confirmation. A failed attempt to open another source cannot leave the old source attachable under the new label.

## Export and independently receive

Open a saved delivery and choose **Reopen complete source**. The original member is resolved again and inspected afresh; its exact deterministic result must match the retained selection.

Use **Export / receive complete case** for the existing Complete delivery desk. Export the selected case revision and transfer the whole native package. Its history includes all original source bundles and unassigned members; the Grafana ZIP is not reconstructed or flattened.

On the receiving machine, start the original Support host with separate private case/source/package stores and the matching inspector source. Receive the complete package through Complete delivery, open the new local case, choose Grafana delivery and select its saved delivery. The original native receiving operation verifies the local case ID and imported revision. The original reviewed selection keeps its sender's case ID. Later local edits remain in that receiving case.

Use the same native receiving request for any lost-result recovery. The CLI's `receive` command performs receiving followed by fresh Grafana reopen in one operator call, and its repeated input reopens the verified native result. The UI locates the completed original package operation in its own package workspace; it does not trust an arbitrary JSON receipt pasted by a client.

Record the actual technical and customer observations in the existing **Implementation** receiving controls. Those records, their inspected material identities, later corrections and original task definitions continue to determine acceptance.

## Runtime and portable source

The native inspector has no target network action. It opens the original ZIP and extracted private read-only checkpoint, invokes the original project/source/ledger validators and removes only its private temporary extraction. The host drains its owned inspector process before closing. The original SF49 service retains upload/prepare and attach operations.

Keep the selected Merchant Support and Observability source revisions with the operator handover. The full native project package carries its own original app source, source data and provider checkpoint. This bridge's complete case package retains that original ZIP as one native source member and adds its saved inspection/task mapping; it introduces no second ZIP or case importer.

For automated operators, [GRAFANA_CASE_DELIVERY_CLI.md](GRAFANA_CASE_DELIVERY_CLI.md) specifies all input objects, exact source selection, immutable result files, export, full receiving and later reopen commands.
