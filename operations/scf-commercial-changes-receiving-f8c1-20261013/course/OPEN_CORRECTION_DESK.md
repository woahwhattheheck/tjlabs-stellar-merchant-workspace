# Open and continue the corrected billing workspace

This opener receives the complete correction-course ZIP into a new private Linux directory, runs its selected current Grant and native Receivables applications, and saves a complete next ZIP when the operator closes them. The original native backup remains the accounting authority. The opener does not create, issue, credit, collect or allocate an invoice automatically.

Use Python 3.11 or later and Node 22 or later. Browser automation and Playwright are needed for the producing course, but not for this customer opener. Choose ordinary persistent storage with space for the complete input, extracted source/account, restored working account and a new compressed edition. Keep the receiving directory outside every earlier native account/state root. Its parent must already exist.

## Receive a delivered edition

Keep the complete delivered ZIP and its independently supplied SHA-256 together. Replace the example filenames, digest and new destination with the actual delivery values:

~~~sh
python3 course/open-correction-desk.py inspect SCF_Correction_Desk.zip --sha256 ACTUAL_DELIVERED_SHA256
python3 course/open-correction-desk.py --node /absolute/path/to/node restore SCF_Correction_Desk.zip --sha256 ACTUAL_DELIVERED_SHA256 --root /absolute/private/correction-workspace
python3 course/open-correction-desk.py --node /absolute/path/to/node open /absolute/private/correction-workspace
~~~

The global --node argument belongs before the command. The restore command creates the named root with mode 0700; it must not exist already. It checks every ZIP member and CRC, safe member paths, the actual runtime selection and each selected file's byte, SHA-256 and Git identity. It then calls the existing authenticated native restore engine with the retained original identity pair and copies the whole primary planning work tree. It never substitutes the optional secondary independent receiving case for the original primary case.

The transport key stays in package/original-account/private/restore-key.txt. It is passed privately to the native recovery child through its environment, never printed. The account archive and key are co-delivered, so treat the whole folder and ZIP as private account material; co-delivery does not provide confidentiality from someone holding the package.

A failed first receiving leaves its partial root and logs intact. That directory is not marked READY. Retain it for diagnosis and receive the unchanged delivered ZIP into another new root. A READY installation is reopened with open; it is never overwritten by restore.

## Use the installed workspace

The open command prints the normal private owner link after both services and the same-ID connection are ready. Open that link in the browser. Choose Delivery operations, the retained case and Customer billing; choose the saved Freeform Solutions schedule. Its original changes, request-recovery controls and linked invoices use the current selected application source.

The native account uses the original workspaceId and sourcesSha256. The original adapter records only the new local transport address under each retained endpoint ID. Existing paid invoices, receipts, allocations, correction history and native request IDs are not reset. Any further financial operation is an explicit action in the original application, with its own existing checks.

Keep this terminal/process open while using the application. Private access details are also in private-access.json. They are local capability links and must not be published. A second opener for the same receiving directory is refused by its existing file lease.

## Close, save and reopen

Press Ctrl-C once for an orderly close. The opener independently stops the planning server, closes its workspace, terminates and reaps its native service group, and closes the logs. It then takes an authenticated full native snapshot and writes a new complete ZIP under deliveries/. The printed COMPLETE_PACKAGE_SAVED receipt and last-delivery.json provide its actual path, size and SHA-256.

The saved edition contains the current complete primary planning tree; the new authenticated native backup and private key; every selected runtime source; the original immutable input and original course; earlier backups indexed by manifest; and actual opening, connection and close logs. Each outgoing ZIP is fully inspected before publication. It keeps the same receiving layout, so inspect and restore can receive it into a genuinely different private root.

Reopen the same working directory after a normal close:

~~~sh
python3 course/open-correction-desk.py --node /absolute/path/to/node open /absolute/private/correction-workspace
~~~

This preserves later local edits and the installed native account. For a separate explicit export while all services are closed:

~~~sh
python3 course/open-correction-desk.py --node /absolute/path/to/node export /absolute/private/correction-workspace --output /absolute/private/next-correction-edition.zip
~~~

The output filename must be new. The source selection and logical account identity are checked again before snapshot. If shutdown or snapshot cannot complete, the opener retains the complete working directory and actual error instead of reporting a finished package. Check opening-history.json, opener-logs/ and any last-delivery.json before continuing. An abruptly killed process may not have saved a new ZIP; the last successful ZIP remains its own immutable edition.

Inspect the exact outgoing ZIP's usable files and reports. Capture meaningful light and dark surrounding-context states with readable labels and controls.
