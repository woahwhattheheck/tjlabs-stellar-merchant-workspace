The maintained BLS regional labor workspace gives a regional economic-development customer one editable project for official releases, regional analysis, dataset publication and complete customer receiving. The installed `bls-labor` selection opens through Applications. Its [complete operating entry](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/aee0d55e1c9964475fb1cf3b9db3a56e88109d8b/products/bls-labor/OPERATING.md) leads to saved county and regional analyses, monochrome charts, customer commentary and report revisions. The [regional analysis guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/8a9c1240a2cbb6600683e9ee27e5d70fcd361011/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/workspace/REGIONAL_ANALYSIS.md) covers complete customer files and definition reopening in the received working project.

The original Northeast Kingdom case covers Caledonia, Essex and Orleans, retaining 408 LAUS resident-labor observations and 96 QCEW workplace observations. Its [source contract](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/8a9c1240a2cbb6600683e9ee27e5d70fcd361011/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/contract.json) preserves the original files, dictionaries, source records, units, adjustment, disclosure and missing-value status. The [regional calculation engine](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/8a9c1240a2cbb6600683e9ee27e5d70fcd361011/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/workspace/regional.py) sums distinct county resident totals and computes unemployment from the original unemployed and labor-force components. Workplace jobs and wages remain separate, with regional weekly wages derived from quarterly wages and all three monthly employment counts. Every calculated statistic keeps its exact fraction and original source membership. Annual comparisons require matching coverage, including the retained eleven-month 2025 annual average.

The [complete original-case receiver](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/8a9c1240a2cbb6600683e9ee27e5d70fcd361011/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/workspace/receiving.py) retains the seven existing county/change briefings and prepares the complete regional analysis and its customer-commentary revision. Each regional report delivers all values, original observations and revision differences in JSON, CSV, printable HTML and a complete analysis ZIP. Its exported definition reopens for editing in the original or fully received workspace. The whole project carries raw source captures, observation indexes, analyst notes, report history and saved operations, so another analyst can continue the customer's next release.

[Native publication and customer receiving](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/8a9c1240a2cbb6600683e9ee27e5d70fcd361011/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/workspace/NATIVE_RECEIVING.md) use the original publisher plans, candidate review, dataset versions and SF88/Vitality receiving. A recurring service receives each new official edition, explains comparable changes, revises the customer's analysis and delivers both the updated report and the complete editable project.

### Continue the regional project through the customer's agent

The installed regional application now exposes the same saved analyst project through twelve customer-agent tools. The [current operating guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/aee0d55e1c9964475fb1cf3b9db3a56e88109d8b/products/bls-labor/OPERATING.md) and [complete Merchant setup](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/aee0d55e1c9964475fb1cf3b9db3a56e88109d8b/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/workspace/MERCHANT_SETUP.md) cover connection, analysis, interruption and delivery. An operator selects an existing workspace, its original input files and independent receiving destinations in one private connection. Managed attachment joins the Applications listener already running that project; owned attachment launches the maintained Python application and owns that process. Each attachment identifies the actual workspace, installed source and live instance.

An analyst's agent can read the selected edition and every original observation, reopen a saved regional definition, inspect its proposed next input, and save the resulting analysis or commentary at the current workspace revision. Source capture, source-edition selection, county reports, original comparisons and native publication continue through their existing operations. The [complete source-owned tool catalogue](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/aee0d55e1c9964475fb1cf3b9db3a56e88109d8b/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/workspace/catalog.mjs) exposes those original actions; the [agent client](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/aee0d55e1c9964475fb1cf3b9db3a56e88109d8b/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/workspace/agent-client.mjs) and [Merchant runtime](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/aee0d55e1c9964475fb1cf3b9db3a56e88109d8b/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/workspace/merchant.mjs) retain their complete accepted input and state. This extends how the customer operates the existing statistical product. The original LAUS/QCEW populations, source definitions and regional calculations stay with that product.

A source import selects the operator's configured file alias. Its complete bytes and SHA-256 are retained before the original operation receives the upload. The saved operation binds its request ID, source, workspace and expected revision. After a lost response, the operator reads that exact operation and resumes the retained request. Reusing an ID for changed input is rejected. Completed original work remains inspectable when an external source file later changes. A received project retains the original history; further work on its new host selects that host's current aliases and a new operation where the original request depended on its former directory.

Customer delivery includes the whole report or source member and the complete editable project. The agent first retains the selected original file, then reads its complete bytes with its length and SHA-256. Interrupted file reading resumes from the saved export identity and offset; the temporary reader belongs to its actual process. The full project export carries source captures, observation indexes, regional definitions, analyst notes, reports and saved operation history. Receiving verifies that whole ZIP in a separate configured directory before reopening the existing application. The [installed product declaration](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/aee0d55e1c9964475fb1cf3b9db3a56e88109d8b/stellar/scf-starforge-20261009/distribution/contributions/bls-labor.json) carries the Applications entry, original typed client and this source-owned agent provider together.

Commissioning therefore includes a useful customer course: open the selected original project; read a complete source edition; revise a real saved analysis; recover its original request after an interruption; receive all selected report files; export and independently reopen the whole editable project; and close the actual attachment. Managed close leaves the existing Applications owner running. Owned close drains the process it started. Targeted stop selects the exact live native-publication operation and retains its saved publication state for continuation. The commissioning team runs this course in the existing NEK receiving case, keeping its original source, saved reports and recorded operation results.
