## Original grant accounts and saved operating work

The grant operator can carry an original bank statement through reviewed cash, account reconciliation and complete case receiving. CSV uses explicit column, date and number mapping; OFX / QFX and MT940 retain their original account sections and parser reports. The operator reviews each movement, classification, supplier allocation and opening or closing balance before one case transaction receives the batch. Stable account and provider identities preserve distinct payments and recognize overlapping statements. Original cash corrections retain the payment history and the link back to the bank source.

For recurring periods, **Use a saved statement setup** saves the actual account, currency and interpretation as a named immutable edition. Before applying it to a new original file, the desk shows exact CSV header matches, missing mapped headings, added columns and every account or format choice that would change. Reordered columns retain their exact-name mapping; renamed required headings need an explicit remap and a new edition. OFX / QFX and MT940 require a fresh original-account inspection, with the selected bank context checked against the setup. Applying keeps the new original file and starts this period's balances, classifications and invoice allocations fresh.

The selected setup name and edition travel with statement preview, original source review, saved case and complete receiving. Operators can revise or archive setups while retaining every earlier edition and its source basis. An interrupted setup save keeps the original request before dispatch and reconciles its returned edition with the current case on resume. Original statement reopening preserves that historical selection; subsequent saved setups do not rewrite earlier cash or statement interpretations.

For a larger statement, the same desk lets the operator select exact source rows across pages and applied filters, inspect separate currency and direction totals, and review every proposed category, grant tranche or reasoned inclusion/exclusion before applying it. Original notes and invoice allocations remain intact; recorded cash keeps its existing classification. A guarded undo point restores the previous draft decisions, while source or interpretation changes clear the old selection. The original native preview then validates the complete revised statement before its existing cash transaction records the result. Full proposed changes can be downloaded, and the saved statement review and complete case handover retain the explicit per-row decisions.

For supplier payments, the statement editor joins supplier and invoice search, original invoice-number suggestions and ambiguity, retained invoice lines and source downloads, and the current native paid/open balance. Operators choose explicit partial or multiple-invoice amounts, see payment capacity update while typing, and review every before/after allocation with the original row note preserved. Other included draft payments and incoming refunds are shown with their proper signs, alongside projected open liability or supplier credit. Each source row retains its own unfinished working copy through the same browser draft and complete recovery file. Applying a current reviewed proposal returns through the original native statement preview and cash import; case, source or invoice changes require a fresh review.

When preparing several bank files, accounts or periods, **Statement working copies** retains named, complete immutable editions in the same operator's desk. Before switching, it preserves the current original file, interpretation, row decisions, unfinished supplier allocations and exact pending request. The operator can search every copy, select any earlier edition and inspect complete changed classifications and invoice work alongside source, account, currency, balance and mapping choices before opening it. A full archive carries every edition and original file into the same retained case in another browser; exact replay reuses matching editions, while conflicting content or an older concurrent tab preserves both originals for review. Opening returns to the current native preview and the existing cash transaction.

The same account desk can send an **Accountant recipient review** from a named immutable statement edition. A complete offline HTML file carries the original bank bytes, account and interpretation, current native rows, initial decisions and retained invoice positions. The recipient can inspect and download the source, search and edit the full statement, recommend classifications, grant tranches and explicit invoice allocations, then download and reopen an attributed return. The intended recipient and stated reviewer travel with the work; the account operator remains responsible for selecting its application.

Receiving shows the original issued value, current draft and returned recommendation for every changed field. Explicit **Keep current** or **Use returned** choices resolve concurrent changes, including invoice allocations. Applying preserves the complete earlier edition, unrelated current work, the returned file and its attribution, then saves a following edition for the existing native preview. The full working-copy archive includes the original saved source edition and complete review history, so another browser on the same retained case can receive the return, reopen the comparison and continue the account work. The original cash import records only the operator's subsequently reviewed native result.

The **Returned review worklist** carries several colleagues' complete attributed recommendations through the same account preparation. Each distinct return retains its own operator note, unfinished field choices and application history; an identical file reopens the existing work item. Operators can search and page both issued and returned work, re-download the original reviewer and explicitly save progress. Switching or reopening resolves the trusted original edition and checks the current case, row decisions, invoice work and preview before resuming choices. A changed comparison keeps the earlier choices available for inspection and requires a fresh explicit review. Complete named-copy archives carry every return into another browser, while a newly issued reviewer contains the selected source edition without recursively embedding earlier review work.

The **Work / invoice workbook** connects contributor and supplier administration to these accounts. Operators prepare an editable five-sheet XLSX from retained work and invoice records, with the original row, invoice and line identities and complete contributor/work-package references. Text-valued cells preserve leading zeroes and exact hours and USD amounts. The returned original workbook is retained as a source attachment; the desk compares its cells against the exported edition and current preparation. Explicit Current or Returned choices resolve divergent fields, while omitted rows keep their retained records.

A second full comparison reviews the saved preparation against current native work and invoices. Existing editable records follow their normal lifecycle; new rows enter through the maintained Work Intake parser, including explicit duplicate/reuse decisions and exact source-row bindings. Applying records the complete reviewed preparation in one native case transaction, including the original source attachments and immutable application edition. Named staff can continue interrupted requests with their original actor and payload. Complete working copies include unfinished row-dialog fields, comparison choices and the original returned file; the full case ZIP carries every saved edition and original operation history.

The **Supplier statements** desk closes the comparison between a supplier's own statement and the original payable account. It retains the complete statement file, stated period and balances, exact source-column mapping and reasoned row/reference corrections. The maintained supplier reconciliation engine compares that selected source against original invoice, payment and refund allocations, showing exact matches, missing items, amount differences and closing-balance variance. Each exception retains an explicit open/explained/linked decision and the chosen original record version. The current implementation uses exact USD cents and up to 1,000 complete statement rows per generation; corrections remain visible alongside their original cells and records.

An operator saves an immutable Draft or Reviewed supplier edition, then prepares a following edition against the current account while retaining the earlier comparison and decisions. The complete handover includes the native case, original statement bytes, all saved editions, a readable HTML report and statement, ledger and exception CSVs. The existing importer verifies the retained account generations, source and review chain; a receiving operator can reopen the selected edition and export the complete case onward. Both new desks include native and existing-host browser operating courses covering saved work, full downloads, request recovery and independent receiving. The original producing operator carries those courses through actual desktop/narrow use and inspection of the outgoing workbook, reports and reopened attachments.

The operating desk groups planning, people, accounts, customers and review work in a neutral interface. **Find in case** searches complete permitted record populations, original source metadata and saved workflow summaries. It opens the exact statement inputs, reconciliation revision, funding edition, issuer terms, cohort comparison or grant procedure in its original desk. Named staff visibility follows the current case permissions. Switching to saved work preserves open drafts and unresolved original requests, including the comparison editor's unsaved commercial fields.

Browser, native CLI, typed client and Merchant operations share the same case and saved identities. Complete account and case exports retain original source bytes, invoice allocations, correction history and selected editions for another installed workspace. The published receiving programme uses the four unchanged original input files and the maintained product to perform desktop and phone entry, request recovery, repeated statements, native bank review, account export, independent import and cold reopening. Its retained continuation records the actual case, request and receiving results as that original operation progresses.

This implemented operating capability supports the existing delivery, integration and handover scope. The canonical proposal continues to control the award request, prospective hours, milestones and customer outcome counts.
