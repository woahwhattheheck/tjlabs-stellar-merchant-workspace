### State, interruption and a receiving engineer

The application keeps source progress and committed destination progress distinct. A source STATE becomes eligible for the next sync only after the destination acknowledges the preceding committed records and echoes that same source state. A completed end-of-file commit can retain records without inventing a new source checkpoint. The existing local destination supports append and an explicitly selected full-refresh overwrite. Incremental overwrite is rejected. Late changes and overlap retain their original record and state meaning; the customer’s deduplication and deletion policy is agreed in the selected source contract.

When a command is interrupted, the operator reopens its retained original request, protocol and destination result. It reconciles that operation before choosing a permitted continuation. Complete receiving preserves pending historical operations while distinguishing the actually running worker, so restoring an archive does not automatically run unrelated saved commands. A receiving engineer obtains the complete workspace and source, reopens the accepted result, inspects the full record and checkpoint population, and can make a later authorized change while an exact replay continues to return its original result.
