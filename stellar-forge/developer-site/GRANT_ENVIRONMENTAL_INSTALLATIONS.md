## Original offer → preparation → Installation

1. **Receive the complete original Workshare.** Retain the native receiving packet with its matching `prepared_case.id`, `workshare_input.source.case_id` and whole `dealscout.workshare-plan.v1` plan. Preserve the original phases, dependencies, deliverables, commercial status and correction terms.
2. **Select original effort values.** The source selection binds every phase to its numeric source pointer, units and full file. The source preparer verifies exact original bytes and plan digest, one complete phase mapping and the full total. A documented prose allocation can use a separately retained literal-transcription companion while keeping the original plan intact. Unknown effort needs an explicit reviewed source; the programme does not derive it from price.
3. **Use the existing Source Preparation Desk.** Open **Installations → Prepare original source workshares**. Create or reopen the original preparation, select all required files, inspect the complete preview and choose **Prepare complete native package**. Preserve the source selection, complete supplier Workshare documents, supplier receiving material and final source-preparation record.
4. **Continue through the original case writer.** Attach the complete cohort in the existing Grant Operations case. Select actual merchant/source, commissioning payer, independent buyer, scientific reviewer, receiving/support and acceptance roles, host/runtime, source permission and useful-task payment budget. Inspect the original native preview; open and save the complete Installation draft.
5. **Operate and hand over the selected product.** Complete the useful source/review/output task above, preserving every original file and required physical row. Continue an interrupted upload, worker or receiving operation through its retained request. Export the full working case, independently import and reopen its selected Installation, operate the agreed receiving application and review returned corrections before saving a later edition.
6. **Record actual acceptance and later use.** The case links the customer's accepted result and receiving person to its original milestone. Actual time follows the selected funding assignment once. A genuinely later delivery, reporting window or approved query creates another useful task; replaying or reopening the earlier result retains its original purchase.
