## Invoice reconciliation, reviewed Stellar deposits and independent customer receiving

A customer who receives a payment observation still needs to establish which original invoice it belongs to, understand discrepancies, preserve the review and hand the complete result to another operator. Invoice & Settlement provides that continuing application. It joins the customer's actual programme and source observations to explicit attribution, native reconciliation, complete reports and an independently received editable workspace.

The operator starts with the actual invoice programme: original invoice IDs and versions, network and asset definitions, exact amounts and any separately declared settlement role. Complete imported files or native captures retain the original responses, request history, cursor, coverage and prior editions. The invoice-instruction register supplies the exact destination, memo and optional sender from the original terms. The application does not invent a company ledger or infer a payer from the amount.

### The complete operating journey

1. **Receive the original scope and programme.** Select the actual customer's Workshare, named invoice owner/reviewer, source population and period, and the existing workspace UUID. Retain the complete selected application/source edition and private configuration references.
2. **Retain complete observations.** Receive the original files or complete native captures, including the network/root response, transaction joins, failed observations and source coverage. Repeated observations remain attributable to their original sources.
3. **Review individual deposits.** Open Horizon deposits against the exact programme/version, register and source IDs. Inspect every movement and native reason. Exact candidates, ambiguous mappings, partial/overpayments, blocked observations and prior decisions remain visible.
4. **Save the reviewer's choices.** The reviewer selects individual movement-to-invoice mappings and reasons. The original native transaction rechecks the full review digest, source and current revision before committing the complete choice set under one retained request UUID.
5. **Create a useful result.** Produce and reopen the original reconciliation edition and complete report. Preserve outstanding issues and later corrections. The named reviewer decides how the result will be used.
6. **Receive the continuing application.** Export the whole original workspace/application publication, verify every original file and manifest, then receive it into an independent directory. Reopen the selected programme, original source, decisions, reports and paused operation state in the same native CLI/browser.

Matching retains exact network, asset code and issuer, decimal amounts and native integer units. G and M accounts remain distinct. Memo matching retains its type and original bytes; a missing transaction join is not a none memo. An ambiguous match or amount discrepancy remains an explicit review question. Local attribution does not transfer funds, mark an external invoice paid or perform an external accounting entry.

### Customer tools use the same native programme

The installed `invoice-settlement-customer` command and its three typed exports expose the original native workspace through the authenticated Merchant service. Thirteen source-owned tools cover workspace discovery/lifecycle, method catalog, native reads and changes, approved input import, complete export/publication and retained-file reading. A declared alias selects the host's existing workspace; authentication remains the existing host's authority and is not inferred from an alias.

The customer binds the actual workspace UUID, reads revision-bound history and prepares each change in a retained private operation directory. The complete original request is published before dispatch and its response before completion. Completed operations reopen offline. Unknown capture or listener outcomes require the original native status and deliberate same-request continuation rather than an automatic new action.

Export and download preserve the original publication UUID, native manifest and every declared file. Interrupted prefixes resume under that exact selection. Downloads stay private; independent receiving prepares a separate hash-bound source copy with the original declared file/runtime modes. The unchanged native receiver restores full application/source/runtime coverage and pauses inherited active work for explicit later continuation.
