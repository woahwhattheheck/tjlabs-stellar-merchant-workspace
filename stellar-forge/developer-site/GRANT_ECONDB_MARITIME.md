## Econdb maritime customer workflow: original sources, port periods and complete paid delivery

TokenJunkieLabs offers engineering capacity that turns authorized Econdb maritime responses into a repeatable analyst workflow: select original port observations, explain period and source-edition changes, deliver the complete reviewed dataset, and let another operator reopen the same editable work. Econdb is a proposed data-service candidate for the existing SCF programme. This chapter does not report an Econdb customer agreement, redistribution licence, selected payer, live merchant, settled purchase or awarded grant.

The useful customer result is a port-period report and its complete source-bound data. A maritime analyst can see whether an apparent change comes from the selected period, operator population, flow, source revision or missing observations; a buyer can receive every selected typed row through the existing paid-service workflow. A second operator can continue the original project and customer return without reconstructing its sources. These are implemented software paths; their installed customer receiving and actual visual use remain pending.

The [source receiving guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/3be88b396b3a94acdd9fa824ed1a97518782db4d/stellar/scf_2026/sf49_data_commissioning/econdb/sources/ECONDB_SOURCE_RECEIVING.md) records what was obtained.

| Source choice | Meaning retained by the product | Selection constraint |
| --- | --- | --- |
| Port catalogue | Issuer's top 400 ports by traffic | Not every port worldwide; missing identities cannot select a port |
| Capacity by operator, throughput | Calling-vessel TEU capacity | Distinct from estimated container TEU |
| Capacity flow selection | Imports, exports, transshipment or cargo changes the measure/population | Original flow, operator and population stay with the result |
| Operator population | Default top operators can include Others; top=0 explicitly requests all operators | For a selected operator, omit top because the issuer ignores it |
| Container traffic | Original dated import/export/transshipment observations | No declared monthly frequency; preserve original Date labels |
| Period | Local half-open selection: from <= Date < until | These endpoints declare no upstream date_from/date_to filter |

The capture path receives the full original response before local selection. It uses the fixed official HTTPS API origin, rejects redirects, and keeps credentials in the private environment. A complete HTTP response that fails decoding or interpretation remains retained with its error. Reopening an edition verifies its original bytes without another GET; a later acquisition has a new explicit edition identity. The [original source receiver](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/3be88b396b3a94acdd9fa824ed1a97518782db4d/stellar/scf_2026/sf49_data_commissioning/econdb/maritime-native.mjs) and [analysis engine](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/3be88b396b3a94acdd9fa824ed1a97518782db4d/stellar/scf_2026/sf49_data_commissioning/econdb/maritime-analysis.mjs) implement those boundaries.

Original numeric lexemes are preserved and decimal arithmetic is exact. Null, missing and unsupported values remain distinct; none becomes zero. Equal, disjoint whole-month windows can be compared within one declared monthly capacity series. Missing months, duplicate dates and unknown values prevent a complete total. Partial-month selection retains observations with monthly completeness uncomputed.

Source-edition comparison is separate: it requires the same request and role with a later captured edition, and separates data changes from metadata and coverage changes. Two dated rows in one response are not two editions. Dwell-time examples remain excluded because their meaning was not resolved. The [period acceptance contract](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/3be88b396b3a94acdd9fa824ed1a97518782db4d/stellar/scf_2026/sf49_data_commissioning/econdb/PERIOD_ACCEPTANCE.md) preserves these distinctions in export and review.

### One analyst-to-buyer operating course

The reviewer and future customer use the existing product. The [offline operator guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/3be88b396b3a94acdd9fa824ed1a97518782db4d/stellar/scf_2026/sf49_data_commissioning/econdb/OPERATOR_GUIDE.md), [complete project guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/3be88b396b3a94acdd9fa824ed1a97518782db4d/stellar/scf_2026/sf49_data_commissioning/econdb/PROJECT_GUIDE.md) and [installed operating guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/3be88b396b3a94acdd9fa824ed1a97518782db4d/products/econdb/OPERATING.md) describe the same sources and selection rules.

1. **Receive and interpret originals.** Select the complete response and descriptor; inspect source/request/port/measure identity and the original bytes. Load documentation examples explicitly when no customer source is authorized. The application starts empty.
2. **Select and apply a report period.** Apply local dates and inspect coverage, unknown values and series results. Unapplied controls do not alter the saved applied analysis. Select an actual earlier source for an edition comparison while retaining both originals.
3. **Assemble a whole project.** Select 1–48 entries, each with its current source and optional prior edition. Aggregate current-plus-prior population is bounded at 500,000 cells before expansion. Every entry retains its port, role and request; different measures and populations are never added into a false total.
4. **Save, reopen and deliver.** Review the 100-cell pages, then download complete CSV/JSON/HTML and the editable browser workspace. Reopen independently, change a selection and apply it. Native projects retain every response, descriptor, report and producing module, subject to the separate 2 GiB handover limit and smaller source/browser limits.
5. **Publish the selected population.** Choose current or current-and-previous explicitly. The SF30 projection retains entry, port/request, role, edition, measure, population, original date, source identity, exact numeric text and value status. Initializing its typed version store is not a payment or a redistribution licence.
6. **Complete a real buyer return when selected.** Use the original merchant, approved terms, native signer and buyer inbox. SF88/SF100 owns settlement and delivery. The maritime join verifies source/snapshot/query/page identity; a filtered buyer package does not silently acquire the full private raw-source archive.
7. **Hand over editable work.** Export the complete operator directory, receive it into a new intended directory, reopen its history and continue only the received copy. Software transfer and operating-data transfer are distinct. Original request and source/buyer identities survive.

The [complete SF30 join](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/3be88b396b3a94acdd9fa824ed1a97518782db4d/stellar/scf_2026/sf49_data_commissioning/econdb/sf30-publication.mjs) and [publication and buyer contract](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/3be88b396b3a94acdd9fa824ed1a97518782db4d/stellar/scf_2026/sf49_data_commissioning/econdb/SF30_PUBLICATION.md) reuse the original payment and dataset service. The installed browser/API performs no external source capture or purchase dispatch. Capture is an explicit source CLI operation; payment remains subject to the original selected authority and spending rules.
