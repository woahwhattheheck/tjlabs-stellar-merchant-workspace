## Start and open the purchase reviewer

In the installed merchant workspace, select **Applications → Grant purchase reviewer**. Choose the maintained runtime with Stellar packages, MCP and operator support, and a workbench directory under an existing private parent. For the bundled original purchase, leave Packet and SHA-256 empty. Choose **Review → Save → Connect → Start → Open**.

The same product opens from the installed command:

~~~sh
starforge grant-demo workbench --dir /srv/starforge/state/grant-review --port 0
~~~

The grant entry’s **Prepare a command for this installation** panel supports the installed command and a complete source checkout. Select the installation and absolute private directory, then **Prepare command**. The displayed command quotes paths, including spaces and apostrophes. **Copy command** copies that exact selection. **Download opening guide** retains the command and the full source, result, export and receiving sequence.

After starting the workbench, the page’s **Open a running workbench** panel can open its existing private instance:

1. Use a browser on the same host as the reviewer.
2. Select that running instance’s **workbench-connection.json** file.
3. Read the displayed workbench identity, instance and local address.
4. Select **Open this workbench**.
5. After a restart, select its current connection file again.

The workbench writes this file inside its chosen private directory. The entry accepts its exact active connection schema and original local listener address. The existing native browser receives its access code through the opening fragment and clears the fragment after connecting. **Forget connection** clears the selected connection from the entry. The opening guide contains the operating instructions and chosen packet details.

## Export and receive in another workspace

In the original reviewer, choose **Handover → Close Buyer and export packet**. Retain the complete packet and the exact SHA-256 displayed by that export.

In the grant entry:

1. Choose **Existing exported packet**.
2. Enter its absolute path on the receiving host and the supplied export digest.
3. Choose the full file in **Compare the exported file** when it is available to this browser.
4. Read its complete byte count, retained quote count and digest comparison. Its filename must match the receiving path.
5. Select a separate private workbench directory and **Prepare command**.
6. Run the prepared command on the receiving host, then open that current workbench through Applications or its connection file.

The prepared receiving command uses the installed product’s real **inspect** operation before starting its **workbench**. The second command runs when inspection succeeds:

~~~sh
starforge grant-demo inspect --packet '/srv/starforge/received/reviewer-packet.json' --sha256 ORIGINAL_EXPORT_SHA256 &&
starforge grant-demo workbench --dir '/srv/starforge/state/received-review' --packet '/srv/starforge/received/reviewer-packet.json' --sha256 ORIGINAL_EXPORT_SHA256 --port 0
~~~

The command preparer substitutes the selected complete file path and real 64-character digest. The file comparison reads at most the native product’s 8 MiB packet limit. Editing a selection invalidates the previously prepared command. A packet that is present only on the receiving host can still use the same path-and-digest preparation; the native inspect operation reads and validates it there.

In the receiving workbench, receive that selected packet, open its original Buyer, and read the full original results. Keep its directory and original action identities for reopening or continuing interrupted work. The downloaded opening guide retains this receiving sequence with the chosen command and packet metadata.

## Materialize the complete static reader

The installed source server resolves every declared browser route through
`browser-assets.json`. For the existing static publication, materialize that same
complete mapping:

```sh
starforge grant-application export --out /private/new-static-grant-reader
```

The output contains the full current reader and every declared original asset,
including shared catalog modules whose source files live outside `dist`. Publish
the complete output and open `/grant.html`. A bare copy of `dist` does not include
those mapped source aliases.

`starforge-static-reader.json` records each route, content type, copied filename,
source path and complete byte/hash identity. Its explicit `rootRoute` retains the
server's original `/` alias without overwriting the distinct `/index.html` file.
Use that mapping if the publishing host needs the same root route. The grant
entry itself remains `/grant.html`.

The export reads the currently selected original manifest and source files,
streams each complete asset, and rejects source changes during the operation.
The output directory must be new; failed output retains completed files for
inspection. Select a new output after correcting any missing or changing source.
No remote source is refreshed. Serve the output through the existing HTTP/HTTPS
publisher so browser modules and the retained-source request use their normal
same-origin routes.

The application API is
`@tokenjunkielabs/starforge-merchant/grant/static-reader`:
`exportGrantStaticReader({ directory: absoluteNewDirectory })` returns the entry,
complete route/file counts and exact static-manifest identity.
