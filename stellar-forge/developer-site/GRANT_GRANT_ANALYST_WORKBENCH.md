# Grant Analyst Workbench — installation and customer operations

## Grant Analyst Workbench: complete source review, Learning decisions and commissioned-study receiving

Grant Analyst Workbench adds a complete customer analysis operation to the existing Merchant and Installation programme. It makes an existing privately supplied analyst application usable through managed Applications, its original browser and CLI, and a customer agent that retains complete requests, reports, source files and operating handovers. Its useful output is an independently editable customer workspace with original data, reviewed decisions, full history and clearly selected recipient reports.

The reusable public contribution contains newly authored generic integration source. The complete original analyst application and commissioning source remain privately supplied under an exact external authority. Customer records, private examples, commercial context and original case selectors are not placed in the public product. This permits the same integration workflow to be installed for another authorized customer without claiming a licence to redistribute an earlier private application or case.

This chapter joins the existing canonical SCF programme. It does not add a separate funding request, duplicate supplier or acceptance count, new payment scheme or another project schedule. The current six-package,400-hour,USD38,000,150-day programme remains the commercial authority. Completed integration source, actual operated customer evidence and funded future customer commissioning are recorded separately.

### The customer problem and the complete delivered outcome

A grant-analysis handover often loses its original rows, selection rationale or editable review history when reduced to a spreadsheet or report. A later source period can change the evidence behind a decision without making that change visible in an exported summary. Commissioned studies also need to distinguish the issuer's actual roster from the wider publisher population, grant awards from investment principal, working evidence from public citations and an internal report from approved external text.

The workbench preserves these distinctions in one operating course:

1. Receive the whole original publisher package and privately supplied executable source.
2. Retain source editions and their exact numeric/string meaning.
3. Save explicit codebook and reviewed grant decisions with source references.
4. Read complete native reports and grant-ID comparisons.
5. Preserve full source snapshots behind Learning findings and action reviews.
6. Operate actual commissioned question, roster, investment, evidence and answer history.
7. Produce immutable internal and separately authored external report releases.
8. Export complete working source/data/history and independently receive it.
9. Reopen the same customer workspace through browser, CLI and customer agent.
10. Record actual observed acceptance through existing Installation.

The adapter performs transport, source selection, durable input/result retention and lifecycle integration. The original analyst remains the analysis engine. It performs exact Decimal parsing and totals, reviews, comparison, Learning and study validation and full original export/receive. Native operation ownership and existing equipped receivers remain unchanged.

### Complete source population and financial meaning

The original360Giving JSON package is imported as complete bytes. Native source storage retains original grant IDs, fields and numeric tokens. Agent tools do not parse and reserialize the source before import. Every source edition has its original byte count/SHA and a content-derived dataset edition ID; identical reimport can reuse that edition while a changed package remains distinct.

Reviewed grant decisions select the current codebook and existing original grant IDs. Each decision carries named reviewer, include/exclude choice, category, reason and source reference. Reports expose unreviewed and stale decisions. A complete source comparison joins original grant IDs and retains before/after rows for added, removed, changed and unchanged records.

Amounts are exact native decimal values. Currency totals remain separate. A commissioned investment register uses decimal text or null for principal and remains distinct from grant awards. Missing values do not become zero, and a publisher record is not evidence that a payment occurred. The study roster may include issuer-selected IDs whose source is not yet available; those remain awaiting source rather than being dropped from the report.

This full-population boundary applies to the installed customer-agent interface as well. Compact tool responses contain file references for complete underlying bodies. Original report paging uses explicit offset/nextOffset; full report and artifact tools retain all rows. Retained byte-range reads continue through EOF, so an output too large for one conversational response remains complete.

### Learning is retained history, not a rewritten report

A Learning cycle starts from an actual reviewed report and a selected set of original grant references. The original model saves the complete report snapshot and its SHA/bytes with the finding. It records concrete actions, accountable owners, review dates and criteria. Each later action change has an explicit expected revision, status, reviewer, rationale and evidence.

A later cycle review retains another complete report snapshot, the original source comparison, all action decisions, interpretation and limitations. Historical snapshots remain immutable when current source or grant decisions change. The application distinguishes evidence, reviewed interpretation, planned action and observed progress.

The installed receiving course can add explicitly technical local notes to prove editable continuation. Such notes preserve the original customer finding and selected action status, title, owner, due date and criteria. They are not fabricated evaluation findings or evidence of customer outcomes.

### Commissioned-study workflow and report release

A commissioned study starts with an actual question matrix, not a set of inferred conclusions. Question editions retain full wording and evidence definitions. The reviewer selects source editions, exact issuer grant IDs and separate investment records. Ambiguous source joins are rejected; unresolved IDs remain visible.

Evidence can be an original public source, full document, deidentified interview/workshop note or analysis note. Each entry keeps its source/page reference, scope subjects, reviewer, reason and history. Document actions explicitly keep, replace or remove an attachment. Replacing retains full original bytes, MIME, display name and SHA; historical evidence remains independently readable.

Answers identify supporting and contrary evidence, summary, limitations and contrary interpretation. Native answer context binds current question, roster and evidence hashes. A relevant change makes an earlier answer require review. Releases require every current question to be reviewed, including explicit open answers where conclusions are not supported.

An internal report and an external report are different native releases. The internal release contains full working evidence and roster/context. The external release requires separately authored anonymised text for each question, an explicit disclosure review and individually selected already public citations. It does not automatically publish or redact the internal handover. Immutable release IDs preserve what was actually approved.

The installed tools expose exact selected JSON, Markdown and CSV releases and complete historical evidence documents. Working handover ZIPs remain private, regardless of whether a particular external report is approved.

### Installation and managed application

It uses the existing Workshare, Installation workorder, assignment and acceptance machinery, preserving the actual customer, integer atomic price/count/budget, network/asset/recipient and spending selections. Its eleven steps cover source authority, preparation, managed Application, source review, exact reporting, Learning, commissioned evidence, report/handover, independent receiving and observed acceptance.

Preparation receives a literal full private source authority and actual source directory. It preserves the original application directory and all commissioned receiver/template/guidance leaves. The original executable SOURCE_FILES declaration is checked against that exact inventory. Preparation observes the actual selected CPython and isolated imports; it does not open a customer workspace or make findings. A complete private source-transfer ZIP is distinct from an original analyst operating handover.

The Application provider uses the original serve implementation, original Bearer token, actual workspace ID and a separate owner lease. The native request lock remains per operation. Review/Save/Start binds source, interpreter, private launch file and selected workspace. Stop joins actual server/handler ownership while preserving saved data and request history; reopen continues that same workspace.

The command declaration supplies grant-analyst-workbench, grant-analyst-workbench-prepare, grant-analyst-workbench-managed and grant-analyst-workbench-receive. Source selection composes the existing grant-workspace, Merchant provider tools and browser assets rather than duplicating those systems. ### Complete customer-agent operation

They cover configured attachments and connection lifecycle; original info/state; full or paged reports, comparisons, Learning and studies; twelve exact native mutation names through a stable request contract; full host-declared action/source/document intake; independent original receiving; and complete retained files, structured inspection and request history.

The host declares immutable file inputs by full SHA/bytes and actual name/MIME. Remote calls select those aliases and cannot supply arbitrary local paths. Host/connection/launch/capability files are excluded from ordinary file capture. The private generated token never enters retained reports or request artifacts.

Before a mutation, the host selects the complete original request and any input-file identity. The unchanged native engine journals stable requestId, action/body fingerprint and result. An identical replay returns the saved result and preserves later edits. A conflicting body under that ID is rejected. Complete HTTP errors remain observations; they are not interpreted as evidence that no native effects occurred. A deliberate same-request retry can use the native journal after interruption.

Retained file access binds actual workspace ID, directory and source authority. A reused alias cannot expose a different workspace's request/file history. When a full response has arrived, local custody can complete even if the listener stops; subsequent reading reauthorizes current source/workspace. Full artifacts are streamed, hashed and retained through the same existing Merchant reader.
