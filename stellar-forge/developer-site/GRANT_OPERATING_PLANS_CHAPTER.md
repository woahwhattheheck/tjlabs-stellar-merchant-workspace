## Customer operating procedures and returned work

### The customer receives working instructions and a continuing record

A customer installation needs a named person to operate it after delivery: what to open, which source and reporting period to use, what to run, what result to expect, and how the next person continues. The installed Operating Plans application gives that work an editable procedure with ordered steps, responsible people, dates, progress and full recorded results. The customer keeps the complete saved history alongside the native workspace and readable handover.

A step can contain a manual task or an actual registration from the selected toolkit. A registered step retains the installed package identity, original command or provider, source records and declared runtime groups. Its exact argument array stays with the entered instructions. The operator performs the action in its original application and then records the actual outcome in the plan. This lets the handover explain both the useful result and the concrete source and operation needed to reproduce or continue it.

### Perform, hand over and return the same procedure

The complete customer course uses the existing applications:

1. **Prepare the selected work.** Open the team's original submission and native planning review. Select its saved source revision and work packages, name the customer and operating owner, then create the operating procedure.
2. **Open the customer's working plan.** Start Command finder at the regular browser address and import the complete plan into Operating Plans. Enter the reporting period, responsible people, actual source locations, exact arguments and receiving instructions.
3. **Record the work as it occurs.** Run the selected operations in their original applications. Save the procedure's full result, progress and actual dates. Each saved revision retains the earlier instructions, registrations and results.
4. **Deliver complete working files.** Keep the full editable plan with the original native workspace and customer deliverables. Export readable HTML or Markdown from the intended saved revision for the receiving person.
5. **Review the customer's returned work.** Reopen the original grant planning review and open the complete returned Operating Plan. Compare each original package with the returned owner, due date, status, instructions and full recorded result.
6. **Review the actual sequence.** Read the complete originally prepared, previously selected and returned step lists. The comparison shows their positions and added or removed steps, and indicates when the sequence changed.
7. **Receive the current comparison.** Enter the review note and explicitly receive the later matching history. The original prepared copy remains available; the current continuing plan includes the complete received history and its receiving entry.
8. **Continue with the next operator.** Save and export the original submission with the retained customer work. Download its current plan or readable handover for the next person, using the same native case and selected customer procedure.

### Preserve unfinished work and conflicting copies

Opening a returned file stores its complete incoming plan, filename, original planning source and native revision, entered receiving note and compared operating revision in the saved original planning selection. Save, retained versions, restored drafts and complete draft export/reopen carry that unfinished work. A reviewer can stop midway and resume with the whole file and note present. Opening, refreshing, closing or receiving retains the preceding complete draft.

If the continuing procedure advances after the return was compared, the reviewer can explicitly refresh against its current history while preserving the opened file and note. Acceptance checks the selected comparison revision. The full pending download remains accessible if the current history conflicts.

The original Operating Plans receiver compares every shared saved revision. An identical or older matching return keeps the later current history. A later matching return extends it. A divergent copy keeps its complete history through the original copy and conflict controls. A received grant procedure retains its original preparation and a single complete continuing history with ordered receiving ranges.

The command-line receiver uses the same behavior. It retains a matching saved review note when no replacement is supplied, preserves unrelated pending work, and exports actual matching replay cleanup with the preceding whole draft retained. An unchanged replay retains the current complete draft state.
