### Complete client briefing, offline review and returned editorial work

The [installed economic client workspace](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/90038cecf49f2829f783ad88da64c616b7ceaadb/stellar/scf-starforge-20261009/distribution/selections/economic-client.json) extends the economic-report installation through the customer's own review and the analyst's following edition. An analyst chooses authorized original sources, prepares the useful report and sends one complete offline review document. The customer opens the report, examines its original values and sources, records questions or editorial proposals, saves revisions and returns the full document. The issuing analyst compares the proposals with the current draft, chooses dispositions, saves a following report and hands over the complete working project. This is a concrete recurring service for research and reporting teams whose deliverable includes both an interpretation and the evidence needed to review it.

The source is merged in [public Merchant PR1704](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/pull/1704). #### The customer's complete review

The [customer operating guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/90038cecf49f2829f783ad88da64c616b7ceaadb/products/economic-client/application/CUSTOMER_REVIEW.md) describes a self-contained HTML document with the original report, complete report files, every selected source response and all original companion attachments. Its [offline editor](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/90038cecf49f2829f783ad88da64c616b7ceaadb/products/economic-client/application/public/customer-review.mjs) opens without a running analyst server or a provider credential. Customers can browse the report and original targets, download each source file, search selected series and observations, and record Approved, Question or Change requested with comments.

The [shared review model](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/90038cecf49f2829f783ad88da64c616b7ceaadb/products/economic-client/application/review-core.mjs) binds decisions to the complete original package and target. Observation targets retain their absolute original position, including repeated historical periods. Editable proposals are limited to the report summary and editorial notes, and the selected series title, interpretation or methodology. Original numerical values, source periods, units and capture identity remain unchanged.

Save revision keeps the complete decisions and notes in a parent-linked edition. Browser storage retains an unfinished draft; a working HTML download carries that complete draft and all original files to another browser. Return JSON checkpoints the current review before exporting its entire saved chain. A browser-storage failure leaves explicit downloads usable. The intended-reviewer field identifies the requested workflow; commissioning still determines how the actual customer is identified and how its returned file is accepted.

#### Analyst disposition and the following customer edition

The [original receiving implementation](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/90038cecf49f2829f783ad88da64c616b7ceaadb/products/economic-client/application/customer-reviews.mjs) accepts the full returned document only into its issuing package and project. The analyst sees the original editorial value, current saved draft, proposed replacement and original source target together. Acknowledge, defer, reject and use-proposal are explicit recorded actions. Replacing a changed current value also requires confirmation of that conflict and its current value hash. A proposal tied to a captured series that has left the draft cannot be applied to a different source edition.

Each disposition retains the accepted return, comparison, original and current values, proposed text, analyst reason and before/after draft. The analyst then saves the resulting draft as a new full report. Prior reports, customer return bytes and all dispositions remain in the [same project model](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/90038cecf49f2829f783ad88da64c616b7ceaadb/products/economic-client/application/workspace.mjs). Complete project export carries all original source/client state, companions, reports and review objects. Repeating the identical received packet reopens the accepted project while preserving later legitimate receiving edits.

Interrupted work retains its original inputs. A rejected selected file stays available while a corrected customer return obtains its own bound attempt. An already accepted return is recovered before a file is resent. Following-report recovery uses its original save request; complete transfer recovery compares against the retained archive's own review state. The analyst operator also binds pending requests to the original project and preserves unfinished visible selections and disposition notes.

#### Commissioning and the existing funded packages

A selected customer workorder defines source coverage and rights, report cadence, useful analytical question, reporting period, review participants, editable text, required files, return route and receiving analyst. The agreed review includes how a disputed interpretation is resolved, how later source revisions are identified, and who approves the publication. These decisions are practical installation work around the delivered reusable product.

| --- | --- |
|T1: merchant-resource integration|Join authorized source and report selection to the customer's original publication, complete source rights and reviewer responsibilities. Retain the existing merchant's published resource and payment terms.|
|T2: deployment and buyer validation|Operate the complete selected source/report/customer task on the chosen installation, with the existing independently configured buyer operations where applicable. Resolve original source, transport, editorial conflict and receiving recovery cases.|
|T3: recurring production and handover|Establish the actual reporting and review cadence, complete retained customer editions, installation recovery and transfer to the receiving analyst or maintainer.|
|Remaining shared packages|Continue the application's existing security, reusable operations and delivery measures without allocating the same product adaptation twice.|

The application retains its existing USD38,000, 400 prospective hours, 150-day period and six-package allocation. This product supplies reusable implementation and a concrete customer workflow within that plan. It does not establish a selected paid installation, an independent buyer, collected revenue or a new funded package. Actual customer use can measure source-to-report effort, review turnaround, accepted corrections, time to a usable following edition and successful continuation by another analyst.
