# Allium customer installation and complete receiving

## Customer task and purchased output

An Allium installation starts with a customer's approved Explorer query and a downstream decision that needs its complete result. The merchant operator retains the product declaration, query parameters, response meaning, source access and permitted customer use. A receiving analyst or application consumes the selected data edition or a distinct saved query and can continue from the delivered workspace.

The maintained Allium data workspace supplies the complete operating path: product revisions, original acquisitions and result bytes, typed dataset queries, merchant terms, dataset version history, publisher candidates, buyer configurations and independent customer receiving. Applications, the typed Node client and the merchant tools use the same source-owned workspace and listener. The selected distribution is `allium-data-workspace`; its application is **Allium data workspace** and its merchant provider is `allium-workspaces`.

A commissioning workorder names the source custodian, query/product, permission and credential owner, merchant host, buyer operator, customer receiver and complete acceptance task. It also identifies the actual service price, payment asset/network and selected facilitator configuration. Credentials stay in the customer's existing private environment. The buyer receives the output and operating history selected in that workorder.

## Operate the complete customer task

Begin with the current workspace status and product revision. Review the selected acquisition's product revision before preparing a publisher candidate: an unrelated editable product head can describe different field or pagination semantics. Save a changed product through the original expected-head and operation-ID contract. The customer retains both original and revised products.

Select a complete original provider result or run the approved query with the existing source credentials. Retain the actual acquisition/provider-run identity and follow it through collection or recovery. An interrupted transport continues that acquisition. Review the full retained result, source declaration and dataset files; query the dataset with the original filter and pagination contract. Decimal source values retain their original representation.

Configure the merchant from the agreed acquisition and reviewed terms, using its previous configuration identity. Start the selected merchant launch. Refresh or activate the intended native dataset version, then stage that exact acquisition in the original publisher. The publisher retains the candidate, dataset files and buyer configuration for operator review.

The buyer's complete task keeps its selected resource, approved terms, native transfer and full returned output together. An installation example's challenge-only merchant provides the original source and handover exercise; the selected external installation records its actual purchase and service outcome under the programme's existing cohort rules.

Export from the current expected workspace revision. The source engine drains the original merchant and publisher and exports all portable customer data. Read the retained export completely, following its read ID, SHA-256 and next offset to the end. Reopening the same retained file with its SHA continues a transport interruption. If an export stopped before its bytes were retained, inspect current workspace state and use the original API's next export operation while retaining the previous intent.

Deliver the full workspace file and manifest to the declared receiver. The receiver imports every file into the selected private directory, opens the original workspace and continues from its saved products, acquisitions, snapshots, publisher candidates and buyer configurations. Repeating the completed receive returns the same destination and import identity: the source replay matches the original import directory to the export's source directory as well as the workspace, export and manifest identities.

Stop the original managed application after the task. Stop retires the exact private connection while the writer is held, drains services and releases the lease. Restarting the same reviewed application retains customer identity and creates a new instance; clients reconnect to that instance before further changes.
