# Complete native receiving course

The included receive-native.mjs runs the actual installed original OECD engine, the economic client application and a fresh receiving workspace. It accepts one original input and writes a durable stage journal. Repeat the same command/input after interruption.

## Native prerequisites

- Node 24 or later and the complete application source including its native source client and vendored parser.
- The existing complete installed OECD source graph and its actual Python executable. The selected original client module must have access to its maintained source/parser dependencies.
- Separate private directories for the receiving journal, source client project, customer client project, original OECD project and receiving OECD project.
- For optional EconData acquisition, actual authorized source credentials in the selected environment variable, exact dataset/release/series selection, and the complete reviewed source-use terms.

The public-source course needs the original official OECD source already included in that installed project. It does not contact a subscriber source when no EconData selection is supplied.

## Run the complete course

Copy examples/receiving.json to the operator's private directory and replace every absolute path with the actual selected host path. Keep operation_id stable.

    node /absolute/application/receive-native.mjs \
      --input /private/original-economic-client-receiving.json

The same native command continues its original journal and project. Each source or save action retains the original immutable operation/input. A completed step's exact returned result is adopted on continuation.

The course performs these connected product actions:

1. Open the original client project and seed its installed OECD source.
2. Save the original native OECD briefing and a notes revision in the same source project.
3. Attach the complete revised native report, rows, dataset descriptor and project ZIP.
4. When configured, acquire the selected original EconData source and its complete metadata/history.
5. Save a complete client report edition and an editorial revision.
6. Compare the original native observation groups and retain the comparison JSON.
7. Download every report file from both editions, preserving its full original hash/size.
8. Export the complete client project, close it, and receive that archive into the separate named customer workspace.
9. Download both customer report editions and compare their complete original bytes.
10. Import the same original OECD ZIP into the fresh native customer project; compare every original report file and original rows/snapshot.
11. Close and reopen the customer application, then read all saved report files again.

Its final JSON identifies the complete archive, both original OECD briefings, both client editions, project directories, receiving journal and actual browser launch command. receiving.json retains the full native stage results, errors and exact operation binding.

      ],
      "rights": {
        "citation": "Actual producer, dataset, version, release and accessed date",
