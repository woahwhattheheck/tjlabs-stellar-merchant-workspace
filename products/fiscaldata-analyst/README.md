# Fiscal Data analyst

Review a Treasury source once and carry its exact meaning through capture, native
CSV/query, comparison, refresh, report and customer receiving. The installed
**Fiscal Data analyst** product uses the original Fiscal workspace throughout.

The grayscale browser presents complete source pages, field and unit review,
dated measure cards, row differences, saved refresh plans and full downloads.
**Applications → Fiscal Data operations** retains its existing review, Start,
Open, Stop and reopen workflow. The new **fiscaldata-agent** command opens the
same named Fiscal adapter with an authenticated MCP endpoint and its borrowed
browser. **fiscaldata-remote** operates that endpoint and resumes complete file
downloads after interruption.

## Complete source workflow

1. Select the original Treasury endpoint, date/filter/sort and all reported fields.
   Capture retains each source response and its receipt, metadata and row positions.
2. Review the full field list. Record original units, scale annotations, dates,
   null markers and row identity; build an immutable READY native edition.
3. Query that edition and compare two pinned editions. All financial values,
   exact sums and deltas remain strings. The comparison retains complete rows
   and date-ordered first/last observations.
4. Prepare the complete source export and offline briefing. Retain all files,
   their original byte counts and SHA-256 values.
5. Save the reviewed baseline as a refresh plan. Preview the next actual date
   window, run, pause or continue that same request, and review changed metadata.
   Promote a completed candidate explicitly.
6. Seal the original workspace, receive the complete package into another
   private directory and reopen it. Saved source, reviews, comparisons, reports,
   refresh plans and history remain usable.

The included [Debt to the Penny profile](profiles/treasury-debt-source-review.json)
is an authored starting point for nominal daily observations in an explicit
October 2026 interval. Review its metadata against the actual selected capture.
Daily outstanding debt is a stock: adding observations across dates is a sum
over selected rows, not Treasury borrowing, expenditure, or a period-end total.
The product does not calculate inflation adjustment or silently change units.

## Installed commands

- **fiscaldata**: original browser, model actions, capture worker, checkpoint and
  portable receiving.
- **fiscaldata-agent**: inspect a complete named binding, then start its existing
  MCP adapter and borrowed browser on loopback.
- **fiscaldata-remote**: native authenticated actions, exact file selections,
  resumable download, verification, independent receiving and reopen.
- **fiscaldata-briefing**: the original complete offline comparison report.

The selected source retains the existing publisher, SF82 release and native
buyer integration. Commissioning the public-source analyst does not start a
payer. Merchant terms, a configured buyer and native approval remain explicit
separate selections if the operator later uses those actions.

## Source and validation provenance

The standalone adoption preserves all 24 full bodies from the reviewed public
refresh and client releases. [SOURCE_RELEASES.json](SOURCE_RELEASES.json) lists
each original merge, full path, expected preimage and imported Git blob. The
named host composes the original Fiscal adapter and original authenticated HTTP
transport; it introduces no financial, capture, query, payment or storage engine.

The completed prior Treasury model/browser/checkpoint workflow is described in
the original Fiscal [README](../../stellar/scf-starforge-20261009/sf30-seller-sdk/fiscaldata/README.md).
A new installation or customer commissioning has its own actual READY identity,
selected source, accepted results and receiving record. A source release does
not stand in for those customer results.
