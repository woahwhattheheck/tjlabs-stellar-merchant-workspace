# Fleet Incident and Useful Work Study — domain contract
Edition 15 October 2026. This application retains supplied fleet records and reconstructs incident context, useful work, costs and human assessments. A study starts with an explicitly selected asset class, actual application and complete population boundary. Its calculations and source comparisons remain separate from any supplier's attributed analysis.

## Complete intake and operator workflow
Twenty-four CSV families have explicit original headers. Keep original CSV/JSON/document bytes with SHA-256, upload name, byte length, source account, retrieval time and every selected extract/mapping edition. Import or edit a complete family through ordinary visible forms. Users can add a row, correct a row, map a provider heading, choose an extract, link an original document, inspect a full record and export/reopen the whole study with unresolved forms. Both native edits and browser edits must pin the same study and selected extract, including explicit null for a genuinely new family.
Use stable internal ids as well as actual provider keys. A retained old extract is never overwritten by a new mapping. Canonical rows preserve the original value next to normalised values and reasons. Exact document bytes remain downloadable even if metadata, mapping or downstream validation fails.

## Record identity and time
Common fields are id, record_key, revision, supersedes_id, record_status, recorded_at, available_at, source_document_id and source_ref. Business family identifiers join actual source records. Duplicate active identities, broken predecessors and conflicting provider keys remain visible and make affected projections unresolved. Revisions require an explicit predecessor; selection order does not resolve contradictory versions.
All usable timestamps carry an explicit UTC offset or a declared source clock. Preserve source timestamps and corrected observed time separately. A clock adjustment has its own effective interval, recorded/available times, approving reviewer and uncertainty. Do not infer an offset from a later failure. Event time, entry time and first availability have separate meanings. An as-of view includes only source versions actually available and recorded by that cutoff, within their effective interval; a later correction or report parent cannot leak backward.
Source identity links bind a source-system asset key to exactly one actual asset for a declared interval. A reused rental fleet number does not merge two serial numbers. Configuration changes and attachment changes are time-specific. A later current assignment or operator never overwrites the historical assignment. Missing/ambiguous time, identities or units stay unresolved with their source rows.

## Population and comparable work
A review question declares one application, exact historical window, actual cutoff, asset class, complete eligible population boundary and cost basis. The population includes failed, disputed, returned, missing-data and otherwise unproductive assignments within that boundary. Incident selection is not itself a complete fleet-performance denominator.
An application profile defines useful output and the actual job: for example accepted compacted square metres under the same acceptance criteria, or warehouse pallet moves with a declared load and route. It also records comparison conditions: load, configuration, terrain/floor, lift height, aisle/access, operator context, age, maintenance and record quality. Keep actual member inclusion decisions and exclusions visible. Never manufacture a common production unit from engine hours.
Member inclusion requires a recorded reviewer confirmation of comparable context. This supports a declared comparison; it does not establish a causal effect. If comparability, output coverage or population coverage is unknown, show individual observed records and the unresolved group result. No score is generated from missingness.
Exact unit conversion requires a declared numerator, denominator and source; denominator must be positive. Compare only the same output definition and compatible units. Group cost per useful output is total eligible cost divided by total accepted useful output, never the mean of individual ratios. Nonpositive or incomplete output suppresses that ratio. Keep zero-output and excluded assignments visible.

## Work, telemetry and downtime
Work intervals distinguish operating, idle, scheduled unavailable, out on rent and unknown states. Calendar rental time, engine meter change, productive time and useful output are distinct measures. Valid closed intervals must have end after start. Clip intervals to the exact study/assignment boundary and union overlaps before adding time. For asset availability use asset intervals; for interrupted job time use job/assignment intervals. Multiple incident logs for the same downtime do not multiply lost hours.
An open downtime interval may be reported as observed-to-cutoff only when its start and continuous coverage are known, explicitly labelled open/censored; it is not silently marked repaired. Missing endpoints or contradictory availability remain gaps. Replacement equipment can restore job availability while the original asset remains down, so show both measures. Planned downtime has its own category and declared availability denominator.
Meter readings use a declared unit and real start/end. A negative delta is unresolved unless an explicit rollover rule applies; a reset/replacement is not guessed. Instantaneous telemetry is an observation, not an integral. A mean/rate/energy result needs its actual aggregation method, interval and coverage; sparse samples do not become continuous work. Flag duplicate event IDs with contradictory values globally before analysis. Do not downsample or round source records during ingestion.
Output records distinguish period quantities and cumulative readings. A cumulative quantity uses its explicit prior valid output record within the same assignment/asset/definition; it contributes only the actual increment. Explicit reversal/void links preserve the earlier result at its historical cutoff. Acceptance and quality determine useful output; rejected output is not silently useful.

## Events, maintenance and historical review
Keep scheduled maintenance, actual inspection, reported finding, work performed and completed repair as separate typed maintenance records. A later work-order narrative may explain a failure currently without being evidence available before it. Incident occurred, reported and resolved times differ. Every incident belongs to an actual asset and its relevant assignment; the source can explicitly leave that assignment unknown.
Outcome labels are separate from pre-event input. Preserve unknown, disputed, later revised and confirmed labels with the actual reviewer and source. A retrospective pre-event report must not include a later label or a later repair diagnosis as a predictor. Current outcome review can show it clearly with its availability time.
Assessments retain the actual person's finding, selected source record/version set, time and supersession. No automated fault, negligence, insurability or equipment-control decision is produced. The review may include a supplied Lotew result as an attributed original; the companion's arithmetic does not impersonate that result.
A report freezes its exact question, cutoff, selected population, record revisions and original/extract parents. Its reproducing source set includes dependencies, not just top-level rows. Changing a current mapping never retroactively changes an already frozen report. Show current/frozen differences and why any prior assessment needs reconsideration.

## Costs, credits and actual payments
Use exact rational/decimal arithmetic and declared currency precision/rounding. Preserve source decimal strings. Never combine currencies or gross/net cost bases without an explicit source conversion/basis; costs are grouped by currency and declared tax basis.
Actual incurred/posted expenses, forecasts and estimates are separate states. Preserve labor, parts, fuel, transport, rental charge, replacement hire and other actual cost categories. An hourly rental list price multiplied by downtime is a proposed estimate only; it is never an actual invoice, cash loss or customer credit.
A source document line may be allocated across assets, jobs or incidents. document_key + document_line_key identifies the whole original line, with its actual document_line_total, currency and basis. All allocations must reconcile to that original total before projecting it; exact duplicate imports count once, conflicting totals make all affected totals unresolved. The whole amount cannot be inferred from the sum of questionable allocations.
Posted credit/reversal entries link to the actual original cost, use explicit signs and dates, and apply once. A promised credit does not reduce posted cost. Source invoices and cost recognition are distinct from actual payments/refunds. Cash events deduplicate globally by processor and external_transaction_id before every asset/job/incident projection; split allocations must reconcile to explicit transaction_amount with compatible currency and event type. A conflict cannot appear paid in one view and unresolved in another.
Unknown cost coverage is not zero spend. Retain known subtotals plus completeness/issues, and suppress a supposedly complete total or rate when a material included cost/credit/cash allocation is unresolved. Customer credit and vendor expense remain separately labelled if their economic basis differs.

## Effort and operating outcomes
Record actual person-minutes for source collection, identity/time reconciliation, transcription/mapping, engineering review, correction, financial reconciliation and recurring feedback. Initial setup is separate. Duplicate work_instance_id cannot inflate effort. Overlapping logged person time must be resolved when adding actual duration.
Compare only matched questions/assignments and the same recurring phases. Show the matched result, each unmatched case and complete population totals. If a required phase or population is incomplete, do not present a complete saving. A failed reconstruction and time spent resolving it remain part of delivery.
All sample cases are authored exercises with fictional identifiers. They exercise actual supplied-record calculations and ordinary operator actions without pretending to be a prospect's production results.

## Canonical header details

report_inputs uses target_revision and target_document_id for its referenced record and row_sha256 for exact canonical bytes. comparison_members explicitly supplies output_coverage_complete and cost_coverage_complete. output_records carries coverage_start/coverage_end, and cost_entries/accounting_events carry economic_basis. Historical review_questions.source_selection_json and incidents.pre_event_selection_json map exact canonical family names to retained extract IDs; an omitted map uses selected current extracts, which must themselves have been available at the historical cutoff. Reports preserve their own exact per-family extract and row bindings. A later complete export cannot serve silently as an earlier source snapshot.


## Completeness and historical dependencies

Useful-output coverage requires both the recorded coverage declaration and valid observed accepted or rejected output intervals covering the complete member window. A full-window accepted zero remains observed zero; an absent or future acceptance leaves output unknown. Cumulative readings use an explicit retained predecessor and the stated coverage interval for the increment. Overlapping output intervals remain unresolved.

Cash entries must reference a reconciled actual cost with the same asset, assignment, currency and economic basis. Refunds and reversals keep the original payment's cost and assignment lineage, and all reversals share the original amount limit. Cash is still distinct from recognised cost.

A frozen report or assessment validates the containing extract's actual availability as well as the row's recorded and available times. Clock approvals, approver authority, correction values and identity approvals are evaluated against the historical question decision. Later available rows cannot bypass that boundary by carrying an earlier effective date.

Operating, idle and scheduled-unavailable intervals describe mutually exclusive operational states. Overlap between different states makes the affected state totals unresolved; their observed intervals and union subtotals remain retained. The out-on-rent calendar layer may overlap operational work. An observed empty effort table retains its source but does not establish a zero-effort comparison: complete phase and population observations are required.
