# DNN receiving and acceptance

## Contents and operating acceptance

The source edition contains the dedicated DNN staff UI/API, maintained storage/authentication source, original auditor, Windows modules, private connection template, primary-source map and runbooks. An explicitly installed private receiving bundle may also include its selected scope and input documents under application/commercial. Public source packages contain no commercial records.

The workspace edition adds one coherent original database generation, immutable files, native returns and paired backups, all request/review/report history and native relocation metadata. The manifest names/hashes every member.

| Deliverable | Receiving action | Actual result |
| --- | --- | --- |

| Production backup and paired staging | Backup production; restore the same pair to bound staging | SQL readability/checksum, exact tree, isolated bindings and restored version |

| Staff/source handover | Create report; export and restore the workspace | Same requests, revisions, native IDs, source hashes, backup returns and report reopen |

The original workshare receiving map qualifies the actual environment and selected maintenance change. Automatic inventory supplies technical versions/modules. Staff prompts collect owners, scope, access references and window.

## Original native result states

Complete means the requested native action and its specific checks are present. Waiting identifies the actual connection/input or native security decision required by the original operator. Uncertain preserves a dispatched mutation while its own native outcome is recovered. Failed retains an actual completed failure before dependent release work is accepted.

A newer return of an unfinished original operation retains all prior editions. A completed return remains immutable. Reviews bind the actual environment and package set. An editorial note may retain unchanged implementation results; a changed implementation creates a different intent.

## Portable source and working data

The included builder validates the declared original engine and includes every required Python import plus cutover.py. Python3.11+ and its standard library run the desk on Linux/macOS/WSL. Native Windows operations use the selected host's actual IIS management assembly and SQL/DNN access.

A complete workspace export is saved beside the working database. Future exports contain the actual original records and immutable inputs without recursively ingesting every earlier whole-workspace ZIP. The receiving team retains previously delivered archives in its existing delivery/backup location.

Restoration verifies every archive member, reopens the original SQLite generation and checks its complete original-file index before publishing a new directory. It returns the exact included application path/launch command. Intake remains outside the private database. Staff renew their HTTP sign-in; accounts, history, native IDs, approved intent and original bytes remain attached to the same workspace.

## Monthly report basis

The service queue is its current saved edition at generation. Native operations are selected by their actual completion time or original preparation time in the chosen month.

Provider availability combines only non-overlapping actual intervals wholly within the month. Observed seconds, unavailable seconds and the measured share of total calendar seconds remain explicit. Cross-month totals wait for the provider's actual month-specific measurement; overlapping intervals remain separate. Correction entries name the retained measurement they supersede.

Manual incident start/restoration times are reported as recorded intervals. They do not imply a continuous monitoring denominator. The report ZIP includes readable HTML, service CSV, complete machine-readable record and original monitoring inputs.

## Saved handover downloads

Each complete workspace export carries the flat byte parts and recipes referenced by its saved handover history. After restoration, opening an earlier download reconstructs its exact original ZIP and verifies its saved length and SHA256. The current export includes each shared part once; earlier complete archives are not nested repeatedly inside later ones.
