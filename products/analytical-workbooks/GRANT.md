# Analytical Workbooks in the SCF customer delivery

## Customer task and product boundary

The analytical customer buys a complete dataset or recurring source edition, interprets its original fields, produces a useful report, and keeps an editable warehouse for subsequent work. Analytical Workbooks is the receiving application inside the existing Stellar Forge DuckDB buyer. It uses the original dataset edition, source file inventory, payment/acquisition records, dictionary mappings, saved queries and warehouse identity.

The application has six connected areas: Source and fields, Analysis builder, Results and comparisons, Workbook editor, Published reports, and Requests and history. Its browser-workspace controls retain the complete analyst draft with those native records. The operating guide is the authoritative customer procedure: [OPERATING.md](OPERATING.md).

### Work from a complete source edition to a useful report

The operator first selects a retained edition and reviews its original fields, types, NULL counts and source meanings. An analysis specifies grouping dimensions, measures, explicit filters and, where needed, selected-value pivots. Native review returns the interpretation to be saved. The operator executes that exact saved revision and can inspect every resulting row.

The [native analytical model](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c3dfa9b3748a41902f0032c22bf57c25be19fb6b/stellar/scf-starforge-20261009/sf88-operator-buyer-cli/python/stellar_forge_buyer/duckdb_analytics/model.py) retains the source edition and reviewed field references with the result. Calendar dimensions operate on actual date or timestamp columns; UTC is explicit for timezone-aware timestamps. Measures distinguish source row count, non-null count and distinct count. Numeric measures retain their chosen NULL treatment. Overall totals are computed from the selected source independently of displayed groups, preserving meaningful averages and distinct counts. A selected pivot records which values it represents and how much source coverage remains outside those selections.

A later acquired edition can be analyzed on the same reviewed keys. The comparison requires a complete unique group key, compatible native types and an explicit before/after selection. It keeps added, removed and matched groups with their original values and differences. This gives the buyer a concrete reason to acquire a later period or refreshed source: the updated report answers the same business question against the later edition.
