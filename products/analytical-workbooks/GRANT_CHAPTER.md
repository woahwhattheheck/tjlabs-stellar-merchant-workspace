## Acquired datasets, editable analytical workbooks and complete customer receiving

A buyer who purchases a complete dataset needs a usable working result: the original fields and meanings, an analysis that can be reopened, a report that retains the selected edition, and the ability to continue the work on another receiving host. The installed Analytical Workbooks application provides that customer workflow inside the existing Stellar Forge DuckDB operator. It connects the original acquired source to a saved analysis, an editable report and a complete portable workspace.

The [customer operating guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c3dfa9b3748a41902f0032c22bf57c25be19fb6b/products/analytical-workbooks/OPERATING.md) describes the full six-screen application and its original CLI and agent interfaces. The work starts from an acquired immutable dataset edition already held in the buyer's warehouse. Source files, typed values, dictionary decisions and the original acquisition records remain available throughout the customer task.

### Work from a complete source edition to a useful report

The operator first selects a retained edition and reviews its original fields, types, NULL counts and source meanings. An analysis specifies grouping dimensions, measures, explicit filters and, where needed, selected-value pivots. Native review returns the interpretation to be saved. The operator executes that exact saved revision and can inspect every resulting row.

The [native analytical model](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c3dfa9b3748a41902f0032c22bf57c25be19fb6b/stellar/scf-starforge-20261009/sf88-operator-buyer-cli/python/stellar_forge_buyer/duckdb_analytics/model.py) retains the source edition and reviewed field references with the result. Calendar dimensions operate on actual date or timestamp columns; UTC is explicit for timezone-aware timestamps. Measures distinguish source row count, non-null count and distinct count. Numeric measures retain their chosen NULL treatment. Overall totals are computed from the selected source independently of displayed groups, preserving meaningful averages and distinct counts. A selected pivot records which values it represents and how much source coverage remains outside those selections.

A later acquired edition can be analyzed on the same reviewed keys. The comparison requires a complete unique group key, compatible native types and an explicit before/after selection. It keeps added, removed and matched groups with their original values and differences. This gives the buyer a concrete reason to acquire a later period or refreshed source: the updated report answers the same business question against the later edition.

### Retain the analyst's complete working state

The workbook editor arranges tables, bar and line charts, and plain-text editorial pages around exact retained result identities. Saving creates a new workbook revision; publishing captures that saved revision and its result/source selections. Previous reports continue to identify the editions from which they were prepared.

The [saved browser-workspace model](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c3dfa9b3748a41902f0032c22bf57c25be19fb6b/stellar/scf-starforge-20261009/sf88-operator-buyer-cli/python/stellar_forge_buyer/duckdb_analytics/browser_state.py) also carries the complete authoring state: unfinished JSON, dimension and measure controls, filters, pivot selections, ordered pages, chart settings, selected native revisions and original operation requests. The operator can save a named version, download it, reopen an earlier version, or receive it in the independently restored warehouse. Revision checks make concurrent changes visible while keeping the operator's current draft available.

The same original warehouse, private operator listener and product identity serve this work. The original CLI exposes the analytical commands, and the [registered DuckDB agent schema](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c3dfa9b3748a41902f0032c22bf57c25be19fb6b/stellar-forge/mcp-paid-agent/native-duckdb-analytics-schema.mjs) exposes source review, saved analyses, execution, comparison, workbooks, publication, complete browser state and package receiving. A customer can use the operator interface for interpretation and approval while an agent carries the exact reviewed task through its existing registered service.

### Deliver the whole usable customer workspace

A published workbook exports the complete report, full CSV and typed Parquet results, source meanings, original input files, installed application and original native warehouse snapshot. Its manifest binds every member. An export can also retain the exact saved browser-workspace revision, including its full portable JSON and byte identity.

The [complete receiving implementation](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c3dfa9b3748a41902f0032c22bf57c25be19fb6b/stellar/scf-starforge-20261009/sf88-operator-buyer-cli/python/stellar_forge_buyer/duckdb_analytics/package.py) checks the original manifest and member identities, restores a separate editable warehouse and reopens the original workspace, report and source editions. Original input directories and completed export directories keep their own identities. The receiving customer can recover each original source file, open the report, continue its unfinished authoring state and create a later analysis without rewriting the published edition.

This completes the customer side of a paid dataset service. Stellar payment approval, merchant settlement and acquisition stay with the original paid operation. An analysis or report prepared from an already acquired edition is recorded as customer work; a new source purchase is joined through its own original approval, transfer and complete acquired output.
