## Acquired datasets, editable analytical workbooks and complete customer receiving

A buyer who purchases a complete dataset needs a usable working result: the original fields and meanings, an analysis that can be reopened, a report that retains the selected edition, and the ability to continue the work on another receiving host. The installed Analytical Workbooks application provides that customer workflow inside the existing Stellar Forge DuckDB operator. It connects the original acquired source to a saved analysis, an editable report and a complete portable workspace.

The [customer operating guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c3dfa9b3748a41902f0032c22bf57c25be19fb6b/products/analytical-workbooks/OPERATING.md) describes the full six-screen application and its original CLI and agent interfaces. The work starts from an acquired immutable dataset edition already held in the buyer's warehouse. Source files, typed values, dictionary decisions and the original acquisition records remain available throughout the customer task.

### Work from a complete source edition to a useful report

The operator first selects a retained edition and reviews its original fields, types, NULL counts and source meanings. An analysis specifies grouping dimensions, measures, explicit filters and, where needed, selected-value pivots. Native review returns the interpretation to be saved. The operator executes that exact saved revision and can inspect every resulting row.

The [native analytical model](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c3dfa9b3748a41902f0032c22bf57c25be19fb6b/stellar/scf-starforge-20261009/sf88-operator-buyer-cli/python/stellar_forge_buyer/duckdb_analytics/model.py) retains the source edition and reviewed field references with the result. Calendar dimensions operate on actual date or timestamp columns; UTC is explicit for timezone-aware timestamps. Measures distinguish source row count, non-null count and distinct count. Numeric measures retain their chosen NULL treatment. Overall totals are computed from the selected source independently of displayed groups, preserving meaningful averages and distinct counts. A selected pivot records which values it represents and how much source coverage remains outside those selections.

A later acquired edition can be analyzed on the same reviewed keys. The comparison requires a complete unique group key, compatible native types and an explicit before/after selection. It keeps added, removed and matched groups with their original values and differences. This gives the buyer a concrete reason to acquire a later period or refreshed source: the updated report answers the same business question against the later edition.

### Preserve unfinished choices and resolve the original request

Named working copies retain source inspection, complete mappings, unfinished SQL and parameter JSON, selected view/query/export/publication revisions, checkpoints, completed outcomes and original pending commands. The browser commits a complete command to its warehouse-specific storage before posting it. A local storage conflict leaves the current work available for download and deliberate receiving as an alternative. Imports retain all original copies and request identities rather than replacing another operator's work.

Every native command has one stable request ID and exact body. Repeating that request receives its original outcome; changing the body under the same ID is rejected. A lost reply is resolved by reading the original request and continuing that same command. View recovery can receive the original historical transition without resetting a later selection. Saving a query and its workflow receipt uses the original database transaction.

A confirmed rejection and an uncertain operation lead to different user decisions. A read-only admission failure or a query failure with a successful rollback before any commit attempt has a retained `REJECTED` receipt declaring no effect. The operator can correct those retained inputs and submit a new request. An uncertain native or transport outcome stays `PENDING`. An explicit revised alternative preserves the original unresolved copy and command; it cannot submit identical action inputs under a replacement request ID. The original history remains readable in both cases.
