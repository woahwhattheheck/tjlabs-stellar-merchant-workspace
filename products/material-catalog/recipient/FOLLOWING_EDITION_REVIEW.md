# Review a following catalogue edition

The Material catalogue recipient can now retain a complete earlier working review while reviewing the author's following catalogue. This is part of **Review and return** in the existing offline reader. It runs on the selected files and creates proposals; the original author still owns decisions, comparison, explicit adoption and Journal recovery.

## Complete operating flow

Open the original catalogue and restore its complete working review, including any unfinished form. Save the earlier named proposals normally. Choose **Open following catalogue for re-review**, selecting the author's actual complete JSONL export for the same catalogue and tenant. It must have a different active edition and retain every earlier immutable record and original source. The original comparison engine checks the reviewed catalogue, every original material/proposal revision and earlier author decision. A different catalogue or rewritten/missing original history is refused before replacing the current view.

The following-edition section retains the entire original working JSON and both original catalogue files. Each original customer/description context shows the complete prior proposal, following material and current author decision. Expand the full records to inspect units, attributes, reasons, revisions and source identities. Search and paging do not limit what the complete working file retains.

Choose one disposition for every context:

- **Carry unchanged proposal** is available only when the material's exact content is unchanged in the following selected edition. This explicit choice creates a new proposal with the earlier status and rationale, bound to the new catalogue.
- **Revise against current material** requires a selected actual current material, an explicit Approve or Reject proposal and its new rationale. Search all current materials, including a replacement with a different material ID.
- **Leave out of new return** retains the entire old proposal and reason in this re-review. It produces no new proposal. It never deletes a customer decision or means Reject.

Every disposition needs its own re-review reason. **Save re-review choice** keeps its full earlier saved values in the choice history. Unsubmitted control values are retained in the complete working download. **Complete new review return** requires all contexts to have saved choices; changed unfinished fields must be saved first. Each completion retains the whole generated review and the exact choice-history position. Repeating an unchanged completion reuses that result. Later changed choices produce a separately retained completion.

The output is an ordinary named recipient review created by the unchanged review engine. **Download new return** carries all new proposal history. **Download new working review** includes the full following catalogue and that new review for further normal proposal editing. The complete re-review file is the separate full provenance/working record, including the prior bundle, prior working state, full following bundle, decisions, drafts, all saved choice history and all completed outputs. Preserve both when handing the work back.

## Saving, reopening and source custody

While re-review is active, **Save complete working review** saves the full following-edition working file, and **Save complete working HTML** embeds the same complete work in the offline application. **Restore complete working review** accepts this file through the existing control. The original bundle, review, previous unfinished form, following source, choices and completed returns are fully validated before installation. The original normal working format remains supported.

The full dated comparison/report downloads separately. You can download the exact prior working JSON and unchanged following JSONL. **Return to prior working review** requires preserving unsaved re-review first; it returns to the exact earlier working source rather than rewriting it. Normal opening/closing warnings include re-review drafts and pending file reads. A late file-read response cannot replace a changed original selection.

The original 256 MiB input bundle, 4 MiB review-return and 400 MiB full working limits remain. A re-review includes two complete catalogues and the previous working state within that single 400 MiB allowance. It accepts at most 10,000 saved choice revisions and 100 complete returns. Capacity errors preserve the existing complete working state; no originals, proposals or histories are truncated. Source parsing, histories and decoded bytes require additional browser memory. For large catalogues use the existing native streaming importer for original author operations.

A re-review report is a source observation and proposal history, not an author approval. The author opens the resulting ordinary named return with the current actual catalogue, refreshes its original comparison, explicitly chooses Keep current or Adopt for every proposed context, saves the exact original request, and uses the maintained CLI/installed receiving transaction. A subsequent source change can make that return stale again. Exact Journal recovery and all-keep versus adopted portable receipts remain unchanged.
