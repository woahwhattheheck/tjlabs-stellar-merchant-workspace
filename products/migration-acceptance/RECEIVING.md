This course continues the **same original Definian receiving operation** through the Merchant installation, Applications and customer-agent interfaces. The complete 208-file workbench remains unchanged. Its Fruitshop and Chinook stages use the original dlt 1.31.0 runtime, pipeline state, native jobs and request history.

It does not import a replacement project or repeat extraction, normalization, loading or verification to produce another set of results. The original receiving module decides whether an unfinished stage must continue or a completed result can be reopened.

## Mutations and interruptions

Every mutation has one saved exact actor/request/body/expected-revision selection. Save that intent before dispatch. If the native response is missing, malformed, an HTTP error or a post-commit retention failure, keep the same intent and reconcile or replay it. Do not generate a replacement request ID merely because the caller saw an error.

The original workspace can commit a request before a later consumer-file materialization fails. The request remains the authority in that case. An error response alone does not authorize a new action. Uploads similarly retain their original actor-bound upload ID, whole digest and committed byte range.

Applications review and Start have their own retained original selections and process custody. On interruption inspect the saved application record and actual original owner. A surviving managed owner must be adopted through the existing Applications continuation; an ended owner may be restarted only through that same saved application record. A new connection record identifies a new launch of the same workspace, so the agent must reconnect deliberately.

Stop drains the actual managed listener and workspace writer. A failed close retains that exact owner handle and the receiving lease. The course cannot announce completion or free its programme ownership while a managed application remains open.

## Exact entry

Run this entry from the source directory selected by the existing READY Merchant installation. The installation's source manifest must include the complete Migration Acceptance contribution and its unchanged 208 workbench files.

```bash
NODE SOURCE/products/migration-acceptance/receive.mjs \
  --source SOURCE/products/migration-acceptance/workbench \
  --directory ORIGINAL_DEFINIAN_OPERATION \
  --config SOURCE/products/migration-acceptance/workbench/reference/programme.json \
  --runtime-ready ORIGINAL_DLT_RUNTIME/runtime-ready.json \
  --source-manifest SOURCE/products/migration-acceptance/workbench/SOURCE_MANIFEST.json \
  --playwright EXISTING_PLAYWRIGHT_MODULE \
  --chromium EXISTING_CHROMIUM_EXECUTABLE \
  --python SELECTED_PYTHON \
  --merchant-workspace EXISTING_RUNTIME_WORKSPACE \
  --merchant-runtime READY_MERCHANT_INSTALLATION \
  --resume
```

Replace the capitalized selections with the original host's actual absolute paths; they are selectors, not a second installation request. For a first native invocation omit `--resume`; any unfinished original or Merchant course requires it. A complete original course is validated and reopened without another native pipeline run.

The existing Runtime Workspace attaches the selected READY Merchant runtime, reviews and saves the managed application, adopts its original release through the maintained Applications path, and starts the original listener. It never calls an alternative server launcher. The private agent host is initialized through `initializeMigrationAcceptanceMerchant` and its actual registered provider, using the same exact alias configuration.

The extension creates `merchant-receiving/operation.json`, immutable intents, complete retained source/response content, operational records, and `merchant-receiving/MERCHANT_RESULT.json` beneath the original operation. The artifact manifest references the complete already-retained byte files, avoiding another copy of large native archives. Authentication tokens are not included.

A successful invocation returns the completed Merchant result. An interruption preserves the selected installation, original applications and exact mutation intents. Reuse the same command with `--resume`. Source binding failures require the actual selected installed source; a different runtime or arbitrary edited source tree is not a continuation.
