# Loaded Bikes catalogue — original native intake and receiving

This adaptation prepares a complete public catalogue review for the existing migration-acceptance workbench. The unchanged workbench owns source retention, operation history, dlt 1.31.0 execution, DuckDB exports, full typed comparison, business acceptance and portable receiving.

The public catalogue establishes publisher product/variation identities and retail claims. It does not establish a selected ERP's identifiers, approved production BOM, supplier master, stock balances or a production cutover decision. The source issues and attributed review decisions remain available alongside measured migration results.

## What the complete package contains

The package keeps the original 208 workbench files under `application/workbench/` and this complete adaptation under `application/adaptations/loaded-bikes/`. Each directory has its own full `SOURCE_MANIFEST.json`; both manifests and every listed byte are checked when the native handoff is prepared. The addon manifest excludes only itself and lists all actual addon source files.

The saved `project.json` contains the complete original capture, optional source-claims companion, explicit review mapping, issue decisions and edit history. The native input contains every exact original response, the complete capture, review, four staging NDJSON tables, four independent typed expected tables and per-cell source assertions. Each file has its original or generated byte count and SHA-256.

The four selected source tables are:

| Table | Original identity | Retained content |
| --- | --- | --- |
| products | product_id | Parent catalogue fields, descriptions, price minor units/currency, availability and original measurements |
| variants | variant_id | Actual variation ID, original parent ID, selected description and its own complete catalogue fields |
| variant_options | variant_id + attribute_index | Every original parent-declared variation option; zero-based source position remains explicit |
| product_categories | product_id + category_id | Original parent category memberships and labels |

The October 13, 2026 capture contains 20 parents, 70 variants, 70 option rows and 49 category rows. The source loader validates the capture's declared complete population rather than assuming these counts for later editions. Original duplicate complete objects must agree exactly and retain both source placements.

Prices stay in the publisher's integer minor units and declared currency scale. Empty price tokens become explicit unknown null, never zero. Boolean staging values are actual JSON booleans; the original workbench's typed export represents boolean cells with the text tokens `"true"` and `"false"`. Missing stock quantities remain null. Raw HTML, entities, empty strings and measurement text remain exact.

## Prepare the native inputs without starting a model or load

A native operator can initialize the same editable project directly from the complete original source files, before any browser edit:

```sh
node application/adaptations/loaded-bikes/prepare-project.mjs \
  --capture /absolute/original/catalogue-capture.json \
  --claims /absolute/original/source-claims.json \
  --operation loaded_bikes_20261013 \
  --output application/adaptations/loaded-bikes/project.json
```

The optional `--title` selects a project title. Omit `--claims` only when no source-claims companion is supplied. The initializer verifies the full original source, creates the unchanged default mapping and allocates a stable review-project identity bound to that operation and both source packets. It records no invented review event. Repeating the exact initialization preserves an existing same-project review/history; a different project requires an explicit new output path.

The browser's prepared export contains the complete source, staging, independent expected tables and source assertions. Node callers can use the same exact adapter:

```js
import {prepareProject, materializePrepared} from './native-intake.mjs';
const prepared = await prepareProject(savedProject);
materializePrepared(prepared, '/absolute/owned/loaded-bikes-input');
```

This step has no native job or destination effect. `prepareProject` accepts only the complete saved `tjlabs.loaded-bikes-project.v1` object. `prepareCatalogue` in `catalogue.mjs` is the browser-compatible pure preparation entry point.

Independent expectations come from a separate complete original-response projection in `acceptance.mjs`. Every selected original value is compared with that projection before reviewed corrections are applied. Per-cell assertions retain the source response/hash/JSON pointer, original value, explicit correction and expected typed cell. Full source originals remain available for an independent reviewer.

## Run the existing native load and complete receiving course

Use Node 24+ and the actual already installed original dlt runtime. The runtime-ready file is the maintained workbench runtime installation result; it is not a newly invented environment description. Follow `application/workbench/OPERATOR.md` for its installation and original runtime commands.

Choose an owned private primary directory and a separate owned private receiving directory. The original Workspace enforces its cross-process writer lease. Do not run a second receiver against an active server's workspace. An existing owner can call the retention API below inside its already-held Workspace lease.

From the package root, substituting actual retained paths:

```sh
node application/adaptations/loaded-bikes/receive.mjs \
  --project application/adaptations/loaded-bikes/project.json \
  --directory /absolute/owned/loaded-bikes-primary \
  --receiving-directory /absolute/owned/loaded-bikes-received \
  --runtime-ready /absolute/original-runtime/runtime-ready.json \
  --operation loaded-bikes-catalogue-20261013 \
  --actor local-console
```

Optional `--python /absolute/python` selects the actual interpreter. Optional `--native-project ORIGINAL_ID` selects an existing original workbench project; the driver checks it is idle before retaining inputs. With no native project supplied, original `Workspace.create` allocates a real project identity.

The course performs the following original operations and retains their exact request IDs before dispatch:

1. Retain all source, review, staging, expected and assertion files through original chunked upload and `source.retain`. Keep a portable source-request ledger with the original real source IDs.
2. Compile and review `dlthub.pipeline-input.v1` through the original planner, using only actual retained staging and expected source IDs.
3. Select the original runtime, run the native `run` stage, then the original `verify` stage continuing from the completed native load.
4. Require complete typed parity for all four tables, with no pending packages or failed native jobs. Evaluate the original acceptance engine's four business objects, three relationships and eleven exact controls.
5. Select the checked retained catalogue consumer. This selection is local staging output; its reason explicitly says it is not a production ERP cutover.
6. Export the unchanged native portable NDJSON handoff containing the full project history, original sources, complete job artifacts, comparisons, acceptance and all editable application files.
7. Receive that exact archive into the separate original Workspace. Reopen the same original project and source IDs, including the source-retention ledger, instead of recreating them.
8. Close both Workspace lifetimes. Run a fresh subprocess from the actual copied application to reopen the received project, verify its original sources/jobs/history and reopen the exact original named archive to its SHA.

The source manifests compose the archive as `workbench/<original files>` plus `adaptations/loaded-bikes/<complete addon>`. The native runtime still uses the original workbench directory. This preserves the addon relative imports without modifying any of the original 208 files.

## Continue an interrupted original operation

Use the same project JSON, operation ID, actor, directories and source edition. The original request journal and input identity reject accidental substitutions. Completed native phases replay their original requests.

If the original native job is ended and explicitly interrupted, rerun with `--resume`. This resumes the same retained native job and preserves its prior attempt. An uncertain original target write, failed job or other unresolved state remains a real native finding requiring the original operator's supported continuation; the driver does not fabricate a fresh successful job.

Do not change the review or source files under an existing operation. A revised catalogue is a new explicitly selected operation, with the previous project/input/history retained.
