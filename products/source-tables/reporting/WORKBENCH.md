# Reporting Programmes browser workbench

Open the installed Reporting Programmes entry on the same stable local origin as the existing Source Tables application:

~~~sh
starforge reporting-programme serve --port 8787
~~~

Use the URL printed by that original installed server. The managed Applications entry uses the same source-owned lifecycle. The workbench entry is /products/source-tables/reporting/workbench.html. Keep the established host and port when continuing a browser copy. All state remains in the browser and the complete files the operator downloads.

## Open, save and resume

Open either a complete native Source Tables project containing its reporting programme, or a full Reporting Programmes workbench file. The native engine validates the original project, definitions, rows, receipts and operation history.

**Save workbench with drafts** retains the entire native project, every unfinished definition/run/delivery/source form, full selected files, the exact prepared operation and its original project preimage. A new operation does not alter a prior pending request. Earlier unfinished operations remain selectable under Exact prepared operation.

**Download project** produces the complete native editable project. **Export complete handover** calls the original exportProgramme and includes the native merchant workspace, table editions/reviews, full reporting history and every complete original file. Preserve the full workbench too when unfinished forms matter.

The browser copy is convenience custody on its exact origin. A quota failure leaves the current in-memory work and file downloads available. A change from another tab stops automatic overwriting of that tab's saved copy. Save the complete current workbench, then choose Restore browser copy to inspect the other successor. Do not clear browser storage until a full download has been reopened.

Opening another workspace, loading an older definition into the editor, or starting a new workbench downloads the existing work before replacing it. The browser may ask to allow multiple downloads; keep those original files. Keep the downloaded workbench when changing host, port, browser or installation.

## Create and revise definitions

Enter the programme ID/label and the first report's stable ID, title, complete business meaning, source ownership, parameter object and SQL. A complete existing merchant starter can be supplied when continuing its native workspace. Leaving that field empty uses the original Source Tables illustrative testnet starter.

Retain the actual or proposed calendar status, IANA timezone, provider expression and period/missed-run rule. A configured calendar needs its original native schedule ID. The reporting provider remains responsible for executing SQL and scheduled work.

An imported original SQL file remains downloadable in the full workbench while the editor contains the current draft. Source intake can retain that original separately in the native project when the edited definition differs.

Loading a retained definition copies its exact full SQL and metadata into the editor; saving creates a successor revision while preserving its original definition hash and history. New report IDs add reports to the same programme. Identifiers use letters, digits, dot, dash or underscore.

## Receive actual runs

Choose the exact retained definition revision used by the provider. Supply the original provider run ID/query version, source snapshot, full period and resolved parameter JSON, observed status and original reported row count. Keep exact large numeric identifiers and amounts as JSON strings where appropriate.

Choose the complete original UTF-8 CSV and its delimiter, header and empty-record settings. A complete run's reported count must match the parsed original; an observed complete empty result uses zero. The native engine creates or advances that report's Source Tables document, retaining prior full result bytes and reviews.

Failed and truncated observations may leave the reported count blank when the provider did not supply it. This is recorded as null. Partial output and error/log files remain complete original attachments; they do not become a complete result table. Any binary or non-UTF-8 original belongs in the additional attachments field.

Each original file is limited by the native engine to 16 MiB. The native project's original receiving limit is 128 MiB. Complete request bodies and original result editions are retained, so plan for their full storage. The browser's complete workbench opening limit is 512 MiB; download and preserve native project plus exact request/preimage individually for a larger accumulated draft workspace.

The file reader rejects a stale completion after another file selection, workspace opening, form edit or active operation. It leaves the newer work intact and asks for a fresh selection in that context.

## Review tables and return the full successor

1. Download the current complete project from Reporting Programmes.
2. Open that file in the existing Table review link, /source-tables.html.
3. Inspect field types, stable keys, original rows, retained corrections and period comparisons through the original Source Tables controls.
4. Download the full edited project from Table review.
5. Reopen that returned full project here before recording the next programme operation.

The two workbenches keep independent browser selections. A change in one does not silently replace the other. The original Source Tables import/export preserves the complete reporting extension.

## Record delivery observations

Select the original run, actual route ID, intended audience and observed status. A succeeded observation requires a complete original receipt and a complete run. Empty suppression requires a complete zero-row run. Failed and uncertain observations remain explicit.

A recovered outcome or later attempt uses a new observation ID and its original same-run predecessor. Retain actual original status/provider material. Sending continues through the original configured provider, authority and relationship owner.

## Retain independent sources or receive the existing desk

Source intake stores complete original account/export material with its description and native operation history.

Desk intake receives the original complete datarunner.report-handover.v2 JSON through the unchanged receiveDeskHandover adapter. It retains the whole desk handover, each original historical run snapshot, current prepared definitions and unfinished desk material. The same full handover/context pair recovers the same receive. Complete route observations and receipts use the ordinary delivery form.

## Exact operation and recovery

The recording operator, stable operation ID and timestamp belong to the exact native request. New operation ID and timestamp creates the next identity; a prepared request remains unchanged if the operator edits the live form afterwards.

Before applying, the workbench retains the full native request and exact original project preimage. Download either under Exact prepared operation. For desk input, Download exact operation produces its complete source and receive context. Earlier uncompleted operations remain held in the full workbench.

Recover this exact operation passes that same request to the original engine. An already retained identical operation returns the current project with later history intact. A changed request under the same ID is rejected. A new operation prepared against a different project fingerprint is rejected, leaving the current project and full pending request available. Continue from the actual returned current project rather than changing an old operation's identity or bypassing its source lease.

Every retained original SQL/result/receipt can be downloaded under History and originals. Operation history contains complete original requests; selecting one recovers its exact body. A historical operation selected from an independently imported native project has no separately retained whole-project preimage unless it also came through the saved workbench.

The five browser files are additive to the existing reporting product. workbench-model.mjs constructs requests and owns full browser file/draft custody. programme.mjs and desk-receive.mjs remain the reporting source of truth. No alternate reporting engine or backend state writer is introduced.

Open the exact installed entry at desktop and narrow widths. Inspect populated definitions, a real selected result, failed/empty states, complete delivery receipt, full original downloads, saved/reopened workbench and native handover. View the actual resulting screenshots and open the exported members. The original DataRunner/Source Tables native receiving operation owns this continuation.
