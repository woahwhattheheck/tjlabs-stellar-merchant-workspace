# Complete original Tenderly managed receiving

This program continues the existing saved Tenderly case through the managed product delivered in PR405. It receives the original operator, attaches Applications, the typed client and merchant tools to the same instance, reopens the saved provider observation and recovery, resumes the complete response after detachment, operates the original profile, receives its full analysis, reopens both original customer exports and restarts the operator.

The complete original input and customer exports remain the source of the operation. The original private environment comes from its existing operator driver and is used only within the private native process. The customer delivery binds that original driver by hash.

## Source and runtime

The product source is fixed at `b9d888ab2c417d956c804b9b9133ed86ac3c9c0a` in `woahwhattheheck/tjlabs-stellar-merchant-workspace`. `receiving-source.json` records the exact 237 required receiving files, 2,953,861 source bytes, their SHA-256 values and Git blob identities, plus the complete adjacent Node receiving driver.

Use Python 3.12 or newer, Node 22.16 or newer, and an existing compatible installed dependency directory. The original cloud runtime has used x402 core/stellar/extensions 2.28.0 and Stellar SDK 16.3.1. The full managed source must match the manifest before the receiver starts. The receiver copies those selected bodies into its new private operation, so another checkout writer cannot change the running source.

An isolated checkout of the immutable product supplies the source directory:

```sh
git clone --filter=blob:none --no-checkout https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace.git /ABSOLUTE/PRIVATE/tenderly-original-source
git -C /ABSOLUTE/PRIVATE/tenderly-original-source checkout --detach b9d888ab2c417d956c804b9b9133ed86ac3c9c0a
```

Keep these four receiving files from the current receiving contribution together in a separate directory. Their source manifest describes the immutable product checkout; the adjacent receiving scripts carry the complete current continuation.

## Run the whole operation

The parent of the new receiving directory must already be owned, canonical and private with mode 0700. The selected directory itself is create-only.

```sh
python3 /ABSOLUTE/RECEIVING/receiving.py \
  --source-root /ABSOLUTE/PRIVATE/tenderly-original-source \
  --directory /ABSOLUTE/PRIVATE/tenderly-customer-operation \
  --package /ABSOLUTE/ORIGINAL/tenderly-mcp-received-workspace-20261012.tar.gz \
  --original-driver /ABSOLUTE/ORIGINAL/mcp-receiving-journey.mjs \
  --customer-node /ABSOLUTE/ORIGINAL/customer-journey/delivery \
  --customer-python /ABSOLUTE/ORIGINAL/customer-journey/delivery-python \
  --node /ABSOLUTE/EXISTING/node \
  --node-modules /ABSOLUTE/EXISTING/node_modules \
  --save-helper /ABSOLUTE/CURRENT/library_upload.py
```

A restored customer ZIP and the complete saved installed source supply the original inputs directly:

```sh
python3 /ABSOLUTE/RECEIVING/receiving.py \
  --source-root /ABSOLUTE/PRIVATE/tenderly-original-source \
  --directory /ABSOLUTE/PRIVATE/tenderly-customer-operation \
  --checkpoint /ABSOLUTE/RESTORED/Starforge_Tenderly_Managed_2026-10-12_Checkpoint.zip \
  --original-driver /ABSOLUTE/RESTORED/receive-installed.mjs \
  --original-driver-kind installed \
  --node /ABSOLUTE/EXISTING/node \
  --node-modules /ABSOLUTE/EXISTING/node_modules \
  --save-helper /ABSOLUTE/CURRENT/library_upload.py
```

The optional delivery helper saves the complete result and customer archive together before the native lifetime closes. Keep the five current helper files together: `library_upload.py`, `library_hosted_apps.py`, `library_file_transfer.py`, `native_library_delivery.py` and `native_library_requests.py`. The receiver invokes the existing returned-PUT worker, keeps transfer state and original provider requests inside this operation's private directory, and retains the save result and receipt markers there. Without that argument, the same complete files remain in the private receiving directory for the executing host's existing file tools.

The full continuation uses the original saved response and operation identifiers. It attaches the managed merchant without taking over the Applications listener, proves that detaching its own client preserves the other live client, resumes the entire SHA-bound response in a new file-read handle, and lets the original Applications owner stop and restart its listener. The customer and analysis phases operate the complete retained original files.

## Completed customer delivery

A successful whole operation creates:

- `Starforge_Tenderly_Managed_2026-10-12_Receiving.json`: complete operating events, original workspace/response identities, original customer results, source identities and the actual native process outcome.
- `Starforge_Tenderly_Managed_2026-10-12_Customer.zip`: closed operator workspace, full original Node and Python customer exports, complete received analysis, unchanged original workspace archive, operating guide and a full member hash map. The ZIP also retains all selected workspace and customer directories, including empty directories required when reopening.

The source checkout and original private environment remain outside the customer ZIP. The delivered workspace and analysis use the maintained product and installed instructions in `OPERATING.md`.

The Python owner starts one process session, records actual exit code, signal and memory events, and drains that exact owned process group before packaging. Its child records the outer process/session IDs visible through `/proc` before loading the customer program; the owner scans those outer IDs and signals the original inner process group, preserving correct ownership across Linux PID namespaces. If the original native operation ends early, it instead saves a complete `_Checkpoint.json` and `_Checkpoint.zip` with the retained customer case and actual outcome, so the source owner can continue the same operation from its saved state. It retains the private operation directory through complete file saving.
