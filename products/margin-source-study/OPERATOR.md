## Recovery and competing browser copies

The browser uses IndexedDB with a complete-session hash comparison on every save. If another tab advances the saved copy, the desk retains both complete copies and displays a conflict. Use Save & recover to open the saved branch or explicitly adopt the current branch. Adoption preserves the competing branch and allows subsequent ordinary edits.

An import is parsed and fully validated before replacing the current session. The former complete session stays retained. Source reads reserve the interface while the bytes are read, so a file cannot land in an unrelated study selected during the read.

If storage or the 40 MiB session boundary rejects an edit, pending forms/imports remain in memory with an explicit status and emergency download. Save the complete emergency envelope before leaving. Reopen it in the browser to recover the selected study and full pending forms. A pending-input replacement validates the whole successor before clearing the emergency copy. Ordinary native commands accept full sessions and studies; use the browser's complete emergency recovery route for an emergency envelope.
