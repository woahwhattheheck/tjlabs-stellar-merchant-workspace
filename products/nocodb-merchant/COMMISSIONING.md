# NocoDB customer commissioning and complete editable handover

This course commissions the existing NocoDB merchant project for a customer's actual source and receiving operator. It connects the original v3 observation, reviewed scalar contract, immutable source versions, publisher and merchant release to a complete private working handover. The receiver can retain the original operating history and continue independently on its own host.

Use the same installed project, original customer case and native receiving programme. Keep the original source account, publication decisions and private host credentials with their designated owners. The customer receives both its useful approved API/client output and the complete private source project needed to operate that output.

## Read the actual v3 observation

In **Capture source**, choose the host-declared connection and actual base/table/view/filter. **Inspect actual metadata** requests the selected table's metadata through the original reader and establishes field IDs/types. Discovery is a metadata operation; it does not acquire the source rows.

Use native identities from the original responses. NocoDB's returned `records.id_fields` identifies external-source primary keys as well as generated IDs. Include every actual identity field in stable provider order. Represent native record identity through `$recordId`; do not request an external primary key as though it were an ordinary returned `fields` value.

A complete capture binds the server/API version, base, table, view, filter, field/type union and source order. It retains the original metadata/count responses, every consecutive record page, provider-applied page size, complete unique row identities, terminal pagination and closing metadata/count observations. The original reader verifies those parts before marking the capture complete.

This is a paged observation of an existing service. Matching counts and schema do not make it a database transaction spanning all HTTP requests. The retained result preserves its actual observation interval and `atomicSourceSnapshot: false`. For a changing source, agree either its useful observation semantics or an operating change window through the source owner.

A failed acquisition retains the original request and response files. Open its retained attempt to understand what was received. An incomplete manifest is not a complete source edition. A resume can reuse an already durable complete capture; otherwise the original partial observation remains visible and a new deliberate observation has its own request.

## Review exact scalar values and the client schema

Open **Review columns** against the retained capture. Inspect native IDs, provider types, full-row value counts and original examples. The browser's limited sample helps explain a value; the complete validator checks every captured row.

| Chosen representation | Meaning in the delivered contract |
| --- | --- |
| Native string | Requires a real provider JSON string. Leading zeros, date text, timezone notation and numeric-looking text remain as received. |
| Native boolean | Requires a real provider JSON boolean. |
| Native integer | Requires a safe integer whose original numeric value survives conversion exactly. |
| Native number | Requires a finite value that passes the original exact numeric representation check. |
| Number text | Preserves the original JSON numeric token as text, including useful decimal precision. It does not reinterpret a numeric-looking string as a number. |
| Identity text | Uses the actual root record identity through `$recordId`; compound identities retain the provider's exact escaped representation. |
| Nullable value | Permits an actual null according to the chosen contract. A missing field remains distinct and is an error where required by the original projection. |
| Empty as null | Applies only under an explicitly nullable output rule; empty string, null, missing value and CSV representation remain distinguishable. |

Choose lossless number text where decimal or large numeric values cannot survive ordinary JSON-number conversion. Do not round a price, truncate an identifier or strip significant digits merely to satisfy a requested numeric type. Record the resulting public type in the client's schema and example.

Formula, Lookup, Rollup and similar scalar-capable families require explicit typing and actual complete value validation. Linked records, attachments, nested families and automatically inferred joins are not assumed to be complete scalar values. Dates remain original source text unless a separate reviewed transformation is actually in scope.

The captured field/type union and source selection remain bound to the observation. A saved draft can review aliases, scalar representation and null/empty policies within that union. Removing a query or field must leave the complete original selected union represented where the reader requires it. The original publisher later selects the public subset and extraction order. The authoring projection does not silently invent a new row filter.

Save the draft against its current revision. **Validate every row** runs all configured queries through the original typed extractor. A failed row leaves the draft available for a useful correction. Changing an unsaved title, field, query or policy invalidates the displayed preview; an earlier preview is not reused for new edits.
