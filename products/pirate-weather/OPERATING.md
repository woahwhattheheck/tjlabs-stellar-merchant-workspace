# Pirate Weather product operation

The complete maintained [Pirate Weather operating guide](../../stellar/scf-starforge-20261009/sf30-seller-sdk/pirate-weather/OPERATING.md) is included in this selected package. It provides the exact source build and native installation commands, original workspace startup, saved request pattern, response import/reconciliation, report review, original native release/Buyer flow, project receiving and cold runtime preparation.

Use the pirate-weather command from the installed Starforge CLI or its original source CLI. The package directory is INSTALL/package; dependencies and package-lock.json are in INSTALL. Configure the actual private project once and let the original Applications or CLI owner control its lifetime.

## Operator checkpoints

1. Verify the actual built source archive and source-selected runtime readiness.
2. Open the same initialized project and save the actual customer contract.
3. Retain an explicit original forecast request or an authentic saved response with its real HTTP metadata.
4. Inspect the whole 48-hour report and coverage; approve that exact edition by name.
5. Export approved report files or prepare the original native dataset/release. Start and stop remain explicit; Buyer receiving consumes existing original outcomes.
6. Stop native releases, export the complete source-inclusive project and download its exact bytes.
7. Preview/receive using the same trusted application edition, then reopen the received original workspace.
8. If the project retains original runtime source/profile/lock, use prepare-runtime and the maintained installer. Copied old absolute runtime metadata remains source evidence.

All writes preserve the original operation UUID. Recover that request before any retry. Provider limits and unknown invocations are retained; no automatic provider replay occurs.

The application supports an empty source-only project without an API key. Record that outcome as application/source receiving. The full customer forecast path requires real designated source and operator inputs; the shipped product does not contain fabricated provider data or payment outcomes.
