# Complete installed ODR receiving

This programme continues a selected existing original ODR workspace through its generic Installation and managed Applications integration. It does not repeat the original source acquisition/application browser programme and makes no live tenant calls.

Select a complete `commons.odr-installed-source.v1` source packet containing all product files and exact original framework support modules. Select actual original APPLICATION_SOURCE.json and the completed original handover (normally its independent onward edition). Input schema is `stellar-forge.odr-installed-receiving-input.v1` with operation_id, application/handover file identities {path,bytes,sha256}, actual node, playwright module path and browser file identity. An optional successor is another complete actual application file identity.

Run:
```sh
python3 -B products/odr-workspace/receiving/run-installed.py --packet ODR_Installed_Source.json --input ODR_Installed_Input.json --directory /PRIVATE/odr-installed-receiving
```

The driver verifies all complete source bytes, retains exact input selections and copies, and holds the original flock as inherited fd3. The same original root and input resume after interruption; source programme editions and every attempt/log/result remain retained. A surviving donor must still match; a completed retained copy is sufficient when a temporary donor is gone. Use the actual installed Node/Python and permitted Chromium; this programme installs no software.

The whole programme prepares the original handover, checks original source/workspace/history, reads it through configured Merchant MCP, and starts the actual Applications provider's direct native child. It opens the installed original UI, preserves an explicitly authored internal note on an existing notification, saves through the original installed control, intentionally loses one already committed HTTP response, then receives the exact pending save without repeating the business edit. It checks complete retained handover and reload, source-adoption/replay, service reopening, full exports, complete installation snapshot, independent receive, an ordinary received-app edit, onward snapshot and second-generation receive.

Source adoption selects the exact same complete application by default to check original named-operation continuation. To operate a real source change, supply the actual complete successor explicitly; no manufactured code edit is introduced.

Each browser phase retains its original selected record/base/value before editing. If its response or final output marker is interrupted, the next continuation checks the actual original revision/history and exact pending save before continuing. Complete phases validate their full artifacts. The browser is only initialized when an unfinished browser phase needs it.

The driver retains previous RESULT separately, clears only that exact final marker and requires this attempt's child exit0 and matching complete result before reporting success. It writes and verifies a whole output ZIP with every source, original input, installation, artifact, log and result before recording DELIVERY. A failed programme still produces its complete actual partial archive. Private ready files can contain session URLs; the complete output is a private case handover, not a public source upload.
