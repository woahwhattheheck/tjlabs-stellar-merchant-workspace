# ODR source and Alpha review in Stellar Forge

This product installs and operates a complete selected original ODR workbench through Customer Installation, Applications, the typed client and fifteen Merchant MCP tools. It preserves original source accounts, notification definitions, reviewed revisions, Alpha study/measurement evidence and complete Dataverse request/response records. It has no live tenant dispatcher.

Select the original private Workshare and Customer Installation seed, all commercial/source permissions and actual saved workspace. The generic profile `odr-source-review` adds useful operation/receiving steps while preserving the original workorder, Workshare phases and acceptance checks. It does not create another customer case or infer commercial terms.

## Prepare the original application

Retain the selected complete APPLICATION_SOURCE.json and an actual original handover when continuing a case. Both are produced by the original application, whose full source and license remain included. Select actual installed Python and Node executables and a private installation directory.

```sh
odr-workspace prepare --directory /PRIVATE/odr --application /PRIVATE/APPLICATION_SOURCE.json --handover /PRIVATE/ORIGINAL_WORKSPACE.json --node /absolute/node --python /absolute/python3 --request-id ORIGINAL_UUID
odr-workspace inspect --directory /PRIVATE/odr
```

The original builder verifies complete source membership and produces the standalone HTML. The installer receives the original core handover and retains source lineage. Use one original request UUID through interrupted preparation.

## Operate through Applications

Select **ODR source and Alpha review**, its prepared directory, adapter Python and optional loopback port. Review/save the existing managed application as normal. Its direct native child opens the source-selected original UI; use the explicit **Save to installed workspace** control to persist complete records and drafts. Standalone downloads remain available.

Review a complete original notification under its actual selected definition; preserve optional/unknown fields, invalid original values and findings until reviewed. A saved review keeps its exact notification/definition. Later drafts receive their own review. Inspect whole source and current history. Alpha comparisons retain planned versus observed distinctions and actual denominators/definitions.

Dataverse preparation selects actual complete metadata and mapping, retains one exact request and imports the original response under the same fingerprint. The framework does not send that request or invent tenant entity names, identifiers, credentials or accepted results.

On a lost installed save response, the UI receives the same retained payload. If another writer changed the workspace, both complete editions remain available and the operator explicitly receives the current version. Source upgrades use full selected editions with the managed application stopped.

## Configured MCP

A private JSON connection has schema `stellar-forge.odr-workspace-connection.v1` and a `workspaces` map. Each alias selects directory, optional label/sourceDirectory/python/node, application, handover, receiveHandover, receiveArchive, transferDirectory and optional exact installation/source binding. The provider input is `odrWorkspaceConnection`.

Paths and whole source inputs are selected by the host, not arbitrary model-visible file arguments. Tools inspect source/status, prepare/adopt/snapshot/receive, read state/record/history/handover/measurement comparison, receive a complete onward handover under its expected digest, export, receive a named request and describe the service. Every lifecycle mutation retains an explicit request UUID. Close the service for exports/source changes/whole snapshot.

## Original commissioning plan

`odr-commission --seed Original_Installation_Seed.json --bindings Original_Bindings.json --selection Odr_Selection.json --out /PRIVATE/commissioning` uses the maintained readProfile and prepareInstallation contracts. The selection schema is `stellar-forge.odr-installation-selection.v1`:

```json
{
 "schema":"stellar-forge.odr-installation-selection.v1",
 "operationId":"ORIGINAL_UUID",
 "case":{},
 "workshareCaseId":"ORIGINAL_WORKSHARE_CASE",
 "source":{"sourceId":"ORIGINAL_ATTACHED_SOURCE","application":"/PRIVATE/APPLICATION_SOURCE.json","sha256":"EXACT_FILE_SHA256","workshareReference":"ACTUAL_ORIGINAL_SCOPE"},
 "installation":{"directory":"/PRIVATE/odr","python":"/absolute/python3","node":"/absolute/node","handover":"/PRIVATE/ORIGINAL_WORKSPACE.json"},
 "actor":"ACTUAL_RECEIVING_OPERATOR"
}
```

Use the actual full seed.source for case, actual document.workshare.caseId, and a source attachment already selected in the original bindings. The commissioner verifies original application bytes through the native source reader and preserves workorder, Workshare and checks. It writes complete original inputs, prepared Installation document/preview, native request and editable workorder; it performs no external case write or payment.

## Whole receiving

Stop the original service, export useful handover/report/source and snapshot all source/workspace/history/lineage. Receive the whole ZIP into a new private directory with the actual installed runtimes. The original workspace UUID survives; the receiving installation has its own UUID and its sender's records. Open the received managed application, inspect original records/history and make an ordinary explicit saved edit before onward export. Retain actual output hashes and lifecycle request receipts with the original case.

See native/API.md for exact schemas, receiving/README.md for the whole installed receiving programme, and the original selected application's own source/operating guides for its business/source workflow.
