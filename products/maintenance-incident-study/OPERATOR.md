# Browser operator guide

## Open and identify the study

Open Maintenance_Incident_Knowledge_Study_Desk.html. Use a consistent browser profile/origin if you want its private browser storage to reopen. The header shows the selected study and session revision; the status distinguishes saved work, unsaved changes, memory-only storage, conflicts and emergency input.

Enter the actual plant area, machine family, source/returned boundary and responsible source owners. Select operational data for real authorised records. The example button deliberately opens a separately labelled authored study and retains the previous session.

## Import originals and map fields

Choose CSV intake & mapping, the record family and source/returned side. Choose the actual UTF-8 CSV. Original BOM and CRLF bytes are retained in its text representation and hash. Assign canonical fields to exact source columns. A blank mapping is unobserved; it is different from an empty cell in an observed column.

Record when this complete source edition was available, separately from capture into the desk. A later complete export is not an earlier historical snapshot. Review original row numbers, then retain and select the extract. Switching sections retains unfinished imports and mappings.

Selected editions displays every retained extract. Choosing a different edition changes the current study without erasing its predecessor. Prepare mapping revision retains the old mapping and any earlier pending form.

## Map exact identities

Use Identity maps for each family. Unique exact-ID matching adds only unambiguous identical identifiers and preserves existing explicit choices. Otherwise pair original and returned IDs manually. Machine configurations, incidents, output snapshots, cause vocabulary, knowledge editions and dated events have independent identities.

Do not map by a similar label or combine different physical assets because they share a machine type. Cause aliases belong in the cause_aliases table, with explicit type and validity/recording evidence.

## Retain supporting originals

Use Supporting originals to retain actual output files, source manuals, logs, screenshots, knowledge approvals and the complete incident inventory. Same filename/different content remains separate. Link each original to an exact kind, side and record.

Record source availability using the ordinary correction form and a locator/reason. This form binds the study, byte hash and full previous metadata, preventing a stale correction from replacing a newer availability edition. Typed link availability is separate. Removing a link retains the document and preceding study.

Images can be previewed locally. Other originals can be downloaded exactly for the appropriate reader. Uploaded files are not executed by the desk.

## Correct a supplied record

Observed records provides full ordinary forms for each selected table. Prepare correction retains the original row and selected extract identity. Apply the complete sourced revision with its reason and actual recording instant. It creates a later extract edition; earlier rows remain in history.

A draft cannot be applied to a different selected extract or study. Prepare a fresh correction after explicitly retaining the old form. New dated events represent reassignment, reopening, retraction or revised knowledge; avoid editing an original event to conceal its earlier state.

For knowledge content, Calculate exact content digest updates only the pending digest. Save the record explicitly with its source basis. Prepare source review for this edition creates a knowledge_reviews draft with the exact edition/document digest; it leaves the reviewer, decision and source evidence for the actual supplied review. A prepared form is not an approval.

## Declare population and evaluation

In Cohort & evaluation plan, choose the known-at cutoff, incident-open start/end, exact side, complete inventory original and locator. Include all consecutive eligible incidents, including failures, abstentions and unresolved cases. Retain exclusions explicitly.

Declare the actual output stage and top K before reviewing results. The first supplied output at that stage is selected; later successful reruns do not replace a failed or abstained first result. Select any-confirmed or all-confirmed if a source supports multiple causes. All-confirmed matching needs every member of the confirmed set.

Declare all recurring active-work phases and the two measurement methods. Include source confirmation, knowledge review, reconciliation, duplicate entry, correction and handover when incurred. Use the same observed scope in both methods.

## Read the whole study

Diagnosis & knowledge study shows:

- Complete population and ranked/abstained/failed/missing outputs.
- Conditional, confirmed-cohort and whole-cohort denominators.
- Source-edition availability and the exact selected extract.
- Incident states, effective/recorded chronology, confirmed cause sets and selected output.
- Actual used observations, source roles, model/release identity, supplied ranks and original hashes.
- Exact knowledge/activity references and shift acknowledgement.
- Active-work phase totals, missing phases and signed differences.
- Supplied machine intervals, overlap unions and unresolved stop records.

The source comparison screen independently lists exact field, parent identity, mapping and document-byte differences. Equal source/returned counts do not establish equivalence.

## Record study review

Each configured study role reviews the complete current source, plan, mappings and links. Starting a review binds its current digest. A later source or plan change makes the old draft stale; Start current review preserves its previous notes and binds the new edition.

Knowledge source review and whole-study review are different records. A source owner may approve a knowledge edition while the study still contains unresolved transfer or outcome evidence. Neither action creates permission to control a machine.

## Save, recover and transfer

Save complete file downloads the whole portable session. Download complete working export includes readable reports, selected tables and field availability, original files, exact attachments, retained history and recovery branches. Download application source exports the full implementation and guides.

Two tabs use content-bound compare-and-swap on browser saves. If another saved branch appears, both complete copies remain in recovery. Explicitly select the intended branch and continue editing. An acknowledged old branch does not authorise overwriting a newly changed competing branch.

Pending input above the ordinary retention limit remains in emergency recovery with a visible warning. Download-and-clear is explicit. Rejected import candidates remain recoverable. Before replacing a study with emergency input, resolve it or download its complete recovery envelope.

A complete imported file is validated before selection. The previous local session is retained and downloaded before replacement. Native commands preserve ordinary full sessions, including unfinished browser forms; emergency envelopes are reopened through this browser workflow.
