## Saved dataset queries and complete original results

A seller preparing a paid dataset needs to understand the exact rows and fields a customer can request. The original SF30 Dataset workspace already exposes the native dataset schema, indexed equality and range filters, stable ordering, retained snapshots and reproducible request examples. The query-study continuation makes that work durable across sessions and makes the complete result available for inspection.

### Customer and operator journey

The operator opens the original dataset configuration or running versioned service. The installed Applications form can select a private query-studies directory. A named study retains the full source description and selected resource, every guided input, the separate raw query and the last successful original page. Incomplete filter strings and a partially written name can be saved without pretending that the query executed.

Successful execution retains the original query parameters and returned snapshot. Further edits stay separate from that success. A failed query keeps the earlier result visibly attributable to its original request. The operator can return to an earlier edition, fork an alternative analysis, or reopen a complete working file. Switching to a different source is explicit and preserves the previous source and inputs in the study history.

A complete-result export begins from a saved successful query. Its retained request binds that exact native study revision, query and snapshot. It starts at the first page even when the saved preview was a later continuation. It then follows the original engine's actual cursors until every declared result row has been retained. The existing SF100 validators check row types, original source meanings, query signature, selected fields, ordering, total and each page boundary.

The operator receives complete CSV and typed JSONL, the original source-meaning document when present, the saved study, and a manifest containing the complete original page descriptors and hashes. CSV keeps original text unchanged; JSONL preserves typed values and null versus empty-string distinctions. These are local operator results that support source review and customer preparation within the existing paid dataset workflow.

### Durable continuation and source identity

Native saved revisions use create-only publication and a preceding-record hash. A compare-and-swap storage revision protects concurrent editing. An exact retry recovers the original publication rather than overwriting newer work. The portable study retains up to 200 source-bearing editions and an 8 MiB complete working file; reaching those limits produces an explicit response without discarding history.

A result job retains every complete original response as it arrives. Interrupted reading can resume that same job at the last native cursor. The original snapshot expiry response remains meaningful: existing retained pages survive, while resumption requires that original source to be available through its established service. A newer snapshot becomes a separate selected result.

Private file downloads verify their retained hashes before streaming. The same original loopback origin checks and bearer session protect browser reads, edits and downloads. The installed command line exposes named saves, complete working-file import/fork, native query execution, full export, status, resume and complete-file download. The original dataset loader, parser, snapshot writer and payment routes continue to provide their established behavior.

### One source for agent work and the operator browser

The merchant agent can now operate this same saved-query workflow through 27 source-owned tools and a typed client. The private connection names the original dataset or running service, its private study directory and permitted complete-study import files. The installed launcher reviews the exact configuration bytes, opens one native source and study store, and gives the browser and agent that same owner.

A persistent workspace identity survives restart. A separate process identity changes on reopen and accompanies each agent mutation, so a stale caller cannot silently address a different opened owner. Closing the browser preserves the native study store and running result jobs. Closing the owning workspace drains accepted operations and closes its own browser and retained file handles.

The agent can save raw unfinished controls, inspect historical revisions and original rows, execute the unchanged query engine, fork or restore an edition, and explicitly adopt a new source. Importing a complete study first verifies the original host-declared file and its SHA-256. The imported study retains every edition and its original source binding; querying a different dataset requires explicit rebinding.

The complete-file client downloads the original study or the entire completed result. Result receiving includes every retained response page alongside CSV, typed JSONL, the native result manifest and optional source meanings. The same retained-file protocol checks the complete manifest, per-file sizes and hashes, saves private files, and resumes original byte offsets after interruption or process restart. A cold-reopened result returns its retained status for an explicit resume of the same job.

### Comparing complete saved customer selections

The same workspace now compares two complete saved query results. The operator reads both original manifests, source descriptions, queries and snapshots, then explicitly maps every selected field and chooses typed row keys. Matching names are suggestions; renamed fields, added fields and removed fields remain visible in the plan.

The comparison preserves original scalar types and distinguishes a missing field from a present null. It retains every original row in a duplicate or null-key group without choosing an arbitrary pair. Counts separately describe key groups and original rows. A changed result may reflect a changed filter, ordering or snapshot as well as changed source values; the saved source definitions remain available for that interpretation.

Each comparison retains an immutable UUID request before processing. Exact retry recovers the same selected manifests and mapping. The complete result is published only after all report and source files are saved. A restart can resume the original request with its original engine, and an updated installation can still reopen completed comparisons.

The browser offers change-kind views, sparse indexed group pages, and independent member pages for large groups. Unfinished mapping choices, names, source inspection, prior working editions and pending requests travel in a complete working file. The native CLI and the same merchant agent expose the same comparison and original source identities.

A complete comparison package contains the exact baseline and target typed JSONL and their original manifests, the saved request, full comparison metadata, every key group as JSONL, CSV and a readable standalone HTML report. The existing retained-file client receives all nine original files and resumes verified byte offsets after reopening the workspace. This gives a seller and customer a complete review of what changed between two reproducible selections while retaining the original query results and their study histories.
