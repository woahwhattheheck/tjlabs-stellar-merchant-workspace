## Saved dataset queries and complete original results

A seller preparing a paid dataset needs to understand the exact rows and fields a customer can request. The original SF30 Dataset workspace already exposes the native dataset schema, indexed equality and range filters, stable ordering, retained snapshots and reproducible request examples. The query-study continuation makes that work durable across sessions and makes the complete result available for inspection.

### Customer and operator journey

The operator opens the original dataset configuration or running versioned service. The installed Applications form can select a private query-studies directory. A named study retains the full source description and selected resource, every guided input, the separate raw query and the last successful original page. Incomplete filter strings and a partially written name can be saved without pretending that the query executed.

Successful execution retains the original query parameters and returned snapshot. Further edits stay separate from that success. A failed query keeps the earlier result visibly attributable to its original request. The operator can return to an earlier edition, fork an alternative analysis, or reopen a complete working file. Switching to a different source is explicit and preserves the previous source and inputs in the study history.

A complete-result export begins from a saved successful query. Its retained request binds that exact native study revision, query and snapshot. It starts at the first page even when the saved preview was a later continuation. It then follows the original engine's actual cursors until every declared result row has been retained. The existing SF100 validators check row types, original source meanings, query signature, selected fields, ordering, total and each page boundary.

The operator receives complete CSV and typed JSONL, the original source-meaning document when present, the saved study, and a manifest containing the complete original page descriptors and hashes. CSV keeps original text unchanged; JSONL preserves typed values and null versus empty-string distinctions. These are local operator results that support source review and customer preparation within the existing paid dataset workflow.

### Durable continuation and source identity

Native saved revisions use create-only publication and a preceding-record hash. A compare-and-swap storage revision protects concurrent editing. An exact retry recovers the original publication rather than overwriting newer work. The portable study retains up to 200 source-bearing editions and an 8 MiB complete working file; reaching those limits produces an explicit response without discarding history.

A result job retains every complete original response as it arrives. Interrupted reading can resume that same job at the last native cursor. The original snapshot expiry response remains meaningful: existing retained pages survive, while resumption requires that original source to be available through its established service. A newer snapshot becomes a separate selected result.

Private file downloads verify their retained hashes before streaming. The same original loopback origin checks and bearer session protect browser reads, edits and downloads. The installed command line exposes named saves, complete working-file import/fork, native query execution, full export, status, resume and complete-file download. The original dataset loader, parser, snapshot writer and payment routes continue to provide their established behavior.
