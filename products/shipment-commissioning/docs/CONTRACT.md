# Shipment commissioning model

The operator compares captured shipment outputs at ordered, named checkpoints against a reviewed reference edition. It does not extract freight documents or simulate a proprietary platform. A run retains its exact reference edition, method/configuration and conditions. Each checkpoint keeps the complete input sequence description and original document references; actual output captures retain original UTF-8 JSON, mapping edition, observation time and delivery/retry context. Duplicate input delivery and late amendments are exercised by capturing the system's resulting state at explicit checkpoints.

Three mapped observation arrays are supported: document-to-shipment bindings; typed field values with ownership; and gate observations with missing-field sets. Mapping uses exact JSON Pointers into the provider's supplied JSON. Mapping records are editable; every capture retains the mapping actually used. A saved correction creates a new capture and retains earlier observations. A changed selection expires run acceptance. Contract examples are the commissioning interchange schema, independent of any particular provider's native API.

Field values preserve JSON scalar types. Numeric literals are preserved exactly, including large integers and decimal spelling. Shipment/document references must be strings and are never normalized. Duplicate object keys are rejected; duplicate observation keys remain visible as findings. Required reference rows form explicit denominators; extra candidate rows are reported separately. Uncaptured checkpoints stay uncovered, even when their expected arrays are empty.

A reference reviewer approves the case before a run can start. Later reference edits retain full prior editions and require new approval; older runs retain their original approved reference. Readiness labels are supplied reference/observed values. Applicable regulatory rules and the authority to file, release or bill stay with the operator's established process.

All commands carry a unique original ID, actor, offset timestamp, expected workspace revision and exact expected hash. Their complete original payload and prior workspace hash are retained. Exact retries after later operations return the current state without overwriting it; changed requests under the same ID fail. Imported workspaces replay from the complete original command journal before adoption.

Effort records preserve performer, phase, interval, active seconds and comparability declaration. Overlapping intervals for one performer are rejected. A difference is shown only for the same frozen case with matching recorded phases and comparable declarations. Results are specific to the measured case.

A run review may include an explicit disposition for every current finding: finding_id, status (needs_change, accepted_exception or investigate), responsible owner and action/explanation note. The review is bound to the exact selected run basis; selecting another capture expires it. Earlier original review commands remain replayable. The normal browser review form supplies these rows and export includes a separate disposition CSV.

Field and gate mapping records can include values: an explicit list of {observed,canonical} aliases. Observed strings must be unique. Canonical field owners are proposed, human_edited, locked or unknown; gate states are ready, blocked or unknown. Unmapped canonical values are accepted unchanged. An unrecognized value is rejected. Original raw JSON and the frozen mapping remain retained, so normalization is inspectable.
