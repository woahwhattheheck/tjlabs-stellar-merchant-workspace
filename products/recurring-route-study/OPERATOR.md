# Operating the Recurring Route Study Desk

## Prepare the actual study boundary

Use one agreed company/team and a complete consecutive route period. Obtain the original scheduled-stop inventory from the system that actually owns the work. Include cancelled, missed, blocked and unfinished obligations. Keep the source file, its exact extraction scope and an explicit completeness statement. A selection of successful proof records cannot stand in for the schedule.

In Study scope, enter a readable label, original and returned scope, source owners and actual service/billing authority. Data class is operational for authorised real records and authored_course for method fixtures. Notes support the working study without changing imported source bytes.

In Route & measurement plan, enter the inclusive scheduled-start beginning, exclusive end and actual as-of instant. Choose company and service scopes, the retained complete inventory file and its precise section or row locator. Check completeness only when the source owner has supplied that boundary. Set all recurring effort phases and required review roles before comparing work. Changing the plan keeps its previous edition and makes older acceptance historical.

## Import original CSVs

Choose a record family and source or returned side. Select the original CSV. The desk stages the full original text before applying a mapping. Assign each canonical field to an actual original column; leave unavailable fields unmapped. A source column cannot silently serve two different fields. IDs are text, so leading zeros and punctuation remain intact.

The source's available time is when that edition was available for the study; intake capture is a separate event. Do not label a later reconciliation export as if it existed at dispatch. Save each complete mapped extract, including empty but complete tables when the source confirms there were no records. An absent table is unobserved.

Earlier extracts remain selectable. Preparing another mapping retains the previous unfinished form. Invalid CSVs and unsupported session imports remain recovery candidates with their original content and error. The application does not repair a malformed file by discarding rows.

## Reconcile identity and source editions

Selected editions shows the exact original and mapping on each side. Choose the actual returned trial edition; do not overwrite the first version. Identity maps pair original IDs to returned IDs. The exact-ID helper adds only unique pairs and preserves existing choices. Similar names or identical row counts do not establish identity.

Use separate IDs for scheduled obligations, attempts, proof, reports and invoices. A blocked stop followed by a revisit has one scheduled stop and two attempts. Requirement and dispatch changes have their own retained predecessors. A changed site coordinate is a new source edition, not a silent correction to historic location evidence.

## Save, recover and hand over

The browser stores complete sessions locally. The status bar distinguishes saved, unsaved, memory-only and competing branches. Download a complete file regularly and before changing machines. Keep the file with the source owner.

Two open tabs cannot silently overwrite each other. In Save & recover, explicitly select the saved or local branch. Both complete preimages remain recoverable. Opening an earlier branch retains the current branch.

If a large pending form cannot enter the durable session, its full content remains in memory and the application offers emergency recovery. Download it before clearing or closing. The limit is on expanded retained session state; use a complete authorised study scope that fits rather than repeatedly accumulating unrelated years of work.
