# Recurring Route Study Desk

Open **Recurring_Route_Study_Desk.html** in a current desktop browser. The application runs offline and begins with an empty study. It provides ordinary forms for scheduled work, dispatch revisions, actual attempts, proof, exceptions, reports, billing decisions and accounting observations.

The authored eight-stop course demonstrates the whole workflow. Open it from Study scope; its records, original payloads and results are labelled authored. Retain your current working file before replacing it. A complete session keeps every original, applied edition, unfinished form, review and retained browser branch.

## What the study answers

For the complete consecutive schedule, which obligations have an actual completion statement? Which have the required source proof? Was that proof available to the office when each report was created? Which exact report supports the actual owner's invoice-ready decision, and how does the separately issued invoice reconcile?

The study also exposes reported location uncertainty, offline arrival, unresolved exceptions, stale report decisions and actual operating effort. It preserves incomplete and cancelled obligations. It does not turn a photo, signature or location observation into a claim that service happened.

## Start with one complete route period

1. Define the scheduled-start window, cutoff, service scope and source owners in the study plan.
2. Retain the full schedule and exact supporting originals.
3. Map supplied CSVs to the twenty-three canonical record families.
4. Select the actual source editions, map original/returned identities and review differences.
5. Examine attempts, office receipts, reports, invoices and all recurring effort.
6. Record named reviews, then export the complete working session and readable report.

See **OPERATOR.md** for the full process, **SOURCE_INTAKE.md** for mappings, **MEASUREMENT.md** for interpretation and **NATIVE.md** for the Node18+ CLI. **DOMAIN_CONTRACT.md** contains exact headers, chronology and calculation rules. **RECEIVING.md** describes a complete native/browser receiving workflow.

The standalone HTML embeds the complete maintained source. Its source ZIP can rebuild the same HTML. All external-system references remain literal supplied identifiers; no vendor API, live route, customer send or accounting write is performed.
