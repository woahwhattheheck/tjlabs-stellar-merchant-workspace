# Property Operations receiving and continuation

The maintained product includes the original complete programme under `operations/scf-property-operations-receiving-20261012/`. It operates the existing installed Property workspace, SDK and merchant attachment; retains the original customer delivery; exercises normal Applications Stop and reopen; and restores the complete portable workspace with the original CLI.

Use the original business operation, customer identities and selected workspace. The source adoption provides an executable receiving programme and complete product documentation. Its actual result is the report written by the receiving owner after those stages execute.

## Select the original inputs

Use Node 24+ on Linux with Python 3, GNU tar and flock. The runtime must be READY and contain the complete `property-operations` selection or equivalent maintained `property-operations-interfaces` contribution. Run the entry from that runtime's actual `package/source` tree, as returned by runtime inspection.

## Browser runtime selection

Browser receiving is optional. When its original operation calls for it, add exactly:

~~~json
{
  "browser": {
    "playwrightModule": "/absolute/existing/playwright/index.js",
    "executablePath": "/absolute/existing/chromium"
  }
}
~~~

The receiver accepts exactly these two keys and validates both absolute paths **before dispatch**. Additional keys, missing runtime fields and non-object browser values fail with `PROPERTY_RECEIVING_BROWSER_INPUT`; invalid or relative runtime paths fail with `PROPERTY_RECEIVING_PATH`. The programme supplies the actual application URL, original creation time, Property ID and output directory; those identities cannot be replaced through browser options.

The original browser visits all eight workspace sections and four Property views, receives the largest existing export member through its normal UI button, and checks desktop 1440×1000 and mobile **390×844** views. The selected Playwright module supports both its ES module namespace and its CommonJS default export. Screenshots stay in the operation's private `private/browser-inspection/` directory for local inspection. Only `Browser_Receiving.json` and the complete downloaded native member enter the customer directory. Its route policy allows reads and the four selected original Property read actions. Preserve the actual browser result and any failure with the same receiving operation.

### The single complete journey

1. **Bind the installed source and original case.** Verify the complete runtime manifest and source registrations, original workspace creation time and selected initial bytes. Retain the complete existing paid ZIP and its customer identities.
2. **Save and connect the managed application.** Use the original Applications review/save/source-adoption path and the same selected binding. Read its actual current release and native history.
3. **Start the original owner.** The manager verifies the selected source, application request and private startup announcement. SDK and merchant clients attach to that owner.
4. **Receive the complete retained case.** Save the reviewed HPD baseline from its existing edition and import the existing paid ZIP through the declared source alias. Retain every prepared action/key/revision/input digest before invocation. Read every Property collection to its terminal page, compare complete SDK/MCP records, receive all retained files and complete the selected dataset query.
5. **Export and receive the complete customer files.** Create one original native package export, retain its exact inventory, prepare the merchant manifest and receive every declared file. Close the borrower and merchant listener, then independently reopen the same downloaded files.
6. **Stop normally and reopen the same application.** Retain the actual first run outcome, listener/process closure, removed matching announcement and successful original CLI lease open/close. Start the same saved application again, receive its retained case read-only, and stop normally a second time. Compare complete workspace JSON across both lifetimes.
7. **Restore independently.** Import the selected portable package with the original CLI into the receiver's empty cold directory. Verify every member's bytes/SHA and re-export the restored logical workspace. Preserve the original IDs and all full source bytes.
8. **Seal complete output.** Freeze the customer roster, write its manifest and publish the original complete archive from those exact retained members.

Selecting browser inputs composes the original browser receiving into both successful managed lifetimes. The same source capture, vendor request and paid purchase are reused through this workflow.

## Resume the same operation

Run the same entry with the same input and output directory. Read the retained journal and actual original application history before acting.

| Boundary | Original continuation |
| --- | --- |
| Property write response lost | Inspect the exact prepared key. Reuse `DONE`; preserve `ISSUED` and explicit retained-evidence recovery; review a changed revision before a different request. |
| Native package export response lost | Reconcile the saved pre-export ID set with the original export list. Reuse the one resolved new export. Ambiguous or absent outcomes remain pending. |
| Application Start/Stop interrupted | Continue through the original request and Applications recovery. Establish the original owner/listener closure before another listener. |
| Merchant download interrupted | Keep its original endpoint, workspace, manifest and per-file checkpoints; receive only the remaining original bytes. |
| Cold import interrupted | Continue only from the original empty receiver or a populated target that equals the selected complete logical workspace. |
| Customer archive publication interrupted | Use the frozen original customer roster and staged archive identity; keep the full report and complete members. |

A process exit is separate from a native business outcome. A missing startup response does not authorize a second owner. Use the original manager and workspace lease rather than removing a lock or changing a selected input to make a stale operation pass.
