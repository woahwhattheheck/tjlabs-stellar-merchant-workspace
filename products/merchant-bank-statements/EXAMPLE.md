## Original account arithmetic

The first native OFX source describes the original operating-001 checking account, its institution and USD currency, with these posted movements:

| Original source record | Signed bank amount | Accounting use |
| --- | --- | --- |
| NET100 | 97.00 | A 100.00 customer receipt with a separate -3.00 fee. |
| R200 | 200.00 | Link the retained original 200.00 customer receipt. |
| FEE5 | -5.00 | Classify the original bank fee. |
| ZERO | 0.00 | Retain the original row and explicit zero-amount reason. |
| REF20 | -20.00 | Match the original recorded customer refund. |

Its original opening balance is 1,000.00 and closing balance is 1,272.00:

~~~text
1,000.00 + 97.00 + 200.00 - 5.00 + 0.00 - 20.00 = 1,272.00
~~~

The 100.00 gross receipt satisfies the original 100.00 invoice while the source cash movement stays 97.00. The 20.00 refund has its own negative movement and original refund identity. The OFX source also retains its separate pending observation.

Open the source's original CLOSING record to inspect the selected balance dates. The download range remains available as its separate acquisition context.

## Run the original complete example

The operating bank product uses its maintained runtime described in [INSTALLATION.md](INSTALLATION.md). Running the complete browser example additionally requires the original Playwright and Chromium installation.

From the corresponding source root:

~~~sh
SCF_BANK_TMP=/private/original-bank-examples \
SCF_BANK_KEEP=1 \
node stellar/scf-starforge-20261009/merchant-settlement-accounting/receivables/bank-statements/EXERCISE.mjs
~~~

The private parent directory must already exist. SCF_BANK_KEEP=1 retains the complete resulting case and native-result.json. SCF_BANK_CHROMIUM may select the actual installed Chromium executable.

The example creates its own private working case. For ongoing customer work, open the customer's original accounting directory through the normal application.
