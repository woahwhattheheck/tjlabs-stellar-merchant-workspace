# Telemetry comparison contract

Version 1.0.0, prepared 14 October 2026. Independently authored read-only file workflow. It does not connect to controls, issue work orders, train a model or certify energy savings.

## Complete input

Use blankInput() for an empty workspace. scope specifies siteId, podId, clockId, timeFormat, start, end and cadenceMs. Windows are start-inclusive/end-exclusive and a whole number of cadence intervals. ISO timestamps require an explicit Z or numeric offset; naive local times and leap seconds are rejected. Epoch milliseconds/seconds and declared relative seconds are supported, with exact millisecond resolution. Relative and absolute streams cannot share one evaluation. A clockId is an explicit assertion by the preparer, not inferred timezone conversion.

points contains id, label, quantity, target unit and optional lower/upper review limits as exact strings. Absolute temperature C/F/K uses affine conversion; temperature_difference uses scale only. Power W/kW/MW and energy Wh/kWh/MWh are distinct. Humidity percent/fraction, fractional ratios, pressure and volume flow have separate tables. Unknown units require an explicit upstream mapping; they are not guessed. All source numeric tokens remain original lexical strings. Calculated mean bias, MAE and MSE include exact rational numerator/denominator; RMSE is a labelled floating square-root approximation.

streams identifies every original source and its observation/prediction role, mapping and clock. Wide layout maps columns[].pointId/field/unit. Long layout maps pointField/valueField/unitField (or a literal unit) with explicit optional pointAliases. CSV/TSV selectors are exact header names; JSON selectors are RFC6901 pointers relative to each object in arrayPointer. Quality fields require an explicit acceptedQuality list. The original order and every invalid/duplicate/missing/outside-window occurrence remain visible. Prediction streams require runId and a model context containing id, version, calibrationStart, calibrationEnd, calibrationClockId and optional note. Calibration overlap with evaluation is reported explicitly.

Alignment is exact with zero tolerance or nearest within an integer tolerance less than half the declared cadence. Predictions are processed in timestamp order; each chooses the nearest observation in the tolerance. Equal-distance candidates and attempts to reuse an observation are excluded and reported. This is a deterministic local rule, not a global matching optimization. There is no interpolation, hold-forward, averaging, resampling or extrapolation. Duplicate policy is explicitly reject (default), first or last in retained stream/source order. First/last decisions remain warnings and do not erase original occurrences.

Coverage lists expected timestamps, selected/on-grid observations and missing counts; missing-time examples are capped at 1,000 while the full count remains. Metric denominators are the actual paired occurrences, with unmatched, ambiguous and attempted-reuse counts separate. Review limits are owner supplied, not recommended operating setpoints. Compare frozen editions uses common unchanged measured occurrence identities, requiring matching site/pod/window/clock, alignment, units and limits; it discloses dropped/added coverage and all model/calibration contexts. Model deltas are not operational savings or proof of better physical operation.

## API and immutable lifecycle

createTelemetryAPI(runtime) receives synchronous sha256, encode/decode UTF8 and Base64. Public methods: createWorkspace, addSource, readSource, inspectSource, mapStream, analyse, saveEdition, review, compare, exportWorkspace, importWorkspace, canonical, timestamp, blankInput and fields. Mutations use {operationId,expectedRoot,at}. addSource returns {workspace,sourceId}; saveEdition returns {workspace,editionId,report}; review returns the workspace directly. saveEdition accepts name, input and optional parentEditionId/preparedBy/note. Reviews require editionId, decision approved/needs-work, reviewer and note. Same operation retry must exactly match original payload/time/previous root. Stale saves reject.

Workspaces and cached source inspections are deeply frozen. Root commitments bind exact original identities and input/report/payload SHA256 values. Import replays the complete operation history and compares every full retained body; cached trust applies only to exact immutable object identities. Source content remains full Base64 even if opaque or unparseable. Export is complete compact JSON; JSON pretty-printing is not part of identity. The blank workspace is separate from the explicitly authored demonstration.

## Admission and actual performance

20MiB per original, 64MiB total originals, 128MiB complete compact workspace, up to50,000 rows per selected table,256 points,32 streams and250,000 expanded point occurrences. These are admission ceilings. A declared window may contain at most100,000 expected timestamps. The actual 1,000-row/12-point full receiving course is retained separately with measured timings; no real browser/Node performance is claimed from source execution.


The complete operator exports the existing validateWorkspace method in the public API. Its implementation is unchanged: core-produced immutable workspaces use the core's private trusted set; unknown or mutable inputs replay all original operations and return the validated immutable reconstruction. The operator reuses that authority after mutations instead of calculating the whole history again. The exact preceding core is retained under history/telemetry-core-before-validator-export.mjs.
