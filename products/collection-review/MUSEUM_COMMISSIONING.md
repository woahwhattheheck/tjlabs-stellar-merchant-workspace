# Museum content release and commissioning

## Purpose and current boundary

The museum extension uses the maintained Collection Review catalogue, editorial revisions, source-edition correspondence, unfinished working copies and complete colleague receiving. Museum records live inside those same immutable revisions. There is no second store or command journal.

The current source implements media metadata, explicit public visitor content, immutable releases/decisions, endpoint package preparation, continuing withdrawals and commissioning evidence. Source implementation is not observed installation. Operate the exact outgoing app, media, copying, receiving and rendered controls under section 9 before calling it customer-ready.

The actual CMS, hardware, rights, supported native import and installation authority remain project inputs. No proprietary CMS connector or customer tenant is supplied by this generic code. The supplier's selected content authority remains authoritative.

## 1. Import, review and save the original material

Import the complete catalogue through Collection Review. Structured source schema stellar-forge.collection-input.v1 retains supplied titles, original absolute HTTP(S) URLs and extra rawRecord fields. Repeated URLs remain separate occurrences. A real offline catalogue without that URL needs an agreed source-format extension; never fabricate an institutional link to pass admission.

Save inclusion, suggested titles, summaries, story order, notes and rights observations. A release reads its exact saved editorial revision: each occurrence must be explicitly included, ordered and permission-recorded with its own basis/citation. Supplied visitor titles/summaries must match that saved review. Inclusion and a rights observation are operator records, not legal permission determined by software.

Import a later catalogue as a distinct source edition and use the maintained correspondence workflow to carry choices explicitly. Preserve earlier bytes and decisions. The release's default content key is the occurrence ID, keeping repeated-URL records distinct. The model preserves an already published key across later releases and across the original saved, explicitly reviewed source-edition map decisions. A mapped successor cannot select a different key to evade an older withdrawal. Establish that original correspondence deliberately; URL equality alone never creates it.

Use the original pending request UUID, full payload and expected revision. Exact replay reuses its original result; changed input under the same UUID refuses. A newer saved revision preserves the unfinished draft for reconciliation. Receiving unions immutable histories and retains the local selected head; it does not execute an incoming pending command.

## 2. Register actual media and retain physical files

The existing limits remain 4 MiB per catalogue source, 64 retained sources, 20,000 occurrences, 1,000 revisions and 64 MiB for complete metadata. Keep large media outside that JSON.

Current media fields are id (media-SHA256), sha256, bytes, private filename, content-addressed path, mime, role and private label. Roles are original, working, uncompressed, encoded, transcript, captions or source. There is one role per asset identity. Do not alter identical bytes to manufacture multiple role records; keep their reviewed business-role mapping in the handover inventory/evidence.

This version has no typed derivative-parent, caption-language, custodian or per-asset-expiry field. Retain such actual project requirements in the private source/evidence; do not call them automatically validated.

describeMuseumMedia hashes the selected actual file. Imported metadata alone does not prove presence. buildMuseumPackage separately checks every required file against its SHA and byte count. Images require alt text; audio/video require a full transcript; video also requires a retained text/vtt captions asset. Watch/listen to the result: those field checks do not establish accurate captions or successful playback.

The browser package allowance is 256 MiB for selected media plus generated text; an individual described file has the same bound. This is admission, not a demonstrated performance promise. Larger physical custody uses the maintained streaming directory command. Actual count/format/byte/time and partition limits must be measured on the accepted deployment; a commercial sizing assumption is not observed throughput.

Retain the real supplier export/import contract and version, original export, reviewed mapping, generated import and independently returned native results where a CMS integration is required. Generic JSON is not evidence of a proprietary connector.

## 3. Approve the exact release and inspect its public projection

Create the endpoint with its original UUID, key, public label, story/browse family and private textual equipment profile. Record OS/browser, display, controls, audio, codecs, storage, connection, update and restart assumptions there. The profile is not an automatic compatibility engine.

Prepare the release from the saved source revision. It retains actor/time, title, introduction, ordered items, endpoint IDs and explicit expiry. Private items also retain permission basis/citation. Concept/detail/alpha/beta/final decisions are immutable. A final refusal remains a revision requirement; prepare corrected successor content rather than treating a later timestamp as erasure.

The visitor projection includes selected public title/summary, alternative text, credit, media references, transcript/captions, content/occurrence keys, endpoint public identity/family, release/deployment identity, expiry and file hashes/paths/MIME/role. It excludes staff names, equipment profile, original filenames, rights basis/citation and withdrawal reason/evidence. Public control rows contain only withdrawal ID, keys, media IDs and time. Keep the staff workspace in the separate private handover.

Text remains inert escaped text; source HTML/script is not an extension interface. Inspect the exact generated output, including the intentionally private reference note, before release.

## 4. Apply current restrictions without losing history

Implemented controls are explicit whole-release/deployment expiry and monotonic withdrawals by reviewed content keys or exact media IDs. A private withdrawal retains its UUID, author/time, affected identities, reason and evidence. Effective controls come from all retained revisions, including received branches, rather than only the selected head.

There is no reinstatement command, typed use/territory matrix, derivative-family propagation, future withdrawal schedule or per-asset rights expiry in this version. Such requirements need explicit supported integration before that use. Where one permission ends earlier, choose an appropriately early release expiry or a separately controlled release/withdrawal procedure.

An older workspace or release cannot remove known withdrawals. The historical release ID names its complete original content; the exact endpoint manifest names the currently permitted projection after filtering. Do not conflate those identities or rewrite the older hash. Carry current controls to each receiving endpoint; another browser/device does not inherit them magically.

## 5. Prepare a package, then record actual endpoint application

prepareMuseumPackage requires the exact final-approved release and selected endpoint, applies current controls and returns generated visitor files, manifest/control hashes, selected assets and a proposed deployment record. buildMuseumPackage additionally verifies all actual selected files and creates the bounded visitor ZIP.

Package creation is not application. A deployment binds its UUID, endpoint/release, actor/time, control/manifest SHA and expiry. Its separate acknowledgment binds deployment ID, applied/removed/failed, observed time, operator, matching hashes and note. It has no dedicated prior-release field or authenticated hardware telemetry; retain any actual prior-release observation in evidence.

Verify actual local media and current controls on the endpoint before recording applied. A stale/differently targeted acknowledgment cannot close another task. Recover an uncertain result through the same original intent; do not create a second nominal success.

The streaming command keeps private project/intent outside visitor/, copies/hash-checks complete files and writes completion after verification. Its companion CLI guide supplies exact command arguments and continuation paths. A directory handover uses FILES.json identity instead of inventing a giant ZIP.

Offline equipment cannot learn a withdrawal before transfer. Show prepared/applied/unknown distinctly. Bring forward current controls before older-release use; restricted items stay blocked while unrelated items may remain available. Explicit display expiry depends on actual device time. This is neither trusted-clock hardware nor immediate remote revocation. Record and operate the accepted offline/clock/transfer assumptions.

## 6. Record commissioning evidence and separate acceptance

Section 10 gives exact actions and report fields. A protocol binds release, endpoints, window, target hours, required gates/roles/copies, restore requirement, authority and evidence. Mode actual or authored-reference stays visible; multiple protocols remain separate.

The supported run policy is continuous-since-last-blocking-fault, explicitly selected by the reviewer. A contract's general running-period phrase does not supply reset, maintenance or observation rules. Agree those rules; unsupported exclusions cannot silently become passing time.

The report merges overlapping passing intervals without double-counting. Failed/unknown coverage resets the run at its end. A blocking incident resets at correction and blocks while unresolved. A failed/removed acknowledgment truncates that deployment's coverage and resets the endpoint. Every endpoint needs its full qualifying observed interval. Calendar age, missing incidents and a daily spot-check do not evidence every intervening minute.

Intervals follow the matching applied acknowledgment, reviewed window and actual observation time and stay within expiry. Incident correction evidence can identify the actual source/software/configuration change; there is no automatic proprietary ticket link. Contradictory resolutions remain findings.

Contractual acceptance is a separate retained authority/source decision: accepted, accepted-with-conditions or not-accepted. technicalEvidenceComplete never manufactures it; the report always sets contractualAcceptanceInferred:false.

## 7. Deliver the full private project and receive editable successors

Retain actual issued handover requirements in the private source/protocol: source code, dependencies, operating/CMS access instructions, catalogues, rights/editorial history, original/working/uncompressed/encoded media, transcripts, commissioning and operation records, copy destinations and retention commitment. Generating files cannot prove years of future custody.

The private handover preserves the original Collection export, all registered files and controls. Its full member manifest does not replace the files. Absent required roles remain gaps or explicit reviewed exclusions, not supplied facts.

Use artifactKind directory-manifest for a streamed complete folder. archiveSha256/archiveBytes then identify exact FILES.json bytes; inventory binds actual members. For archive, those fields name the exact whole archive. The sourceRevision is the release's original editorial basis, while the private working export also keeps later commissioning/operation revisions.

Two copies require two actual custody destinations and full verification. Duplicate receipts for one custody are one copy; a later failed observation supersedes prior verification. Keep credentials outside generic instructions/public output.

Independently reopen the same original private project and source, preserve withdrawals and make a permitted real editorial/media edit. Save/approve/package it, then receive that progressed project into a second independent recipient. Preserve later local work via the maintained merge or a new directory; opening an old archive must not silently replace a newer project or change a physical endpoint.

## 10. Maintained commissioning module and operator action contract

The generic pure module is museum-commissioning.mjs. It has no transport, filesystem, timer or parallel persistence. All actions go through the existing Collection Review pending command, exact request UUID, expected revision and ordinary saved state. Root action shape is {type:"commissioning",record:{type,record}}.

Exports:

- emptyCommissioningState() supplies the complete schema and arrays.
- validateCommissioningState(value,museum) validates all original references and fields, returning the supplied value without mutation.
- applyCommissioningAction(museum,{type,record}) returns a new full museum state. Exact same record UUID and payload reuse its result; the same UUID with different input refuses.
- assertCommissioningExtension(previous,next) verifies no retained commissioning row was removed or rewritten; the museum parent validator also enforces this original continuity.
- commissioningReport(museum,{releaseId,asOf}) returns all selected protocols, their full endpoint coverage, gate decisions, handover/copy/restore evidence and separately recorded acceptance. Pass an explicit timestamp with zone. It makes no network or clock call.

Every record has id (original lowercase UUID), actor (actual recorded operator) and createdAt (full timestamp with zone). Every child also has protocolId. Evidence is {note,references:[{label,url?,sha256?,bytes?}]}; each reference needs an original credential-free HTTP(S) URL or full SHA-256, and bytes requires that hash. A note without a file reference is still an operator statement, not independently verified physical evidence. Authority is {name,role,basis}; retaining it does not authenticate a legal signature.

The exact additional fields per action are:

| Action | Required fields after id, actor, createdAt |
| --- | --- |
| protocol.add | releaseId, mode, title, endpointIds, windowStart, targetHours, runPolicy, requiredGates, handoverRoles, requiredCopies, restoreRequired, authority, evidence |
| gate.record | protocolId, stage, decision, authority, evidence |
| observation.record | protocolId, endpointId, deploymentId, acknowledgmentId, start, end, observedAt, result, evidence |
| incident.record | protocolId, endpointId, openedAt, severity, summary, evidence |
| incident.resolve | protocolId, incidentId, resolvedAt, outcome, evidence |
| handover.record | protocolId, sourceRevision, archiveSha256, archiveBytes, inventory, exclusions, evidence; optional artifactKind |
| copy.record | protocolId, handoverId, custodyId, location, observedAt, status, archiveSha256, archiveBytes, verifiedItems, evidence |
| restore.record | protocolId, copyReceiptId, targetLabel, observedAt, result, workspaceId, reopenedSourceRevision, verifiedItems, evidence |
| acceptance.record | protocolId, handoverId, decision, authority, evidence |

Protocol mode is actual or authored-reference. Use authored-reference for every invented demonstration event and clearly label the complete reference case. Protocol endpointIds are exact selected release endpoints. The supported runPolicy is continuous-since-last-blocking-fault; selecting it is an explicit reviewed decision, not an invented interpretation of a contract. targetHours is a positive integer; 720 represents a selected thirty-day duration, but no such completed run is generated from elapsed wall-clock age. requiredCopies is a positive integer; restoreRequired is Boolean.

Required gate stages may select concept, detail, alpha, beta and final. Gate decisions are approved, changes-required or rejected. A contradictory or adverse gate remains visible and blocks a complete technical report for that immutable release. Do not use a later timestamp to erase the original refusal; prepare the reviewed successor content/release. More than one protocol may be retained for a release, and the report returns each separately rather than silently choosing one.

Observation result is pass, fail or unknown. The interval start/end has positive duration, follows that exact deployment's matching applied acknowledgment and the reviewed window, finishes before the retained observation time and stays within deployment expiry. Passing intervals are unioned per endpoint. Failed and unknown intervals subtract from coverage; a blocking fault resets the current run at its correction. The end of the latest failed or unknown observation also resets the run. A retained failed or removed deployment acknowledgment ends that deployment's passing coverage and resets the endpoint run; an old successful interval cannot override a later known interruption. Every selected endpoint needs a complete uninterrupted qualifying interval. A gap is not automatically passing.

Incident severity is blocking or nonblocking. Resolution outcome is corrected or withdrawn-as-not-a-fault, with its own original evidence. A later recurrence is a new incident. Concurrent contradictory resolution records remain retained and block the complete technical conclusion; no timestamp silently chooses an authority.

Handover roles are source-code, cms-access-instructions, encoded-media, uncompressed-media, working-originals, transcripts-captions, operation-manual and rights-register. Each inventory item is {key,role,sha256,bytes}; key is unique. Inventory records an exact original retained member; it does not read the file. Required roles need actual members or explicit reviewed exclusions {role,reason}. Do not put credentials into cms-access-instructions or any public report. The handover sourceRevision must equal the release's exact original editorial revision. Optional artifactKind is archive (the default for existing records) or directory-manifest. For archive, archiveSha256/archiveBytes identify the exact complete archive. For directory-manifest, those same retained fields identify the exact FILES.json manifest bytes for the complete streamed folder; they are not a claim that all media is embedded in a single archive. The inventory binds every selected actual member separately. Copy and restore receipts preserve that artifact kind through their original handover reference and verify each full member. Do not silently substitute one artifact kind or manifest for another.

Copy status is delivered, verified or failed. Each verifiedItems member is {key,sha256,bytes}; verified requires the entire original handover inventory to match. Exact archive or directory-manifest bytes and SHA must match the selected handover's declared artifactKind. Distinct custodyId values identify independently held copies; two filenames or duplicate receipts for one custody identity do not become two copies. A later failed or merely delivered observation supersedes the prior verified observation for that same custody; equal-time conflicting evidence takes the conservative state.

Restore result is verified or failed. It must reference an original fully verified copy, preserve its source revision and, for a verified result, match the full inventory. The software retains the actual stated workspace ID and destination; the ordinary complete package receiver performs the physical parsing, hash checks and editable reopening. A form submission by itself is not that receiver run.

Acceptance decision is accepted, accepted-with-conditions or not-accepted. It is a retained external decision about a named handover, independent of technicalEvidenceComplete. The report always sets contractualAcceptanceInferred:false. Preserve contractual evidence even if it conflicts with technical findings, and show both.

The report names protocolId, releaseId, mode, asOf, targetHours, runPolicy, endpoint passing intervals and current reset point, open blocking incidents, gate evidence IDs, conflicting resolution IDs, selected handover, verified copy IDs, successful restore IDs, technicalFindings, technicalEvidenceComplete, separately recorded acceptance and explicit limitations. The latest handover is selected by recorded timestamp with a deterministic ID tie-break; the full original history remains retained. That display selection is not a release or contract approval.

As with the rest of this guide, authored source and pure source-function checks do not meet the actual rendered-product rule. The complete actual programme still needs its original equipped receiver, operated controls, watched media, desktop and narrow inspection, real download/reopen and independent editable receiving before any customer-ready statement.


## 11. Maintained streaming command path

Run the existing Node Collection Review entry from the complete selected source/package. These examples use its source-tree location; choose actual owned private paths and keep every original input:

```sh
node stellar-forge/developer-site/collection-review-cli.mjs museum-action \
  --project WORKSPACE.json --input ACTION.json --out PRIVATE_ACTION_DIR

node stellar-forge/developer-site/collection-review-cli.mjs museum-media \
  --project WORKSPACE.json --file ORIGINAL_MEDIA \
  --input MEDIA.json --out PRIVATE_MEDIA_DIR

node stellar-forge/developer-site/collection-review-cli.mjs museum-package \
  --project WORKSPACE.json --input DEPLOYMENT.json \
  --media-index MEDIA_INDEX.json --out PRIVATE_PACKAGE_DIR

node stellar-forge/developer-site/collection-review-cli.mjs museum-handover \
  --project WORKSPACE.json --input HANDOVER.json \
  --media-index MEDIA_INDEX.json --out PRIVATE_HANDOVER_DIR \
  --copy-a FIRST_PRIVATE_COPY --copy-b SECOND_PRIVATE_COPY \
  --source-package ACTUAL_SELECTED_TOOLKIT.tgz
```

All four input files retain the original id, actor and createdAt. Action, media and handover may include note; deployment input does not accept note because the maintained preparer freezes its own exact request note. Action adds action:{type,record}; commissioning is the nested museum action described in section 10. Media adds role,label,filename,mime. Deployment adds releaseId,endpointId and optional expiresAt. Handover needs no other required field. Use explicit Z or numeric timezone offsets. MEDIA_INDEX.json maps each exact SHA-256 to its actual file path; relative paths resolve beside that index.

Each operation freezes original input/source/media identities in private INTENT.json and retains the original project/input. Resume with the same full files, arguments, operation and destinations. Changed final bytes refuse; verified matching partial output can continue. Do not replace an interrupted operation with a new input or nominal completion.

Action/media/package prepare saveREQUEST.json without automatically saving or recording endpoint application. Preserve that exact request through the original save command:

```sh
node stellar-forge/developer-site/collection-review-cli.mjs save \
  --project PRIVATE_OPERATION_DIR/original/project.json \
  --request PRIVATE_OPERATION_DIR/saveREQUEST.json \
  --out NEW_SAVED_WORKSPACE.json
```

Keep the resulting full workspace before recording an actual endpoint observation. A package request uses the exact request returned by the maintained preparer, including its frozen note/state/revision, rather than reconstructing it.

Only PRIVATE_PACKAGE_DIR/visitor/ is public visitor content. Never serve or email the private parent directory. Handover includes the original Collection export, all registered media and the optional actual toolkit bytes. Selecting no toolkit or missing a required media role remains a declared handover gap; neither is silently supplied.

FILES.json records full output members; COMPLETE.json is written after verification. RESULT.json records the original operation/workspace/revision, prepared request/deployment where relevant, and actual copy directory plus manifestSha256/manifestBytes/file/byte totals. For commissioning, bind those exact FILES.json values as directory-manifest and verify its actual members. The two copies retain identical original intent, manifest, completion and content. Their reported renderedProduct:NOT_VERIFIED and clientReady:false remain accurate until the separate actual product course supplies rendered/operated evidence.

Two verified directory paths establish those copies, not different physical failure domains or successful editable restoration. Record the actual custody and independently reopened project in copy/restore evidence. Keep all final source, media, reports and private history together for the authorized recipient.
