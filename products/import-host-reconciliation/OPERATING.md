# Installed import-to-host reconciliation

Use **Applications → Import-to-host reconciliation**. Choose a physical private workspace directory. For a new workspace, enter a **New workspace label**; the launcher creates it once and retains the installation identity in the original launch request. Existing workspaces resume their saved session. Start, then Open the private application link.

## Complete operator workflow

1. Enter the preparer's name in **Operation actor**. Open **Original sources**, load the exact UTF-8 file, choose its role and retain it. Original bytes, labels and logical records remain available.
2. In **Captured imports**, declare the application, tenant, environment, template and import identity. An imported callback or webhook remains a retained observation.
3. Use **Field mapping** to select exact source business keys and typed, decimal or text comparisons. Preview and freeze each deliberate mapping edition.
4. In **Host plan**, give every original row a create, update or skip decision. Updates select original host IDs. Preview the complete plan and freeze it after review.
5. Retain actual host-result and selected-record readback files. **Reconcile results** separates matched, divergent, rejected, uncertain, unobserved and skipped rows. **Compare editions** preserves explicit row correspondence, changed expectations and unmatched populations.
6. Append named decisions in **Review and report**. The complete working session also retains unfinished forms and raw JSON drafts. These drafts are editable preparation; frozen domain records carry separate operation history.
7. Select **Save complete session**. The managed writer retains the exact original request and full successor before selecting the new current edition. Browser drafts are also saved to a transaction-bound IndexedDB copy.
8. Select **Save retained handover ZIP** after saving. The host retains the complete source, editable offline operator, current working JSON, selected report, original evidence and every saved managed edition/request. The browser receives every chunk and verifies the complete SHA before download.

## Interruption and concurrent work

**Recover original request** reconciles the original request ID, installation identity, base edition SHA and complete content. A committed retry returns its original outcome and the newest saved session. A known validation rejection retains its original request without changing the session. A transport or storage failure remains pending until reconciliation.

If another operator saved a newer edition, select **Open newest saved edition**. The complete local branch is retained as a prior session in **Open and restore**, including its unfinished drafts. Restore that branch only when it is the edition you intend to continue, then save deliberately. Downloads never silently claim an old cached browser edition is the current saved result.

**Save complete recovery JSON** preserves the current editor, pending original request and receiving history. Open that file through the installed recovery control after a port/origin change. It contains no bearer token. The default listener reuses its prior port so ordinary browser recovery remains available after restart. A conflicting listener does not silently switch origins.

## Native commands

Use the installed Starforge entry, or invoke the source directly with Node 22.16 or later:

```sh
node products/import-host-reconciliation/cli.mjs init /physical/private/project "Import reconciliation"
node products/import-host-reconciliation/managed.mjs --workspace /physical/private/project --port 0
```

The first command requires an unused directory under an existing private parent. Applications can create the same new workspace through its normal form. To open the complete fictional course instead, use `cli.mjs course DIRECTORY`.

`cli.mjs receive DIRECTORY WORKING.json` installs complete working JSON into a new directory. `session`, `desk` and `export` produce complete portable copies. `request` applies an exact original request file with the application stopped; `connected` uses its current authenticated listener. Use `request-status` or `connected-status` to reconcile that same file. Run `--help` for exact arguments. Only one writer owns a directory.

## Customer-agent tools

Declare a private `stellar-forge.import-host-host.v1` JSON file with `workspaces` aliases, each selecting `directory`, optional `installationId`, and optional `inputs` mapping aliases to exact `file` and `sha256`. Add its path as `importHostConnection` in the maintained Merchant configuration, or initialize the provider using the normal provider setup command.

The `merchant_import_host_*` family connects the existing Applications writer, inspects paginated current-edition records, previews domain choices, ingests declared complete files, applies original domain requests, receives complete working sessions, recovers exact requests and receives retained exports. Inputs are complete host files; tokens and arbitrary paths are not supplied in ordinary tool arguments. Disconnect closes the client attachment; Applications Stop drains the server and writer.

## Host integration

The included `src/host-bridge.js` supplies the original callback/webhook capture and reviewed-batch orchestration APIs. Actual writes require an installed host's explicitly supplied write/read functions, webhook verifier and atomic durable journal. This application prepares plans and reconciles retained observations. Its managed session writer does not invoke a third-party write API. See `integration/CORE_API.md` and `integration/INSTALLATION_BOUNDARY.md` for the complete contract.
