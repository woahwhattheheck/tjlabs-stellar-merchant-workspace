# Complete handover

The complete application delivery consists of the standalone Warehouse_Activity_Billing_Study_Desk.html and every source member listed in SOURCE_MANIFEST.json. The HTML embeds the full source masters, exact worked studies and manifest, so its Source download reconstructs the maintainable application.

Working exports are separate: session.json contains complete current work, every unfinished form, compact retained preimages and browser branches. study.json contains the selected applied study; it does not replace the full session when drafts matter. comparison.md includes the readable billing report. billing/ contains the exact calculation and ordinary charge, storage, ownership, invoice, effort and exception tables. originals/ and documents/ retain input text and arbitrary original bytes, with identity indexes.

The source course records are genuine executions of the maintained code with the runtime described in each record. A rendered browser and operating-system receive are the receiving operation described in RECEIVING.md. Keep those results separate when recording acceptance.

Customer research and commercial planning worksheets are supplied by the programme owner alongside this engineering application. They are not imported automatically and do not represent actual warehouse records. The application starts empty; worked records are visibly authored.

Accept the handover when the complete agreed case can be imported, mapped, corrected, reviewed, saved, reopened and exported with its originals and full pending work intact, and when the documented source build reproduces the delivered operator. A source owner should resolve operational exceptions before relying on any complete proposal.
