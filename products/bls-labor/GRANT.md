# Regional labor analysis and recurring customer delivery

## Customer problem and usable product

A regional economic-development team needs to explain changes in resident employment, workplace jobs and wages without losing the original statistical definitions. Its recurring work includes receiving official releases, selecting the same geography and periods, checking changes, writing a county briefing, and handing another analyst enough material to update the next edition.

The maintained **BLS regional labor workspace** implements that whole operating project. The selected product is `bls-labor`; Applications opens **BLS regional labor workspace** from the original initialized or received project. Its source engine retains complete Bureau of Labor Statistics files, dictionaries, footnotes and acquisition receipts. The analyst workspace adds source editions, complete observation browsing, county reports, complete regional calculations and charts, source comparisons, revisioned notes and editable project receiving. Its native controller reuses the existing publisher, dataset version store and SF88/Vitality customer receiving.

The complete regional product is merged in [Merchant PR951](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/pull/951), at `8a9c1240a2cbb6600683e9ee27e5d70fcd361011`. The [operating guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/8a9c1240a2cbb6600683e9ee27e5d70fcd361011/products/bls-labor/OPERATING.md) is the exact installation, source-intake and customer-receiving entry. The [native publication guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/8a9c1240a2cbb6600683e9ee27e5d70fcd361011/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/workspace/NATIVE_RECEIVING.md) supplies the original host configuration and saved-operation interface.

## Original regional case

The retained Northeast Kingdom source covers Caledonia, Essex and Orleans in Vermont, with county FIPS 50005, 50009 and 50019. The original source archive is `NEK_Vitality_Official_Sources_20261011.zip`, 21,024,420 bytes, SHA-256 `3473bd56195b486c41a5042f5d9be4cfbf82bcf0d257528fe724b18caea9a28e`. Its original [source archive](https://chatgpt.com/api/library/files/libfile_768d988847e08191afe7f0b0fbb8cf16/download) includes the complete source catalog and acquisition receipts. The BLS input selects eight retained files and eight corresponding receipts.

The original native intake contains 408 LAUS observations and 96 QCEW observations. Within LAUS, 396 values are reported and 12 are unavailable. These original counts identify the retained case alongside the complete source and capture identities. LAUS describes the resident labor market; QCEW describes employment and wages at the place of work. The product keeps those populations and measures in separate original projections.

The original [BLS publisher case](https://tokenjunkielabs.slack.com/archives/C0BTB4SUCP9/p1791850294749669) carries the complete input, executable receiving command and original 4BF5/Actions operation. Its saved `receive-original` journey imports that archive, prepares all six county/projection briefings, the full resident-labor change report and two saved regional analysis revisions, retains an analyst note, exports the editable project and reopens it in a separate receiving directory. The same original operation owns its current native and browser results.

## Reviewer journey

Start in the existing Runtime workspace and build the `bls-labor` selection from the merged source. Receive the resulting complete product archive through the existing runtime installer. Applications then selects the initialized or received analyst directory and the existing Python executable. Its Review, Save, Connect, Review Start, Start and Open controls preserve the selected source, workspace marker and actual native listener.

| Operator action | What the reviewer can inspect | Maintained implementation |
| --- | --- | --- |
| Receive the original NEK archive | Complete original BLS files, acquisition receipts, source declaration and selected source edition | Original BLS capture engine, `receiving.py`, analyst source editions |
| Open resident-labor observations | Every selected LAUS row, exact source status, physical-record reference, raw value and original definition | Original typed LAUS projection and full-row observation view |
| Open workplace employment and wages | Every selected QCEW row with ownership, industry, quarter, measure, units and disclosure status | Original typed QCEW projection and full-row observation view |
| Save county commentary and reports | Revisioned analyst text, complete JSON/CSV/printable HTML, every selected observation | Existing analyst note and report operations |
| Save and revise the whole regional analysis | Complete county membership, exact resident totals/rates, separate workplace jobs/wages, charts, all customer files and the original editable definition | Regional calculation engine and saved analysis operations in the same workspace |
| Compare a later release | Added, removed, changed and unchanged observations with complete before/after values and changed fields | Source-edition comparison using original observation identities |
| Publish the selected datasets | Original saved plan, extraction, candidate review, dataset version and source identity | Existing BLS publisher and native receiving controller |
| Receive the customer project | Full source editions, reports, notes, native operation history and editable reopening | Consistent SQLite backup, full-file ZIP handover and original receiver |

A reviewer can inspect one county's resident labor and workplace reports without treating their populations as interchangeable. For the prior-year resident-labor comparison, the application requires matching series, source period, units, residence basis, seasonal status and annual coverage. Rate differences remain percentage-point changes. Unavailable or incomparable values retain the original status or the reason a comparison could not be made. The current source dictionary and retained file remain available beside the result.

The original seven briefings remain resident-labor and workplace reports for each county, plus the resident-labor change report. The complete receiving programme also prepares the regional labor/workplace analysis and its saved customer-commentary revision. Every regional output includes the full original observation population, exact fractional calculations, all-row JSON and CSV, printable HTML charts, revision differences and a complete analysis ZIP. Full value paging and definition reopening are available in the same browser.

The regional unemployment rate uses total unemployed residents divided by total civilian labor force. QCEW regional employment adds distinct county jobs within one original ownership, industry and size group; regional weekly wages use quarterly wages and all three monthly employment counts. Original county rates and wage averages remain their published values. Missing or suppressed members leave the requested regional figure unavailable, and annual comparisons retain source coverage. The [complete method and customer guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/8a9c1240a2cbb6600683e9ee27e5d70fcd361011/stellar/scf-starforge-20261009/sf30-seller-sdk/bls-labor/workspace/REGIONAL_ANALYSIS.md) describes the calculations and links the original BLS definitions.

Choosing **Revise this analysis** opens the exact saved input in editable controls. Selecting another source edition or changing the customer commentary saves a new complete report with its parent and full statistic comparison. Receiving the entire working-project ZIP preserves the raw sources and history before that same definition is reopened on another host.

## Customer delivery and continuation

The same source edition can publish LAUS, QCEW and the complete original files through the maintained data publisher. The analyst selects an actual reviewer, the review note, projections and any original plan or run IDs. A saved request binds the operation to the full source identity. The controller opens or reuses the original publisher and dataset services, retains the completed review and publication results, and continues the original SF88 acquisition and Vitality import when that customer receiving is selected.

Host-specific seller, session, executable and network configuration stays in the original host connection file. The portable customer project carries its source editions, datasets, reports, note history, saved requests and native results. A receiving host supplies its own connection and can continue the same working project. A completed original delivery remains in history; a new publication uses a newly selected operation.

The complete project ZIP is the practical handover. A customer can receive it into a separate directory, reopen the original editions and reports, edit commentary, compare the next release, and prepare another complete customer export. The exporter takes a consistent database backup and carries the original retained files. Receiving verifies the full archive and its declared complete members before reopening the project.

The saved-operation model also supports ordinary interruption. The browser retains the exact request before sending. The server records the request and original revision; the same ID and input continue that operation. Original report files and native publication history remain attached to the project. This makes handover and continuation part of the operating product.

## Place in the funded programme

This existing implementation is a concrete customer-facing foundation for the current six-package SCF plan. It gives the programme a regional-data commissioning example: receive the customer's selected geography and official source edition, configure its existing publisher and buyer environment, prepare its report mapping, operate the full receiving journey, and hand over a maintainable project.

The work fits the current application sequence: customer/source onboarding; integration with the existing publisher, merchant and buyer; complete customer delivery and operation; and maintainable source and operator handover. The canonical application controls the six package names, milestones, staffing, funding and outcome counts. Its current budget remains USD 38,000 for 400 prospective hours over 150 days.

The recurring service is specific: receive the next official release, preserve prior editions, explain comparable changes, update county commentary, publish the selected complete datasets, and deliver updated reports plus the editable project. Its service boundaries are the selected geography, projections, source periods, review responsibilities and customer delivery format. Commercial commitments are agreed for the customer's actual assignment and capacity.

The regional labor implementation can contribute to a wider regional-data workshare alongside the customer's existing scientific and planning tools. Its commissioning scope names the labor source and delivery work explicitly, with the original source period, reporting responsibilities and receiving application recorded in the customer workorder.
