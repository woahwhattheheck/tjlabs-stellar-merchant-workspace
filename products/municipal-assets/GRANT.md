## Municipal asset migration and target receiving

The asset application carries an existing municipal inventory/GIS migration through complete source intake, explicit identifier and relationship mapping, target reconciliation, repair, returned work-order outcomes and independent editable handover. It complements the existing Open311 service collection, reporting, GIS, follow-through, Field Desk and service-configuration suite.

The maintained source is the original McPherson/Belleville operator and acceptance checker, with complete public capture/geometry/refresh and the source-reviewed Maximo target addon. Every original source-qualified object and typed attribute remains available. Municipal business identifiers that repeat across segments remain attributes or reviewed mapping choices; they do not silently replace the original object identity. Provider geometry remains its observed edition, and a later source observation is compared with the prior actual source.

Operators use the existing SCF Applications lifecycle to select a prepared source/runtime, initialized private workspace and actual Python executable. Review retains the source and stable native identity. Start verifies the exact database binding and source; Open verifies the live authenticated original instance. Named operators then work in the original browser application with its SQLite transaction, expected project revision and stable request-ID replay. A separate received directory preserves its logical project/source history while using independent private authentication.

The configured Maximo collector reads the actual tenant schema and complete target population. The mapping retains compound native keys and source linkage independently of provider resource links. Prepared native loads keep their selected original source/schema/body, receive the full actual returned outcomes and await a following complete target capture. This source does not invent tenant fields or represent a prepared file as a completed external mutation.

The customer receives the complete installed source selection, readable report, original source/target/repair handoff, original acceptance output and a full editable workspace. The stopped-workspace handover retains SQLite plus the actual public-refresh source journals and files. Complete receiving validates every selected member and native database before publishing its directory; repeating the original receiving preserves later local work.

The current installed continuation joins the existing D1CC native programme. The original source and prior native product results retain their own dates and identity. Actual operation and rendered inspection of this newly selected SCF installation are recorded by the existing equipped receiver through the complete [operating](products/municipal-assets/OPERATING.md) and [receiving](products/municipal-assets/RECEIVING.md) course. Customer readiness includes looking at and using the exact app and all outgoing attachments, complete ZIP contents and reopened files.

This contribution extends the existing product/implementation portfolio. It preserves the canonical SCF request, schedule, tranches, payment observations and prospective work packages; no additional grant amount or private customer acceptance is asserted by source adoption.
