# QWC product operating entry

The complete maintained operating manual is
[QWC_PUBLICATION.md](../../stellar/scf-starforge-20261009/distribution/selections/QWC_PUBLICATION.md).
That same original guide becomes the installed selected package README.

Use the original `qwc-publication` recipe with the current complete source
commit. Its normal build entry is:

~~~sh
node stellar/scf-starforge-20261009/distribution/build.mjs \
  --repo /absolute/complete-merchant-source \
  --ref ACTUAL_FULL_SOURCE_COMMIT \
  --selection qwc-publication \
  --out /absolute/private/qwc-release
~~~

Keep the returned complete archive, SHA-256 and distribution/manifest with
the original operation. The manual gives the corresponding same-output
`--resume`, runtime-install prepare/install/inspect commands and original
installed command routing.

The complete customer execution follows the original
[native-journey.py guide](../../stellar/scf-starforge-20261009/sf30-seller-sdk/stac/qwc/NATIVE_RECEIVING.md).
It uses the actual source and executable identities returned by the selected
runtime, one private journey directory, the original GIS editions and existing
QWC host/profile, and one complete original native lifetime. Both editions are
captured while deployed before the same operation restores the first edition,
finishes acceptance, receives/reopens the portable project and writes the
complete customer archive.

For an ordinary operator, open the initialized workspace through **Applications
→ QWC publications** or the original `stac-qwc serve` command. New deliberate
Verify/Reopen actions create new retained invocations; Resume uses the
original returned job input. Stop retains original native and file ownership
through the actual drain.
