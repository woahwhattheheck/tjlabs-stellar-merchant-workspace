This program continues the complete original PREP12 project through its managed product: Applications provider preparation and listener ownership, typed SDK and 21 merchant tools, the original browser, complete project downloads, retained file resumption, application reopen, independent customer editing, and original SF30 merchant loading.

The input retains all 120,012 rows, original source identifiers, two original recipe/result editions, and the original review. The receiving program creates one additional managed recipe/result and a separate customer revision. It compares the complete six-row managed result with the retained original result and verifies every original input/result file after customer receiving.

## Run the complete operation

Use a Linux host with Python 3.11 or later, Node 22.16 or later, an existing Playwright module and an existing compatible Chromium executable. The preparation engine itself uses Python's standard library and SQLite. The browser module and executable are selected explicitly; this program does not install them.

Create an owned private parent directory with mode 0700. The receiving directory must be new. From the maintained repository:

~~~sh
PREP12_SOURCE_ROOT=/absolute/selected-source-at-88feb91b
python3 products/data-preparation/receiving.py \
  --source-root "$PREP12_SOURCE_ROOT" \
  --source-commit 88feb91bc5089dced81813642aca24dc24ca713b \
  --package /absolute/private/Starforge_Data_Preparation_2026-10-12.zip \
  --directory /absolute/private/preparation-managed-case \
  --node /absolute/existing/node \
  --playwright-module /absolute/existing/node_modules/playwright \
  --chromium /absolute/existing/chromium
~~~

The complete operation owns one native session. Its child records its actual inner PID and outer /proc process group/session before loading product code. Cleanup inspects that captured outer group while signaling only the original inner process group. Completion requires the original child to exit successfully and all of its owned processes to drain. Other operators' browsers and application processes are outside that group.

The native run records cgroup memory and process counts before and after the case. It uses a 240-second receiving interval followed by a graceful stop and, if required, termination of that same owned group. It then preserves the complete closed work and actual outcome.
