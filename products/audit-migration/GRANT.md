## Audit source, evidence and complete customer receiving

### A complete migration and reconciliation service

An audit system connects much more than a list of findings. Its audit universe, annual plans and engagements lead to controls, tests, observations and follow-up actions. Evidence files explain those records. Original principals and access declarations determine what the source says about confidentiality, while change history records who changed what. A replacement platform needs those connections to remain reviewable through source preparation, supplier loading and independent handover.

The installed Audit Source Workspace provides the complete source-side workflow. An operator retains original CSV and binary files, maps their actual columns and opaque keys, declares the whole selected population, inspects relationships and evidence, records attributed corrections and reviews, prepares files against real supplier templates, then compares the actual supplier-returned records. The [installed operating guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/f5ac03258dcf69b67b16a7df1217c5d395efffe2/products/audit-migration/OPERATING.md) connects the offline browser, original CLI, typed merchant tools and existing Customer Installation.

This is a practical engineering workshare around an audit owner's and specialist supplier's existing responsibilities. The source owner supplies authorised originals and explains their meaning. The engineer prepares complete, reproducible mappings and shows unresolved differences. The specialist supplier retains its actual import contract, licensed platform, access, configuration and production loading. Audit judgments, risk conclusions and destination permissions remain with their authorised owners.

### Preserve complete originals and exact identities

The [original engine](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/f5ac03258dcf69b67b16a7df1217c5d395efffe2/services/audit-migration-workspace/engine.mjs) stores entire physical inputs, filename, MIME type, byte count, SHA-256 and source representation. Binary attachments remain complete bytes. A transcription is identified as an authored transcription; it does not stand in for an original PDF or workbook that has not been received. The [source API](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/f5ac03258dcf69b67b16a7df1217c5d395efffe2/services/audit-migration-workspace/API.md) and [core operating guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/f5ac03258dcf69b67b16a7df1217c5d395efffe2/services/audit-migration-workspace/CORE_OPERATING.md) describe the complete data and operation contracts.

The twelve neutral migration roles are universe, plans, engagements, controls, tests, findings, actions, documents, principals, access rules, history and relations. They are explicit source-model roles. They do not claim to be tables or field names in a particular audit platform.

| Original source condition | Working behaviour |
| --- | --- |
| Repeated names or labels | Retain separate records unless their actual namespace, role and ordered key parts establish the same identity. |
| Leading zeros, case or Unicode differences | Preserve the source key exactly. No name, email or row-position matching silently joins records. |
| Duplicate headings | Map the original zero-based column position; retain the full ordered header and all source cells. |
| Missing trailing cells and present empty strings | Keep them distinct. A correction names the exact expected current value and replaces only the selected position. |
| Repeated rows for one original identity | Retain every witness. Unequal complete variants remain a conflict; no first or last row silently wins. |
| Unknown or unmapped columns | Retain the original values and expose them with the complete row witness. |
| Evidence inventory | Bind a document to complete selected original bytes, or preserve an explicit qualified external-only source declaration. |
| Access and history records | Retain source declarations and their relationships without claiming that the offline file enforces source or destination permissions. |

Every correction records the actual actor, time, source, row, column, before value and reason. The original bytes and earlier corrections remain available. The [same-workspace CLI](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/f5ac03258dcf69b67b16a7df1217c5d395efffe2/services/audit-migration-workspace/cli.mjs) uses the same engine and original request history as the browser.

### Prepare the supplier's actual files and compare its return

A destination contract starts with complete supplier-provided templates, dictionary or procedure. A clearly authored software example remains labelled as an example. The exact original CSV template supplies its ordered headings, including duplicates. Every target column has an explicit field, source column, key, reference, crosswalk or intentional constant selection. An empty output is an explicit choice.

Every selected source mapping requires target coverage, including a header-only included source. Changed target identifiers require actual supplied crosswalks. Referencing target keys use those original crosswalks and explicit destination-table bindings; no new vendor identifier or version column is invented.

An accepted review, current selected source and complete target assessment precede a new preparation. The resulting edition freezes every output row, key, source witness, CSV byte and target relationship. A later source correction can stale the current preparation basis without rewriting those earlier files.

Actual returned files are retained as originals. The operator maps their real columns to the prepared headings and supplies the real submission reference if one exists. The complete comparison shows matching, changed, missing, duplicate and unexpected records, unreported tables and retained extra fields. A success flag is not substituted for those actual returned values.

The readable prepared and returned reports keep the exact preparation and original source selection together. The installed client derives an omitted source selection from the chosen original preparation, including when a later selection exists. Explicit conflicting selections remain errors. Earlier target history can therefore still be read accurately after later work.
