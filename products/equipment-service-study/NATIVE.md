## Source intake and selection

```sh
node native/service-desk.cjs import-csv --in new.session.json --kind cases --side source --file cases.csv --available-at 2026-10-01T00:00:00Z --out cases.session.json
node native/service-desk.cjs select --in cases.session.json --kind cases --side source --extract EXTRACT_ID --out selected.session.json
node native/service-desk.cjs crosswalk --in selected.session.json --kind cases --file identity-pairs.csv --out mapped.session.json
```

An optional `--mapping mapping.json` supplies the explicit canonical-column map. Without it, only exact header matches are mapped. Unavailable columns remain unavailable. Crosswalk CSV uses `source_id,target_id`.

## Complete plan and row corrections

```sh
node native/service-desk.cjs service-plan --in mapped.session.json --file service-plan.json --out planned.session.json
node native/service-desk.cjs prepare-record --in planned.session.json --kind inspections --side returned --index 0 --out correction.json
node native/service-desk.cjs record --in planned.session.json --file correction.json --reason "Actual source correction" --out corrected.session.json
```

A correction JSON carries the exact study ID and expected selected-extract ID, including null for a new table. Keep both. A request prepared against a different selected extract is refused without writing an output. The previous complete session and pending request remain available.

`set-config` edits study label, source class, original/returned boundary or authority notes. `source-selection` writes the exact current family-to-extract map. The service-plan file uses the actual `config.service` fields shown in the complete authored session.

## Originals and reviews

`add-document` retains exact arbitrary bytes with `--file`, optional `--type` and actual `--available-at`. `link-document` requires side, kind, record, document and link availability. `unlink-document` removes a current link while retaining its earlier study. `document-availability` requires the original byte digest and full current metadata digest plus the source-backed reason.

`review` requires the current study digest, role, reviewer and actual decision. A review prepared against a previous study is rejected. Technical certificates, signatures and commercial approvals are canonical source records, not generated by this review command.
