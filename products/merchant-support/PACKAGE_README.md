## Install the original runtime

Use this archive's actual SHA-256 with the maintained runtime profile and installer. Select the original `schema`, `openapi`, `mcp`, native and operator dependencies, then attach the READY runtime to Runtime workspace. Open **Applications → Merchant support** and select the customer's actual private case, source and package directories.

The optional accounting and buyer connection fields attach the existing native owners for Service adjustments, buyer periods and accountant work. The optional Handoffs profile connects the original remote receiving sources. The application retains its reviewed native profile identity through startup and reopening.

## Accepted quotations through delivery

1. Open **Commercial** for the actual saved merchant case. Prepare the quotation from its retained implementation, Service and pricing sources, then record the customer's response against the saved quote edition.
2. In **Implementation**, review the accepted edition's task and plan changes and its one-time and monthly amounts. Choose **Keep current edit** or **Use accepted scope** for overlapping edits, then select **Review selected choices**.
3. Enter **Recorded by** and an implementation note. Apply the reviewed scope to start the implementation or record an accepted change order. The same case retains the quotation, customer response, reviewed choices and previous commercial basis.
4. Choose **Open implementation and receiving** to assign the agreed tasks and attach their original deliverables. In **Technical and customer receiving**, use **Implementation plan tasks** for accepted custom work or select the original workorder edition for work tied to it. Record the actual technical or customer observation and its source reference.
5. In **Export and reopen**, choose **Open complete case handoff**. The original complete-delivery desk saves the case and retains the export and receiving operations for its full history, source bundles and attachments.

Later quotation revisions continue through the same review and acceptance workflow. The receiving case keeps the original agreement and accepted changes alongside the delivered work.

## Commands

The installed `starforge` command includes `support-console`, `support-watch`, `merchant-implementation`, `merchant-services`, `merchant-commercial`, `merchant-support-agent`, `merchant-service-adjustments`, `merchant-service-adjustment-receiving`, `merchant-accounting-adjustments`, `buyer-expenses`, the original merchant MCP launchers, and the maintained runtime installation and transfer commands.

Read the setup command's original options:

```sh
starforge merchant-support-agent --help
```

The setup command creates the original merchant host for an existing Support connection and case collection. Its original release initialization and immutable configuration publication resume in the same selected output.

## Continue customer work

Receive the whole case package through **Complete delivery**, then open the receiving case named by the original completion. Keep that case directory and native source directory together through reopening. The package retains the complete captured sender history and every original native source archive.
