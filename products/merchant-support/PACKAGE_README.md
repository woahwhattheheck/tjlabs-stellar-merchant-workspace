## OAuth resource support and original operator tools

The package includes the original OAuth resource observer, the SF93 observation collector and the Merchant Support OAuth desk. In **Merchant support → Incidents**, select an existing named OAuth resource from the customer's private incident-source profile and inspect its original configuration revision. Register the reviewed source through the original manager, then use the existing incident watcher and case flow. Browser and MCP callers select a source alias; they do not supply a replacement endpoint or token environment reference.

The installed `starforge mcp-oauth` command is the original OAuth resource operator. Start with `starforge mcp-oauth --help`. Its `describe --config /absolute/private/config.json` reads the original selected configuration; its `discover` and `probe` commands perform their explicit original network operations. The probe uses the selected operator token through `--token-env` or its private token-file option and retains the complete tool catalog evidence. It does not create a Support incident or start a watcher. Use `init` only when commissioning a new authorized resource configuration; existing customer configurations stay with their original owner.

The original public interfaces are included as `./mcp/oauth-resource`, `./mcp/oauth-host`, `./mcp/oauth-discovery` and `./mcp/oauth-operator`, together with their complete adjacent `.d.mts` declarations. They are the same source modules and types used by the existing OAuth host and operator.

Select `--feature mcp` in the maintained `runtime-install prepare` command, then complete `runtime-install install` and `runtime-install inspect --load` for that same installation. The source-selected MCP manifest pins JOSE 6.2.12 and its existing MCP/payment dependencies. The source archive itself contains no `node_modules`; the original installer places the selected graph beside `package/` so module resolution reaches it. Selecting a recipe makes the feature available; it does not itself install dependencies. The complete Support installation also uses the existing `schema`, `openapi`, native and operator selections described above.

## Accepted quotations through delivery

1. Open **Commercial** for the actual saved merchant case. Prepare the quotation from its retained implementation, Service and pricing sources, then record the customer's response against the saved quote edition.
2. In **Implementation**, review the accepted edition's task and plan changes and its one-time and monthly amounts. Choose **Keep current edit** or **Use accepted scope** for overlapping edits, then select **Review selected choices**.
3. Enter **Recorded by** and an implementation note. Apply the reviewed scope to start the implementation or record an accepted change order. The same case retains the quotation, customer response, reviewed choices and previous commercial basis.
4. Choose **Open implementation and receiving** to assign the agreed tasks and attach their original deliverables. In **Technical and customer receiving**, use **Implementation plan tasks** for accepted custom work or select the original workorder edition for work tied to it. Record the actual technical or customer observation and its source reference.
5. In **Export and reopen**, choose **Open complete case handoff**. The original complete-delivery desk saves the case and retains the export and receiving operations for its full history, source bundles and attachments.

Later quotation revisions continue through the same review and acceptance workflow. The receiving case keeps the original agreement and accepted changes alongside the delivered work.

## Tariff quotation and editable handover

Open **Applications → Merchant pricing and scenario planning → Tariff planning** to retain the original schedule, compare exact quantities and complete its selected scenario and pricing requests. In **Applications → Merchant support → Commercial quotations**, choose the saved customer case and open **Tariff sources**.

Capture the completed original selection with its full pricing backup, inspect the retained source and attach it through the original case writer. The quote keeps its selected quantity, saved uniform rate, original tier total and rounding. A changed monthly quantity displays the original tariff calculation alongside the saved-rate charge.

Continue the accepted quotation into implementation and receiving. The complete case package carries the original tariff source and pricing backup with its quote editions, customer responses and delivery history. In the receiving case, restore the original pricing workspace, receive the selected portfolio and reopen both saved native outcomes.

The maintained commands are `starforge merchant-tariffs`, `starforge merchant-commercial tariffs` and the original `merchant-mcp pricing` and Support tools. The linked tariff guide provides the complete capture, three-request attachment, download, export and restoration inputs.

Select the retained review, enter an explicit monthly request volume and choose the existing or a newer received native tariff for the same route. The full customer case carries the performance source as an original material. Its receiving case can inspect and export that source immediately. Complete native continuation uses an original Pricing workspace backup captured after the review and proposal operations, plus the full tariff portfolio. Restore that backup, receive the portfolio through its original owner and reopen Performance to recover the same saved proposal and selection requests.

The package includes `starforge merchant-performance`, `starforge merchant-commercial performance`, the typed `./merchant/performance-client` and `./merchant/commercial-performance-client` exports, and the original Pricing and Support MCP methods. Both linked performance guides describe the exact inputs, source identities, native request UUIDs, downloads and continuation.

## Accepted quotations through billing and the service calendar

Select the published quotation in the saved customer case and download its complete quotation JSON and matching accepted response. Open **Applications → Merchant receivables** or **Applications → Service agreements and billing** with the merchant's original initialized accounting directory and customer.

The invoice import retains the selected tariff and measured-usage source alongside the accepted revised amount. Its view separates the observed period and quantity from the explicitly quoted monthly volume and uniform rate. Review the source, billing scope, dates and resulting draft, then issue it through the original Receivables writer.

For ongoing work, create the service agreement from that same accepted source. Review its original monthly boundaries, billing periods and current quotation edition. Preparing a period creates the original invoice draft; later editions, renewals and cancellation preserve the previous calendar and bills. The same combined server exposes customer records, receivables and the service calendar under one accounting lease.

The package includes the original payment plans, Stellar collection, paid credits, refunds and customer statement closing. Its typed clients and merchant tools continue to use the original Accounting and service-agreement controllers.
