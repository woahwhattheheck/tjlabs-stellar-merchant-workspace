## Tourism source series and customer receiving

### A complete source-to-report service

Destination organisations, councils and their research partners need to bring together economic-impact studies, accommodation series, visitor surveys and administrative records without losing what each number measures. The hard part is often the source contract: the district and county overlap, a website user is a different population from a visitor, a revised model changes comparability, and a published total can differ from the sum of its printed components.

The installed Tourism Series Workspace supplies a complete editable route from those original files to qualified calculations, frozen reports and an actual target-system handover. Its [operating guide](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c49193b0fa27fe80a126af6c28a85ed4d563fdc7/products/tourism-series/OPERATING.md) describes the installed product and customer workflow. The [source adoption manifest](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c49193b0fa27fe80a126af6c28a85ed4d563fdc7/products/tourism-series/SOURCE_ADOPTION.json) retains every byte-complete original application, CLI, guide and receiving helper from the maintained public product.

The work is a practical onboarding and reporting service around a partner’s existing platform. The source analyst selects actual originals and definitions; the implementation engineer prepares explicit mappings and explains exceptions; the receiving operator can reopen the full work and continue it. The platform owner keeps licensing, production access, permissions, hosting, methodology approval and its actual native import.

### Preserve what each observation means

The [original engine](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c49193b0fa27fe80a126af6c28a85ed4d563fdc7/services/tourism-series-workspace/engine.mjs) retains complete physical inputs and CSV rows, immutable registry editions, mapping history, attributed corrections, saved analyses, report editions and target returns. | Source question | Working decision and retained result |
| --- | --- |
| What was received? | Keep the entire original file, its filename and byte identity, source locator, representation and original rows. Identify a transcription as a transcription. |
| Which cells represent observations? | Map actual CSV columns or explicit constants. Preserve zero, missing, suppressed and nonnumeric values as different source states. |
| Which populations can be combined? | Use the selected geographic hierarchy and declared partitions. A district already included in a county does not create an additional population. |
| Which periods and methods can be compared? | Retain the original period span, gaps, model or method edition and an explicit comparability decision. Unconfirmed differences remain visible. |
| What does a published total mean? | Keep the source’s total and components together, including rounding or reconciliation residuals. A discrepancy becomes a review finding rather than an automatic correction. |
| What can be delivered to another system? | Use its actual retained template, explicit target fields and row keys; retain the complete exported rows and later observed return. |

### An operator can finish the work

The [browser application](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c49193b0fa27fe80a126af6c28a85ed4d563fdc7/services/tourism-series-workspace/app.mjs) provides working controls for original files and CSV, registry editions, column mappings, complete observation and correction views, qualified calculations, frozen reports, target CSV and return inspection, and history/recovery. The [standalone application](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c49193b0fa27fe80a126af6c28a85ed4d563fdc7/services/tourism-series-workspace/Tourism_Series_Workspace.html) carries that complete interface and its maintained source without a separate tourism server.

An analyst chooses the complete source series and the actual registry before preparing a calculation. A sum records its selected population and dimensions; a comparison retains its method qualification; a ratio requires a declared compatible relationship. The readable result retains the calculation’s inputs, findings and contributing observations. Freezing a report preserves that original selection even when later source work changes.

The actual public reference used during source development has 178 observations, six saved analyses and four frozen reports. It preserves the reported spending reconciliation residual, a county/district overlap finding and an unconfirmed comparison across method editions. These are useful unresolved source conditions for an operator to inspect, not numbers silently adjusted to make a demonstration pass.

A customer-facing report is an ordinary complete HTML document that can be read and printed. Its full structured companion carries the original values and qualifications. New questions create new analyses or report editions, so a receiving partner can compare the work they were given with later changes.

### Retain unfinished work and independent copies

The [portable source and recovery implementation](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c49193b0fa27fe80a126af6c28a85ed4d563fdc7/services/tourism-series-workspace/portable.mjs) carries the entire workspace, original files, source history, current selection and raw unfinished form values. The browser uses its existing IndexedDB revision check across tabs. A submitted operation captures its selected state and commits the workspace with only that operation’s submitted drafts cleared. A conflicting branch remains recoverable.

A logical workspace ID and a browser copy ID have different roles. Reopening an older file in a browser that already contains a later descendant retains the newer work. A different genesis or divergent branch is preserved as an independent copy. Unfinished empty strings, false values, Unicode text and partially entered forms remain working data rather than being coerced into an accepted calculation.

The [complete delivery builder](https://github.com/woahwhattheheck/tjlabs-stellar-merchant-workspace/blob/c49193b0fa27fe80a126af6c28a85ed4d563fdc7/services/tourism-series-workspace/build.mjs) produces working HTML, full recovery JSON, original source and target files, readable reports, complete source and a usable ZIP. The original source identities remain in the delivery. An independent operator can reopen the whole file, make a meaningful new change and export the complete current work.

### Prepare the actual target and reconcile its return

A target contract begins with a real original CSV template. The operator selects its complete header, explicit output columns, keys and row mapping. Prepared exports retain exact native cell strings and their original source selection. A later source or mapping change leaves the historical export available with its original status.

The receiving operation retains the actual returned file. It compares every selected key and mapped cell, identifies missing, duplicate, unexpected and conflicting rows, and preserves both the prepared and observed values. An exported CSV is useful preparation; the recorded native return is the evidence for what the destination actually supplied.

The generic teaching course can exercise this path using clearly authored template and return data. The public tourism reference keeps its vendor target unconfigured until a real target template is selected. The installed product does not infer a vendor API or turn a local audience filter into a platform permission.
