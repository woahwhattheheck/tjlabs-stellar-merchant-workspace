# Tourism Series and Customer Installation

This product installs the complete existing Tourism Series Workspace beside the original Grant Operations customer workflow. The same offline application retains complete original files, typed observations, source registries, corrections, qualified calculations, frozen reports and actual target CSV returns. Its source-owned commands bind that entire working edition to the customer’s commercial Workshare and saved Installation.

## Use the complete product

Build the original `tourism-series` source selection at its immutable repository commit. Follow the full [installation and receiving guide](../../stellar/scf_2026/sf49_data_commissioning/installation-workorders/TOURISM_INSTALLATION.md) for exact commands, source allowances, original case/seed selection, preview/save and independent receiving.

The installed commands are:

| Command | Complete task |
| --- | --- |
| `tourism-series` | Original source, registry, mapping, correction, analysis, report, actual template/return and full handover CLI |
| `tourism-series-build` | Build the complete editable standalone HTML, recovery JSON, original files/reports, source and ZIP |
| `tourism-installation` | Inspect original working JSON; prepare an explicit full source-edition scope and existing Customer Installation |
| `tourism-installation-receive` | Receive the complete working application and original saved Installation independently, preserving later recipient work |

Open the actual **Tourism_Series_Workspace.html** through Runtime Files or its saved local file. Grant Operations uses its existing Applications provider and Customer Installation interface. The tourism application stores browser work in its original IndexedDB and portable whole-workspace files; no extra server or login is introduced.

## Complete delivery and continuation

Attach the original complete working JSON and whole edition selection to the existing case. Obtain a fresh matching commercial seed after the attachments. Prepare through the existing Workshare profile and preview/save through the original Operations writer. Original commercial phases, fees, effort, funding and open checks remain with that case.

The independent receiving course delivers both the complete offline working folder and the exact saved Installation archive. The receiver verifies every selected original source before native import. It reopens both workspaces and retains later recipient operations and unfinished drafts in **Current_Working_Recovery.json**, separate from the immutable original delivery.

Original Operations source allowances are **8 MiB per file, 24 MiB in total and 200 source files**. The tourism application’s separate working-file ceiling is **128 MiB**. Keep complete larger source in its existing custody; a summary is not a replacement for an original working source.
