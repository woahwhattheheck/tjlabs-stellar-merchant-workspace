# Restaurant Integration Evaluation Desk

Open Restaurant_Integration_Study_Desk.html in a browser. The page starts empty and works offline. Use **Open complete authored workflow** to inspect the clearly labelled fictional five-case example.

The desk retains complete product records, native Compass API journals, exact profile and identity choices, displayed explanations, corpus snapshots, usage evidence and recurring work. It provides normal editing forms, original CSV mapping, binary originals, source-bound reviews and complete portable recovery.

## Ordinary workflow

1. Record the product, named reviewers, places, dietary profiles and complete consecutive cases in Observed records, or import their original CSVs.
2. Set the population window, expected count, knowledge cutoff and recurring phases in Population & work plan.
3. In Requests & journal intake, choose the case and operation. Save the exact request file.
4. Run the request using native/compass-call.cjs in the owner's Linux environment. Keep COMPASS_API_KEY in the environment.
5. Import the complete journal or native export. The desk retains the exact envelope and artifacts and derives every actual dispatch.
6. Select a Search candidate explicitly or use a confirmed Enrich identity to prepare Decide. Preserve the actual case profile. HTTP success, identity resolution and verdict remain separate.
7. In Integration results, prepare a source-bound adoption from a valid Decide response. Record the actual display text, risk context, named reviewer and display time.
8. Review complete inventory reconciliation, provider usage evidence, all recurring effort and unresolved cases. Build a frozen report with exact inputs and its own historical population and named role reviews.
9. Save complete file before moving devices. Complete exports include originals, mapped tables, readable report, analysis and retained history.
